# OpenAPI 3.0 Spec

Visiban exposes a machine-readable OpenAPI 3.0 specification generated by [drf-spectacular](https://drf-spectacular.readthedocs.io/).

## Endpoints

| URL | Description |
|-----|-------------|
| `GET /api/schema/` | Download the raw OpenAPI 3.0 YAML spec |
| `GET /api/schema/swagger-ui/` | Interactive Swagger UI — explore and test endpoints in the browser |
| `GET /api/schema/redoc/` | ReDoc alternative — clean two-panel reference docs |

All three endpoints require authentication (`IsAuthenticated`) — you must be logged in to view the spec.

## Accessing the spec by deployment type

### Docker Compose — development (`docker-compose.yml`)

The backend is exposed directly on port 8000 in the dev stack. The frontend dev server (Vite, port 5173) does **not** proxy `/api/` requests, so you must hit the backend directly:

```
http://localhost:8000/api/schema/swagger-ui/
http://localhost:8000/api/schema/redoc/
http://localhost:8000/api/schema/
```

### Docker Compose — production (`docker-compose.prod.yml`)

The backend port is **not** exposed externally. All traffic flows through the nginx reverse proxy, which forwards `/api/` to the backend internally. Access the spec via your domain:

```
https://yourdomain.com/api/schema/swagger-ui/
https://yourdomain.com/api/schema/redoc/
https://yourdomain.com/api/schema/
```

### Kubernetes (Helm chart)

The nginx ConfigMap in the Helm chart proxies `/api/` to the backend service. The backend is not exposed outside the cluster. Access via the ingress host configured in `values.yaml`:

```
https://<ingress-host>/api/schema/swagger-ui/
https://<ingress-host>/api/schema/redoc/
https://<ingress-host>/api/schema/
```

To access the schema directly from a backend pod for debugging:

```bash
kubectl port-forward svc/<release-name>-backend 8000:8000
# then: http://localhost:8000/api/schema/swagger-ui/
```

## CI validation

The CI pipeline runs `manage.py spectacular --validate` on every change to the backend. This catches schema regressions (missing serializers, ambiguous response shapes) before merge.

## Adding annotations

For most ViewSet actions, drf-spectacular infers the schema automatically. For custom actions with non-standard request/response shapes, use `@extend_schema`:

```python
from drf_spectacular.utils import extend_schema

@extend_schema(summary="Move a card to a different column or swimlane")
@action(detail=True, methods=["post"])
def move(self, request, ...):
    ...
```

See the [drf-spectacular docs](https://drf-spectacular.readthedocs.io/en/latest/customization.html) for full customization options.
