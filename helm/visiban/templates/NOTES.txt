Visiban has been deployed!

1. Get the application URL:
{{- if .Values.ingress.enabled }}
  http{{ if .Values.ingress.tls.enabled }}s{{ end }}://{{ .Values.ingress.host }}
{{- else }}
  export POD=$(kubectl get pods -l "{{ include "visiban.frontend.selectorLabels" . }}" -o jsonpath="{.items[0].metadata.name}")
  kubectl port-forward $POD 8080:80
  # Then open http://localhost:8080
{{- end }}

2. Backend API is available under /api/ (proxied through the frontend Nginx).

3. Run database migrations (handled automatically by a pre-install/pre-upgrade
   Job on every release — see `kubectl get jobs -l app.kubernetes.io/component=migrate`).

4. Django admin — by default restricted to loopback only. Either:
   - Port-forward: kubectl port-forward svc/{{ include "visiban.fullname" . }}-backend 8000:8000
   - Or set backend.settings.adminAllowedIPs to a comma-separated CIDR list.

{{- if .Values.backend.mediaPersistence.enabled }}

5. Media uploads are stored on a {{ .Values.backend.mediaPersistence.size }} PVC
   ({{ include "visiban.fullname" . }}-media). Only the backend pod mounts this
   volume; attachment downloads are streamed through Django, so a ReadWriteOnce
   storage class is fine for a single-replica backend. For HA (backendReplicaCount > 1)
   use a ReadWriteMany (RWX) storage class.
{{- end }}

IMPORTANT: Change the default secret values before going to production:
  --set secret.djangoSecretKey=<strong-random-key>
  --set postgresql.auth.password=<strong-password>
  --set backend.email.fromAddress=<noreply@yourdomain>
