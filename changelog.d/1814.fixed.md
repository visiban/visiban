Groups: deactivating a user now serializes with group admin removal and demotion, so a removal or demotion judges the other admins' current active state and is refused when it would leave no active admin. Deleting a user in the Django admin also waits for a concurrent deactivation of a group's other admin, and promoting an account that is being deleted waits for the delete. Deactivation itself is unchanged and is not refused (#1814)
