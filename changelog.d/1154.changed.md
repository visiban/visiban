A release tag no longer publishes anything unless the tagged commit's own `main` pipeline passed. Before, the tag pipeline's image pushes waited only on one test job each, so images, the Helm chart, the docs and the GitHub release could ship while `playwright-e2e`, `migration-check` or a security gate was red on that commit. A new `release-main-pipeline-guard` job now runs first in every `v*` tag pipeline and every publish job waits on it. It checks each job in that commit's `main` pipeline, not the pipeline's overall status, so a failed `allow_failure` job also blocks the release. If it cannot find or read that pipeline, it refuses. This also covers tags pushed by hand, which `scripts/release.sh`'s own pre-tag check does not see (#1154)
