MCP tool errors now come back with `isError: true`. In the 1.2 pre-releases, a `{"error": {"code": ...}}` result (a WIP limit, a permission or scope denial, a not-found id, a validation error, a throttle denial) came back with `isError: false`, so an agent framework that checks `isError` treated every one of these failures as a success. The error payload is unchanged: it is still in `structuredContent.result` and in the single JSON text block, with the same `code` and fields, and the tools' `outputSchema` is unchanged. A client that reads `structuredContent.result.error` needs no change. A client that treated `isError: true` as "no structured payload" should now read `structuredContent` on errors, but must still allow for an `isError: true` result without it (an input-schema rejection or an unexpected server error). Also, `create_card` and `update_card` no longer list the `assignee_email` argument in their input schema. A call that still sends it is still rejected with a `validation_error` and changes nothing, now as an `isError: true` result. Use `assignee` (a username). See the MCP API reference, "Result envelope" (#2004)
