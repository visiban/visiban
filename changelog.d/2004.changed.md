MCP tool errors now come back with `isError: true`. In the 1.2 pre-releases, a `{"error": {"code": ...}}` result (a WIP limit, a permission or scope denial, a not-found id, a validation error, a throttle denial) came back with `isError: false`, so an agent framework that checks `isError` treated every one of these failures as a success. The error payload is unchanged: it is still in `structuredContent.result` and in the single JSON text block, with the same `code` and fields, and the tools' `outputSchema` is unchanged. A client that reads `structuredContent.result.error` needs no change. A client that treated `isError: true` as "no structured payload" should now read `structuredContent` on errors too. Also, `create_card` and `update_card` no longer declare the `assignee_email` argument, which the pre-releases kept only to reject it. The MCP SDK ignores arguments a tool does not declare, so a call that still sends `assignee_email` is no longer rejected: the argument is dropped and the card is written without that assignee change. Use `assignee` (a username). See the MCP API reference, "Result envelope" (#2004)
