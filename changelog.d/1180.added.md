The Helm chart gains a public demo mode (`demo.enabled`, off by default, reference values in `values-demo.yaml`): a self-seeding install, an hourly whole-database reset CronJob whose schedule also drives the visitor countdown (with the reset disabled, the login page no longer promises one), an egress NetworkPolicy limiting demo pods to DNS and their own datastores, render guards against publishing a login on a writable instance, and a `helm test` that proves the write fence through the frontend (#1180). New `NUM_PROXIES` setting (Helm `backend.settings.numProxies`, default `1`, unchanged for existing installs) sets how many reverse proxies to trust in `X-Forwarded-For`, so per-IP throttles see the real client behind a tunnel instead of one shared address.
