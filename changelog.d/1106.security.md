- `PATCH`/`PUT /api/v1/boards/{board_id}/cards/{id}/` no longer accepts a `column` or `swimlane` id that differs from the card's current value — same-board or cross-board. Changing either now requires `POST .../cards/{id}/move/`, so WIP/weight limits and the `CardMovement` audit trail can no longer be bypassed by editing the card directly; a rejected request returns `400` with `{"code": "use_move_endpoint"}`. Echoing back the current `column`/`swimlane` value still succeeds, so existing PUT clients are unaffected. Card creation now also rejects a `column`/`swimlane` belonging to another board with `400` instead of `404`. A new read-only `find_cross_board_cards` management command reports any cards left in a corrupted state by this issue prior to the fix (#1106).
