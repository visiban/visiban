Board and card panel: a card no longer briefly reverts to an older copy when the response to your own edit, move, create or restore arrives after a WebSocket frame for a later change to the same card. The web app compares the card's `version` and discards a `card.updated`, `card.moved`, `card.created` or `card.unarchived` frame, or one of those HTTP responses, when it is older than the copy on screen. A failed move now puts back only that card's location, and not over a newer version of it, instead of restoring the whole board from before the request and undoing every change that arrived during it. Full board refreshes now apply the same rule to cards changed while they are in flight (#2038). In the Django admin, a card's `version` is now read-only, so an admin save can no longer set it lower (#1969)
