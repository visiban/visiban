- Fixed nine places where the OpenAPI schema (`/api/schema/`) misdescribed a response field, all found by widening the `serializer-ts-parity` CI check from 5 component/interface pairs to 18 — every pair that has a schema component (#1139). `CardComment.author`, `CardChecklistItem.created_by` and `GroupBrief.parent_name` were published as non-nullable although each can legitimately be `null` (a deleted author, a pre-migration checklist row, a root group); `GroupBrief.ancestors` was published as `string` instead of a list of `{id, name}`; and `CustomFieldDefinition.choices`, `SwimlaneCustomFieldDefinition.choices` and `Group.allowed_priorities` were published with no type at all, so a generated client saw `unknown`/`any` where the first two are a list of strings and the third a list of priority slugs. All seven are documentation fixes: the runtime responses are unchanged, and request validation and its 400 error bodies are untouched. The frontend's `CardMovement` interface is also corrected — `from_column_name`, `to_column_name`, `from_swimlane_name` and `to_swimlane_name` are `string`, never `null`, because the underlying columns are `NOT NULL` with a `""` default.
