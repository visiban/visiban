The group list's `member_preview` no longer joins every direct membership of a listed group to its user before keeping the first five. A new `(group_id, joined_at, id)` index, built concurrently, lets a list of groups read memberships in order, and only the kept members' users are loaded. On three groups of 5,000 members each the preview reads 205 buffers instead of 257, and a single such group 56 instead of 150. The list now runs two bounded queries for the preview instead of one, still flat in the number of groups.
