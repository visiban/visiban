Authorization guards that depend on an input now deny or raise when that input is absent, instead of passing through. A board-membership row serialized without a resolvable reader role no longer carries `is_moderator` or `is_site_admin` (broadcast payloads opt in explicitly and are still filtered per recipient); a card serializer built without a board accepts no label; a swimlane's `limit_column_ids` is refused when no board can be resolved; the board permission classes deny a subject that is not a board; invite recipient binding no longer treats an object without a recipient field as an unbound link; and the admin user patch serializer raises when its target is missing. None of these paths was reachable without its input today. Each guard now has a test for the absent-input branch (#1075).
