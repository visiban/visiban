CI now asserts the response security headers of the bundled nginx templates. A new `nginx-security-headers` job fails when a `location` in `nginx/app.conf.template` or `nginx/app-http.conf.template` declares its own `add_header` (which makes nginx drop every server-level security header for that location), when a required header such as the Content-Security-Policy is removed, or when the two templates drift apart. It also starts each template, and the frontend image's default config, against a stub upstream and checks the headers on representative paths, including `/api/`, `/admin/` and static assets. The templates now carry a comment explaining why the header set must not be split across locations (#1073).
