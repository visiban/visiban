Fixed: a lone UTF-16 surrogate (for example `"\ud800"`) in a JSON request body now answers a `400` instead of a server error on PostgreSQL. This covers JSON values such as a saved filter's `state_json` or a custom field's `choices`, a multi-select custom field value, and the Trello importer's export and `mapping` field. A JSON board import with a surrogate in the file's board name now imports it with U+FFFD in the default name. Valid emoji are unaffected. A card `PATCH` title and the MCP `create_card` arguments were already refused (by Django REST framework and the MCP transport), so they did not produce the server error.
