Fixed: a lone UTF-16 surrogate (for example `"\ud800"`) in a JSON request body now answers a `400` instead of a server error on PostgreSQL. This covers JSON values such as a saved filter's `state_json` or a custom field's `choices`, a multi-select custom field value, a form-encoded or multipart JSON value (a custom field's `choices`, a column `policy`), and the Trello importer's export and `mapping` field. MCP tool arguments are refused as a `validation_error` before the tool runs; on the legacy MCP transport a surrogate escape written directly in the request is refused earlier by the SDK as a JSON-RPC `-32700` parse error (HTTP 400), and a surrogate in an integer argument gets the SDK's own validation error. A JSON board import with a surrogate in the file's board name now imports it with U+FFFD in the default name. A surrogate in a field the endpoint ignores (an unknown key, for example) is now a `400` where it was a `200`. Valid emoji are unaffected. A card `PATCH` title was already refused by Django REST framework. A JSON body or form-encoded JSON value nested about 10,000 levels deep now answers `400` instead of a server error. (#2085)
