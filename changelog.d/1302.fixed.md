**Behavior change:** `POST .../columns/reorder/` and `POST .../swimlanes/reorder/` now reject a partial, duplicate, foreign-board, or (on a board that has columns/swimlanes) empty `order` list with `400 Bad Request` instead of applying it. Previously a partial column list could either collide into `unique_together(board, position)` (returning `500`) or leave a gap, and a partial swimlane list could silently leave two swimlanes sharing a `position`; a duplicate ID let the last occurrence silently win. `order` must now be exactly the board's full set of column/swimlane IDs, matching the rule `POST .../cards/{id}/checklist/reorder/` already enforces (#1292). Clients that always send the full list (the Visiban web app's drag-and-drop already does) are unaffected. (#1302)
