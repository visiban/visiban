Fixed `nightly-load-test` (#1082) never actually running — its required GitLab pipeline
schedule (CI/CD → Schedules, cron `0 3 * * *`, `LOAD_TEST_SCHEDULE=true`) was never created,
so the real p95 latency budget it enforces was never checked, and a genuine ~40% regression
on `GET /boards/{id}/full/` shipped undetected. The schedule now exists, and a new
`schedule-config-check` job runs on every scheduled pipeline to fail loudly if any
`$CI_PIPELINE_SOURCE == "schedule" && $VAR == "true"`-gated job in `.gitlab-ci.yml` ever loses
its GitLab-side schedule again — this class of gap left no trace in the repo before now.
`backend/nightly-load-test-baseline.json` stays `"provisional"` until the first real scheduled
run re-derives it (see `docs/development/nightly-load-test.md`).
