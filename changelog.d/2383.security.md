Cross-board parent/child card links are hardened (#2383). Link writes (linking, and unlinking from either end) have their own per-user rate limit, 300 per hour by default (`CARD_LINK_THROTTLE_WRITE_RATE`, Helm `backend.settings.cardLinkWriteRate`); a write over it gets `429` and changes nothing, and reading a card's children is not counted. Deleting a linked card (REST or the Django admin) and moving one to another board in the Django admin now lock the card and its linked cards in the same order as link writes, so such a delete or move racing a link write on the same pair waits instead of failing with a server error. New tests pin the children read's query count at the 100-child cap and that MCP and board export expose no card links.
