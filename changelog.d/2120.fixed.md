Fixed: a request whose `Content-Type` declares the `charset` `utf-7` (or `unicode-escape`, `raw-unicode-escape`, `punycode`, `idna`, `undefined`, or a non-text codec such as `hex`, `base64` or `rot13`) now answers `400 {"detail": "Unsupported request charset. Use UTF-8."}`. Before, a multipart import (for example the Trello import) with such a charset answered a server error on PostgreSQL, because the charset turns plain ASCII into a character PostgreSQL cannot store. Every other charset, such as ISO-8859-2, Windows-1251 or Shift_JIS, is accepted as before, and an unknown charset is ignored as before. (#2120)
