Fixed: a request that declares a non-UTF-8 `charset` such as `utf-7` on its `Content-Type` (for example a query string `?search=%2B2AA-`, or a multipart Trello import) no longer answers a server error on PostgreSQL. Such a request now answers `400 {"detail": "Unsupported request charset. Use UTF-8."}`. UTF-8, US-ASCII, ISO-8859-1, ISO-8859-15, Windows-1252, UTF-8 with BOM and UTF-16/32 are still accepted, while other legacy charsets (for example ISO-8859-2) are now refused, (the check is default-deny, so it also replaces the server error that `hex`, `base64` or `rot13` caused), and an unknown charset is ignored as before. (#2120)
