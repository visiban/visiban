A WebSocket handshake whose authentication cannot be checked because a server-side store failed is now refused with the server-error code `1011` instead of `4001` (not authenticated), and no longer raises out of the authentication middleware. This covers a cookie handshake during a cache outage with a cache-only session backend (`SESSION_ENGINE=django.contrib.sessions.backends.cache`), and a ticket handshake during a cache or database outage. An absent or expired session, or an invalid ticket, still closes with `4001`. The bundled server (Daphne) answers this pre-accept `1011` refusal with HTTP `403`, so clients see the same refused upgrade as before (browsers report `1006` and the web app keeps retrying); the `4001` and `4003` refusals now reach clients as their code (#2145). A REST request made with the session cookie during the same cache outage is handled separately (#2143). Still not covered: other handshake-time outages (the `cached_db` engine during a cache outage, a database outage) still fail as a server error (#2144). See `docs/api/websockets.md`.
