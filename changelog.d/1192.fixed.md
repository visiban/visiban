- Fixed `BoardExportLogSerializer.actor` not declaring `allow_null=True`, which caused the published OpenAPI schema to describe the export-history endpoint's `actor` field as always present, when `BoardExportLog.actor` is a nullable (`SET_NULL`) foreign key that is `null` for a deleted actor.
- Also declared `allow_null=True` on four further nested serializer fields over the same kind of nullable foreign key — `CardActivitySerializer.actor`, `CardAttachmentSerializer.uploaded_by`, `PublicCardSerializer.assignee`, and `NotificationSerializer.actor` — for correctness and consistency with the rest of the schema. These four endpoints do not currently publish a named schema component for their response shape at all (a separate, pre-existing gap), so this part of the fix has no visible effect on the published document today, but corrects the field declaration ahead of that gap being closed. All five fields are read-only; the live API response was already `null` in each case.
