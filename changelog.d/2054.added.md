Rotating a webhook's signing secret can now keep the old secret signing for a while, so a receiver doesn't reject deliveries while you update it: **Rotate secret…** offers **Keep old secret for 24 hours** or **Revoke old secret now**, and the API takes an optional `overlap_seconds` (default `0`, up to seven days) on `POST /boards/{id}/webhooks/{id}/rotate/`. During an overlap `X-Visiban-Signature` lists two values, `v1=<new>,v1=<old>`, and a receiver accepts a request when any value matches; outside one the header is unchanged. A verifier that compares the whole header rejects every delivery during an overlap, so `docs/api/webhooks.md`, `verify_signature` and `verifySignature` all change to the any-match check. Additive API field: `previous_secret_expires_at` on the webhook object. Changing a webhook's address ends an open overlap. A rotation can't revoke a leaked secret: revoke the old secret and replace it on the receiver. Migration `webhooks/0002` adds two columns, with no index (#2054).
