Board admins can write an explicit policy for each column: entry criteria and a definition of done (**Add policy…** in the column menu, or the new **Policy** tab in Edit Column). A column with a policy shows a **Policy** button in its header that opens the criteria for everyone; dragging a card over the column lists its entry criteria (read aloud for keyboard moves); card detail shows the current column's definition of done. In **Ask the mover to confirm** mode, a drop into the column opens a checklist that must be ticked before the move is sent; a WIP or weight limit block wins, and no checklist opens. Policies are advisory: the server never refuses a move because of one, and the checklist is a web-app acknowledgment only. Additive API field: `policy` on column objects and `column.*` events (`{"v": 1, "entry": [...], "done": [...], "mode": "advisory" | "confirm"}` or `null`, admin-writable), on the MCP `list_columns` tool, and per column in the JSON export, import and board templates (`schema_version` stays 2) (#1101).
