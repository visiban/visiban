With a cache-only session backend (`SESSION_ENGINE=django.contrib.sessions.backends.cache`), a cache outage no longer signs web app users out. A request made with the session cookie during the outage, to any endpoint that authenticates with or reads the session, now answers `503 Service Unavailable` with `code: "session_unavailable"` and `Retry-After: 10` instead of `401`, and no longer deletes the session cookie, so the same session works again once the cache recovers. The web app keeps the user signed in, keeps their recent boards, and retries; a page loaded during the outage shows a "Reconnecting to your session" notice and retries until the cache answers. Views that skip authentication and never read the session (the health probes, the public share-link board) answer as usual. An absent or expired session still answers `401`. Personal access token requests, API token requests sent without the session cookie, and the `cached_db` and `db` session engines are unchanged. See `docs/api/index.md` (Session unavailable).
