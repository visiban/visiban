Fixed: a webhook is now turned off as *fell too far behind* (`cursor_expired`) when history cleanup removed an event it would have sent and had not, using the record `prune_board_events` keeps, instead of estimating from a 23-hour scan gap. A webhook whose missed events were all removed, or whose failing event was removed, is now reported rather than skipped; a webhook that missed nothing keeps sending however long it was idle, and `reenable` with `resume_from: cursor` follows the same rule. A new webhook, and one re-enabled with `resume_from: latest`, starts at the board's newest event or its highest removed event, whichever is greater (#2058).
