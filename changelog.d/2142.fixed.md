When the server cannot complete its access re-check on an open board or group WebSocket (a database outage, for example), it now closes the connection with the new retryable code `4503` instead of `1011`. The bundled server (Daphne) refuses `1011` in a server close, so the old close crashed the connection handler: the client still received `1011`, but the server logged an error traceback for every such close and skipped the connection's cleanup (leaving it in the channel-layer group and its keepalive task running). Clients should treat `4503` like `1011` and reconnect; the Visiban web app does. `1011` stays retryable, since the server still sends it after an unexpected error. See `docs/api/websockets.md`.
