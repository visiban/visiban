When the server cannot complete its access re-check on an open board or group WebSocket (a database outage, for example), the connection handler no longer crashes. The bundled server (Daphne) refuses a `1011` server close, so the old close raised inside the consumer: the server logged an error traceback for every such close and skipped the connection's cleanup (leaving it in the channel-layer group and its keepalive task running). The consumer now closes cleanly, `disconnect()` runs, and no ERROR traceback is logged. See `docs/api/websockets.md`.
