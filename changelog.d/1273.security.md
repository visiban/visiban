Profile updates through `PATCH /api/v1/auth/me/` and `PATCH /api/v1/auth/user/` now apply the same username and email rules as the dedicated flows. A username must be unique ignoring case (as with `POST /api/v1/auth/choose-username/`), and renames share that endpoint's rate limit. On instances with `EMAIL_VERIFICATION=mandatory`, a changed email address takes effect only after it is confirmed from the new mailbox. On those instances, clearing an existing address is refused. Until then the response reports it in a new read-only `pending_email` field, and the Profile settings page shows a *Waiting for confirmation* notice. Both fields remain writable.
