- Fixed no early recovery from the per-account login lockout (5 failed attempts / 5 minutes, #1199): a password reset now clears it automatically instead of leaving a locked-out user refused even with their brand-new, correct password until the 5-minute window expired on its own. Site admins also gained a direct `POST /api/v1/admin/users/{id}/clear-lockout/` action (and a matching "Clear lockout" button in the admin Users panel) for the case where a reset isn't an option. The per-IP rate limit is unaffected and still has no early-recovery path — clearing it would undermine the credential-stuffing protection it provides.
