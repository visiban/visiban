A WebSocket handshake refused with `4001` (not authenticated) or `4003` (no access, or a pending password or username change) on a board or group channel now reaches the client as that close code. The server used to send the close before accepting the connection, which the bundled server (Daphne) answers with HTTP `403` whatever the code, so browsers saw a failed connection (`1006`): the web app reconnected every 3 seconds instead of going **Offline**, and a `4001` never signed the user out. The server now accepts the connection and closes it at once with the code, sending nothing in between and never joining the board or group channel. A client's `open` handler can run just before the close. The `1011` refusal for a server-side outage at the handshake is unchanged and still arrives as a refused upgrade, which clients retry. See `docs/api/websockets.md`.
