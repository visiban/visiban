Helm: a password-protected external Valkey or Redis can now take its password from a Secret, `externalRedis.existingSecret` (plus `existingSecretPasswordKey`, default `redis-password`), instead of from `externalRedis.url` / `cacheUrl`. The chart renders those URLs as plain environment values, so a password inside them was visible in the Deployment spec and `helm get manifest`. The backend percent-encodes the Secret's password into both URLs, so it can contain any character, and an ACL username in the URL is kept. A password embedded in the URLs still works unchanged when `existingSecret` is unset. The render fails if `existingSecret` is set while a URL also carries a password, or while the bundled Valkey is on. See [Password for an external Valkey or Redis](docs/getting-started/kubernetes.md#password-for-an-external-valkey-or-redis) (#1361).
