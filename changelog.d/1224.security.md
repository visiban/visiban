- Helm: the frontend (nginx) Deployment now runs with the same hardening the bundled Valkey StatefulSet (#1200) and the backend/PostgreSQL pods (#1210) already ship with: a non-root user, `seccompProfile: RuntimeDefault`, `allowPrivilegeEscalation: false`, a read-only root filesystem, every Linux capability dropped, and no mounted ServiceAccount token. Scratch space nginx needs (`/var/cache/nginx`, `/run`, `/tmp`) is now an `emptyDir`, never the root filesystem. As a non-root user, the container can no longer bind port 80, so it now listens on the non-privileged 8080 internally — the frontend **Service**'s own port (`frontend.service.port`, 80 by default) is unchanged, since it targets the container by its named `http` port. `helm upgrade` replaces the frontend pod to pick this up — no values change is required, but a custom `frontend.image` that writes somewhere else may need `frontend.securityContext` relaxed; it is a new, overridable, `toYaml`-passthrough value, like `backend.securityContext`. `scripts/helm-structure-check.sh` now asserts `runAsNonRoot` and a full capability drop on every rendered pod with no exclusions. Chart version 0.7.0. See [Pod security](https://gitlab.com/visiban/visiban/-/blob/main/docs/getting-started/kubernetes.md#pod-security) and the upgrade guide.
