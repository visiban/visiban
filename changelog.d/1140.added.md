- Custom fields on swimlane rows (#1140). Board admins can define typed metadata fields that attach to swimlane rows rather than cards — text, number, date, dropdown, and checkbox — managed in **Board Settings → Swimlane fields**, a new tab beside the existing card fields tab (which is renamed from "Fields" to "Card fields" so the pair reads unambiguously). Rows represent entities such as an account, project, or candidate, and until now everything but name, contact email, and notes had to be stuffed into the notes field as prose. Up to 15 fields per board, of which 3 can be pinned to the swimlane row header; pinned values render as chips in the row's label panel, and a `+N` chip opens the full list. Values are edited in the Edit Swimlane modal and appear in `/full/`, the swimlane serializers, CSV and JSON export, and the `swimlane.updated` WebSocket payload. Filtering and sorting by swimlane field values is not in this release — see the limitations table in the docs. Each field carries an **Admin only** toggle, on by default, which serves that field's values to board admins alone — members and viewers never receive them, and anonymous share links never receive any row field values at all. A field's type is frozen once any swimlane holds a value for it, enforced server-side rather than only warned about in the UI.
- Swimlane row field definitions broadcast `swimlane_custom_field.created`, `swimlane_custom_field.updated`, `swimlane_custom_field.deleted`, and `swimlane_custom_field.reordered` on the board channel, so a second admin's Board Settings stays in step without a reload (#1140).
- Swimlane updates arriving over the WebSocket are now merged into local board state rather than replacing it wholesale, so an admin no longer loses a row's `contact_email` and `notes` from their own screen when another admin edits that swimlane. This was a pre-existing bug that row field values would have made considerably worse (#1140).
