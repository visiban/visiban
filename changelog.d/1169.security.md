`allowed_priorities` on both groups and boards now rejects a submitted list longer than 100 entries before validating it, and de-duplicates the stored value (preserving first-occurrence order) instead of storing duplicates verbatim — closing a storage/broadcast bloat vector where an authenticated user could submit a list with up to ~1M repeated entries. An invalid priority value is now truncated to 50 characters before being echoed back in the `400` error body, instead of being reflected in full.
