A WebSocket handshake that hits a database or cache outage outside the cases fixed by #2086 is now refused with the reconnectable `1011`, as those are, instead of failing the upgrade with HTTP `500` and logging the full error message (which can include database or cache hosts). This covers a cookie handshake with the `cached_db` session engine during a cache outage, a cookie handshake with the default `db` session engine during a database outage, and the board and group membership lookups at connect during a database outage, including consumers registered through the enterprise WebSocket routing extension point. Only the error class name is logged. Through Daphne every handshake refusal still reaches browsers as HTTP `403` (#2145).
