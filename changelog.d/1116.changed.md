**Helm chart values are now schema-validated, and unknown keys are rejected.**
`helm/visiban/values.schema.json` declares `additionalProperties: false` on the
chart's own blocks, so a misspelled or invented values key now fails
`helm install` / `helm upgrade` with a message naming it, instead of being
accepted and silently changing nothing on the pod. Blocks passed through to a
subchart or to `toYaml` — `global`, `postgresql`, `valkey`,
`ingress.annotations`, `*.resources` — remain open.

If an existing values file carries a key the chart never read, that upgrade will
now fail. That is the intended behavior: the setting was not being applied
before either. Remove the key, or correct its spelling.

The ingress `proxy-body-size` annotation and the frontend nginx
`client_max_body_size` are now derived from the new
`backend.settings.maxUploadSizeBytes` (default 10 MB, +10 MB of framing
headroom), rather than being separate literals that could drift below the
application's own upload cap. Both resolve to the same values as before at the
chart defaults, so no existing install changes behavior.
