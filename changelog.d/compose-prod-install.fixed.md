- Fixed the production Docker Compose install (`init-prod.sh` / `docker-compose.prod.yml`), which could not serve on a fresh install. nginx crash-looped on a malformed start command; the backend never turned healthy because its healthcheck sent `Host: localhost`, which an `ALLOWED_HOSTS` holding only the public domain rejects, so nginx never started (the healthcheck now sends `Host: $DOMAIN`); and the one-time admin password was written inside the exited `backend-init` container, so `docker compose exec backend cat /tmp/visiban_admin_password` never found it. Upgrade note: `DOMAIN` must now appear in `ALLOWED_HOSTS`, or the backend never turns healthy.
- Fixed re-running `init-prod.sh` to switch `TLS_MODE` or pick up a regenerated certificate silently keeping the old nginx config, and nginx never loading certificates the `certbot` service renewed (it now reloads every 6 hours).
- Fixed a database or Valkey password containing `/` (about half of all `openssl rand -base64` outputs, which the docs recommended) breaking startup. The Helm chart now percent-encodes credentials in `database-url`; `init-prod.sh` rejects a Compose password containing `/ ? # % [ ]` or whitespace up front; and the backend fails with a clear `ImproperlyConfigured` instead of an error or warning that printed part or all of the database or Valkey password to the log. The docs now generate these with `openssl rand -hex 32`. Upgrade note: if you percent-encoded `externalDatabase.password` by hand to work around this, give the plain value again — the chart now encodes it.
- Fixed the upgrade docs for the production Compose stack: they rebuilt images the stack never builds and never changed `APP_VERSION`, so an "upgrade" kept running the old release. The procedure is now set `APP_VERSION`, `pull`, `up -d`.
