The board analytics summary, the analytics endpoint and the MCP analytics tool no longer build one board's dwell figures from a correlated per-card movement check, the same shape #2502 removed from the range metrics. The movement term is now an uncorrelated, board-bounded `IN`; the cards counted are unchanged. This is a partial improvement for #2506, not a complete fix. On the nightly fixture the two statements that read movements drop from 71,153 to 64,033 buffers for the load-test board (74,530 to 72,473 for the aged board), and the cards load and history read are faster in milliseconds (for the load-test board, 26.1 to 18.7 ms and 74.1 to 38.6 ms). The movements read is still instance-wide: the bound is only the card's board, so the `moved_at` index scan still reads every board's movements in the range, the history read still drives from a `card_movements_card_id` merge, and on the aged board the card filter still does a sequential scan of `cards`.
