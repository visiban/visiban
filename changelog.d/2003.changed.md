An open board or group WebSocket whose access re-check cannot complete, for example during a brief database outage, now closes with the standard reconnectable code `1011` instead of `4003`. The frame that triggered the check is still not delivered. `4003` now always means the user has no access (or their credential was revoked), and clients still treat it as final. Before, the two cases shared `4003`, so a server hiccup took the web app's board and group tabs offline until the page was reloaded; they now show the reconnecting state and reconnect on their own once the server recovers. API clients that handle close codes should reconnect on `1011` (#2003)
