- A successful password change through `POST /api/v1/auth/password/change/` now clears a pending administrator-forced password change (`must_change_password`), as `POST /api/v1/auth/change-password/` always did. Previously a user who changed their password through this endpoint stayed blocked from every other endpoint. Both endpoints now share one post-change step that clears the flag and revokes Personal Access Tokens in the same transaction as the password save (#1259).
