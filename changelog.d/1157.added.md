Scheduled jobs: the due-date (`notify_due_soon`) and staleness (`notify_stale_cards`) notification scans, and the `prune_board_events` / `prune_notifications` retention jobs, now have a shipped scheduler. For Docker Compose it is an opt-in `scheduler` service (profile `scheduler`, new `run_scheduler` command, times set by `SCHEDULE_*` env vars in UTC). For Helm it is native CronJobs under `scheduledJobs`. Both are **off by default**, so upgrading changes nothing. Until you enable one of them, or schedule the commands from host cron, users who turn on due-date or staleness notifications receive nothing. Within the scheduler, the notification scans are on and the prune jobs are off until enabled individually. If you already run these commands from host cron, remove those lines before you enable the scheduler, to avoid duplicate notifications. See `docs/administration/scheduled-jobs.md`.
