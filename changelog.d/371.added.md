Custom fields on cards — board admins can now define typed metadata fields per board (text, number, date, dropdown, checkbox), and cards carry values for them. Where a label is an untyped tag, a custom field is a named key with a type: "Array type = raid10", "Hypervisors = 4". Manage the schema at `/api/v1/boards/{id}/custom-fields/` (admin only; readable by every board member, viewers included), and read and write a card's values as `custom_field_values` on the existing card endpoints — the same shape both ways, so the representation the API returns can be sent straight back. Values are validated per type, a cleared field is removed rather than blanked, and up to 30 fields per board can be defined with at most 2 pinned to the card face. Custom fields are included in CSV and JSON board exports (additively — the export schema version is unchanged), arrive with the board on `/full/` as `custom_field_definitions`, and are deliberately **excluded** from public share links, which stay anonymous. Backend only in this release: the card detail UI, card-face pinning, and filtering by field value follow in 1.2 (#371).
