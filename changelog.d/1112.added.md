Added `GET /api/v1/cards/` — a paginated, filterable card query across every board the requesting user can access, for table/list views over large boards and for incremental sync. Supports filtering by board, swimlane, column, assignee, label, priority, due date range, and `updated_since`, plus text search, with cursor pagination (`{results, next_cursor}`) so a client can page through thousands of cards or poll for changes without missing or duplicating rows under concurrent writes. The existing `GET /api/v1/boards/{board_id}/cards/` (200-row cap, no pagination) and `GET /api/v1/boards/{board_id}/full/` (unpaginated) are unchanged (#1112).
