Staleness notifications now have their own **Card has gone stale** preference instead of being gated on **Due date approaching**, which described a different event entirely and is now wired to the due-date warning it is named after. Your existing setting is copied across on upgrade, so what you receive today does not change. Notification creation also now fires a `post_notification_created` signal — a stable extension point that lets additional delivery backends be added without modifying any file in the OSS core (#356). One consequence worth knowing: because **Due date approaching** now drives the due-date warning, anyone who had it on — which until now only opted them into staleness alerts — will start receiving the 24-hour due-date notification as well. Turn it off if you only wanted staleness; **Card has gone stale** keeps those coming either way.
