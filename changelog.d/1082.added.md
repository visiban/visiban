Added `nightly-load-test`, a schedule-only CI job that measures real p50/p95/p99 latency for the board-fetch, card-search (trigram-indexed), card-timeline (activity/movement feed), and notifications-poll endpoints against a large seeded fixture (`manage.py seed_demo_data --scale N --with-notifications`, ~2,400 cards), and fails the scheduled pipeline if any endpoint exceeds its committed budget. Closes the gap the existing `perf-check`/`perf-bench` query-count gates cannot see: a regression from a missing index or a data-volume change can leave the query count identical while making the same queries slower. Budgets are committed in `backend/nightly-load-test-baseline.json`, derived from a measured baseline (~1.4x, per a documented formula) and re-derived at each release — see `docs/development/nightly-load-test.md` (#1082).
