**Operator-visible change:** `docker-compose.prod.yml` no longer defaults `APP_VERSION` to
the mutable `latest` tag. `backend-init`, `backend`, `scheduler` and `frontend-build` now
fail closed (`docker compose pull`/`up -d` and `init-prod.sh` exit immediately with a clear
message) if `APP_VERSION` is unset in `.env`. Any install whose `.env` already sets
`APP_VERSION` — the documented path since `.env.example` has always shipped a pinned value —
is unaffected. If your `.env` omits it, add `APP_VERSION=v<version>` before upgrading; see
`docs/administration/upgrade.md` ("Upgrading to 1.2.x").

Also added a scheduled CI job (`check-release-images`, ported from TruePPM) that fails if the
newest released `backend`/`frontend` image tag is missing from the GitLab registry or GHCR,
and documented both registries' retention/cleanup settings plus the digest-pinning option for
operators in the new `docs/administration/container-image-retention.md` (#1074).
