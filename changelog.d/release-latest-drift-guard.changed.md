Added a pre-tag `:latest` drift guard to `scripts/release.sh`: it runs the existing `check-latest-tag-stability.sh` read-only before branching, and stops the release (with the registry repair commands) if `backend:latest`/`frontend:latest` is not on the newest stable release, instead of failing the tag pipeline after the tag is already pushed. `RELEASE_SKIP_LATEST_CHECK=1` bypasses it.
