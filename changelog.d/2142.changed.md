The server now closes an open board or group WebSocket with the retryable code `4503` instead of `1011` when its access re-check cannot complete (a database outage, for example). Custom clients that list retryable close codes must treat `4503` like `1011` and reconnect; the Visiban web app does. `1011` stays retryable, since the server still sends it after an unexpected error. See `docs/api/websockets.md`.
