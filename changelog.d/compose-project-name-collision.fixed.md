The development and production Docker Compose stacks no longer resolve to the same Compose project. `docker-compose.prod.yml` pinned no `name:`, so it took the checkout directory — `visiban` on a default clone — which is what `docker-compose.yml` also defaulted to. Both files declare a bare `pgdata:` volume and both define `db`, `valkey` and `backend`, so the two stacks shared `visiban_pgdata` and could recreate each other's containers in place. Because Postgres applies `POSTGRES_PASSWORD` only on first init, whichever stack started second met the other's password — or the development `SECRET_KEY` landed on production data. Production is unaffected (`visiban` is what it already resolved to); the development stack now defaults to `visiban-dev` and starts a fresh database — see the upgrade note in the installation guide.
