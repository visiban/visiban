`scripts/release.sh`'s version-consistency checks (against `.env.example`, `frontend/package.json`, `README.md`, the `docs/getting-started/` pages, `docker-compose.prod.yml`, and the Helm chart) now abort the release on failure instead of only printing a `WARN` and continuing to commit, push, and open an MR anyway. Nothing has been committed at the point these checks run, so the abort fully rolls back the release branch (`git reset --hard`, checkout `main`, delete the branch) — the same cleanup already used when the release-notes confirmation is declined (#1269).
