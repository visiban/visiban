Lane-filter `contains` rules and card custom-field text filters now accept `*` (any run of characters) and `?` (one character) wildcards and `/regex/` patterns. A `*` or `?` in an existing `contains` value now acts as a wildcard instead of a literal character; use a regex such as `/\*/` to match a literal asterisk. An invalid regular expression is ignored and shows an inline error. (#2227)
Card text and URL custom-field filters also change: a query of only spaces is now inactive (it used to filter on the spaces), queries and card values are trimmed before matching, a saved or shared query over 500 characters is now invalid and ignored, and a saved query that starts and ends with `/` (for example `/usr/`) is now read as a regular expression.
