A JSON board import with a malformed value — a duplicate or out-of-range column position, a `null`, list, or object in a text field, an over-length name or title, an impossible, out-of-range, or numeric date, or a file too deeply nested to parse — now returns a 400 naming the problem instead of a server error. Import now enforces size caps (labels, per-card comments, checklist items, movements and activities, referenced usernames, and total rows; see the API docs) and strict types: true/false fields must be JSON booleans and timestamps must be strings. Plain numbers in text fields are still stored as text. Error messages no longer echo long values from the file.
