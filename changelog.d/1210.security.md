- Helm: the backend Deployment (its `migrate`, `collectstatic` and `bootstrap` init containers included) and the bundled PostgreSQL StatefulSet now run with the same hardening the bundled Valkey StatefulSet shipped with in 0.5.0 (#1200): a non-root user, `seccompProfile: RuntimeDefault`, `allowPrivilegeEscalation: false`, a read-only root filesystem, every Linux capability dropped, and no mounted ServiceAccount token. Scratch space each image still needs (`/tmp` on every container, PostgreSQL's `/var/run/postgresql`, the backend's `collectstatic` output) is now an `emptyDir`, never the root filesystem. `helm upgrade` replaces every backend and PostgreSQL pod to pick this up — no values change is required, but a custom `backend.image` or `postgresql.image` that writes somewhere else may need `backend.securityContext` / `postgresql.securityContext` relaxed; both are new, overridable, `toYaml`-passthrough values, like `backend.resources`. `scripts/helm-structure-check.sh` now asserts `runAsNonRoot` and a full capability drop on every rendered pod except the frontend (nginx) Deployment, which is not hardened yet and is tracked separately. Chart version 0.6.0. See [Pod security](https://gitlab.com/visiban/visiban/-/blob/main/docs/getting-started/kubernetes.md#pod-security) and the upgrade guide.
