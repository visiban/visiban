Django admin: saving a change to a card now increments its `version` by one, as an API edit or move does, so the web app and other clients can order an admin edit against a concurrent save of the same card instead of showing whichever copy arrived last. Adding a card in the admin still starts it at version 1. Side effect: a move endpoint request or MCP `move_card`/`update_card` call that sends the `version` read before the admin edit now gets `409 version_conflict` with the new `current_version`; requests without a `version` are unaffected (#2040).
