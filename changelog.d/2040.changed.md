Django admin: saving a change to a card now increments its `version` by one, as an API edit or move does (any admin save, including one that only archives or restores the card; archiving and restoring through the API or MCP still leave it unchanged), so the web app and other clients can order an admin edit against a concurrent save of the same card instead of showing whichever copy arrived last. Adding a card in the admin still starts it at version 1. Side effect: a move endpoint request (or MCP `move_card`/`update_card` call, whose `version` argument is new in 1.3) that sends the `version` read before the admin save now gets `409 version_conflict` with the new `current_version`; requests without a `version` are unaffected (#2040).
