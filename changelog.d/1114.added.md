Board change feed: `GET /api/v1/boards/{id}/events/` returns committed board mutations in id order with a resumable `after` cursor, so a consumer outside the Django process can replay what it missed after a dropped WebSocket instead of re-fetching `/full/`. Every event the board channel broadcasts is persisted in the same transaction as the mutation it describes, and WebSocket frames now carry an additive `event_id` naming the matching feed row. Events are retained for `BOARD_EVENT_RETENTION_DAYS` days (default 30) and removed by the new `prune_board_events` management command; a cursor that has aged out returns `410 Gone` with a re-sync hint rather than a page that silently skips events.
