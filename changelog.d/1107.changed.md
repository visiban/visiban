Card create, update, move, archive, unarchive and delete invariants now live in a
`boards.services.cards` service layer instead of inline in the REST views, so a
non-HTTP caller reaches the same WIP, weight, ownership, concurrency and audit-trail
enforcement. The REST and WebSocket contracts are unchanged. `boards.permissions`
gains `get_board_roles()`, a bulk role resolver that shares one precedence ladder
with `get_board_role()`, replacing a duplicate copy of those rules in the MCP tools.
