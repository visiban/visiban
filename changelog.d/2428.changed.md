Analytics requests are now admitted through an operator-configurable concurrency limit (`ANALYTICS_MAX_CONCURRENT`, default 1 per server process) and size limit (`ANALYTICS_MAX_MOVEMENTS`, default 150000 movement rows held in memory per request), on REST and on the MCP flow tools, with the new codes `analytics_busy` (503, `Retry-After`) and `analytics_too_large` (422). A request whose board history needs more than that is refused with `analytics_too_large` once it has read up to the limit, rather than answered from part of the history; operators can raise it. Helm: `backend.settings.analyticsMaxConcurrent` and `analyticsMaxMovements` (#2428).
