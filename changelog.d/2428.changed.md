Analytics requests are now admitted through an operator-configurable concurrency limit (`ANALYTICS_MAX_CONCURRENT`, default 1 per server process) and size limit (`ANALYTICS_MAX_MOVEMENTS`, default 400000 movement rows per request), on REST and on the MCP flow tools, with the new codes `analytics_busy` (503, `Retry-After`) and `analytics_too_large` (422). Boards above `ANALYTICS_MAX_MOVEMENTS` now get `analytics_too_large` instead of a slow response; operators can raise it. Helm: `backend.settings.analyticsMaxConcurrent` and `analyticsMaxMovements` (#2428).
