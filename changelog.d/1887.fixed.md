The OpenAPI schema now declares the query parameters these read endpoints already accept, so generated clients and schemathesis can filter and page them: every filter on `GET /api/v1/cards/` and `GET /api/v1/boards/{id}/cards/` (#1887), plus `search`/`offset`/`page_size` on `GET /api/v1/admin/users/`, `limit`/`offset`/`event_types` on the card timeline, `offset` on archived cards, and the filters and `offset` on `GET /api/v1/boards/{id}/movements/` (#1975)
`search` on those card and admin user lists and `exclude_type` on board movements now answer a NUL (0x00) character with `400` and `code: "invalid_query_param"` instead of a `500` on PostgreSQL (#1887)
