Realtime: a user removed from a board or group no longer keeps receiving its WebSocket events when the `member.removed` event that would close their connection is lost to a channel-layer error. Board and group connections now re-check access before they forward each event, using the same rule as the connection handshake. Each connection caches the result for 5 seconds plus a random 0 to 2 seconds, so at most about 7 seconds pass after the last successful check before the next event triggers a new check. A connection that has lost access is closed with code `4003` before that event is forwarded. A connection whose re-check fails, for example during a database outage, is also closed with `4003`. The same window now applies to role changes that send no `member.*` event on the board channel, such as a group role change, a board moved to another group, or a change to all-content access. It also applies to account deactivation. These changes previously took effect only when the client reconnected.
