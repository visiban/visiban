**Behavior change for API and MCP callers:** column WIP and weight limits now apply to every card write path, not only moves. Creating a card in a column (REST `POST /api/v1/boards/{id}/cards/` and the MCP `create_card` tool), restoring an archived card into it (`POST .../cards/{id}/unarchive/`), raising a card's `weight` with `PATCH`, and saving a card in the Django admin are now refused when they would exceed the limit. Requests that returned `201`/`200` into a full column now return `409` with the move endpoint's bodies (`wip_limit_exceeded`, `wip_hard_blocked`, `weight_limit_exceeded`), and nothing is written. A board admin can override a soft limit with the new optional `?force=true` query parameter on create, restore, and `PATCH`, as on a move; under **Enforce WIP hard** no role can. Lowering a weight or editing any other field is never blocked, even in a column already over its limits. Board import (JSON, CSV, Trello) is exempt by design and still restores a board as exported. The Django admin also now applies `allow_card_creation` when creating a card. Integrations and automations that create or restore cards in limited columns should handle the `409` — see the 1.3 upgrade notes (#1428).
