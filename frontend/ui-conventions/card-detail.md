## Rich text editor

- **`RichTextEditor` is the only editor component** — never add a second Tiptap instance or markdown editor
- View mode uses `react-markdown` with `prose prose-sm` + `rehypeRaw` plugin — **never `dangerouslySetInnerHTML`**
- **Color token overrides: use `[&_el]:text-*` not `prose-el:text-*`** — the `prose-p:text-fg-secondary` modifier syntax is unreliable when class names appear in dynamically-joined arrays; always use explicit arbitrary variant selectors:
  ```
  text-fg-secondary                              ← base color on the prose wrapper itself
  [&_h1]:text-fg [&_h2]:text-fg [&_h3]:text-fg
  [&_p]:text-fg-secondary [&_li]:text-fg-secondary
  [&_strong]:text-fg [&_em]:text-fg-secondary
  [&_code]:text-fg [&_code]:bg-surface-hover
  [&_pre]:bg-sunken [&_blockquote]:text-fg-tertiary
  [&_a]:text-info
  ```
- **`html: true` (default) on the Markdown extension is required** — `html: false` strips `<span style="color:...">` from the serialized output, silently discarding text colors on save. Never set `html: false`.
- **`rehypeRaw` is required on `<ReactMarkdown>`** to render `<span style="color:...">` HTML spans from the Color extension in view mode
- **`onKeyDown stopPropagation` is required on `EditorContent`** — prevents board-level single-key shortcuts (e.g. `f` for filter) from firing while the user types in the description
- **View/edit toggle pattern:** hover shows `border-line-strong cursor-text` + ✎ icon (`group-hover:opacity-100 opacity-0`); click enters edit mode with `border-primary-soft bg-sunken`. Apply this pattern to all future rich editable fields.
- `readOnly` prop must be wired to `!canEdit` at every call site — viewers see rendered markdown only, no hover affordance

## Swapping the open card (#449)

- The only sanctioned way to open a different card from inside `CardDetail` is `window.dispatchEvent(new CustomEvent("visiban:open-card", { detail: { cardId } }))`. `BoardView` owns the listener; no new props, no reaching into board state.
- **Panels replace, never stack.** Stacking card detail panels would create an unbounded Escape / z-index / focus-trap chain with no precedent anywhere in the app. Replacement is what the breadcrumb, the `?card=` deep link, and the command palette already do.
- **Every `<CardDetail>` mount site must carry `key={selectedCard.id}`.** The component seeds `localCard` and its collapsible-section state from `useState(card)` initializers, and its fetch effects key on the card id. Without the key, swapping cards renders the previous card's title, weight, labels, and relations while the new card's data loads — a silent stale-state bug. The only prop-sync is the `card.version` effect below.
- **`BoardView` passes `CardDetail` the live card from `board.cards`, not the `selectedCard` snapshot (#1773).** A conflict reload or forced move replaces the card there; the snapshot never changes. When `card.version` changes for a **remote** reason, `CardDetail` resets the Move popover (closes it, clears its inline error) and syncs only `version`, `column` and `swimlane` into `localCard` (the rest can hold in-progress edits; the version must follow so a checklist `onUpdated` never writes a stale one back). Key the reset on **version, never on location alone**: `useBoard`'s optimistic relocation and the rollback of the user's own failed move change the location but not the version. The reset runs only when the version goes **up**: `useBoard`'s rollback of a failed move restores an older snapshot, which is not a remote change. Versions this component caused are **not remote**: every save bumps the version and returns through `onUpdated`, so `CardDetail` remembers the version of each of its own saves and ignores a bump that matches, ignores bumps that arrive while its own move is in flight (a plain Move or the popover's forced move, #1772), and ignores bumps that arrive while its own save is in flight **unless they come with a location change** (a save never moves a card, and a socket echo of our own PATCH can beat the HTTP response). Return focus to the Move button only if the popover was open and focus was inside it or on `body`. The title field's blur check compares against the last title the field was in sync with (seeded from the card, updated by its own saves), never the live `card.title`: another session's rename must not turn a plain focus+blur into a PATCH of the old title.
- **A remote change that closes an open Move popover leaves a notice in the panel (#1773).** If the popover was open (it always pre-fills its targets, so open means "may hold a selection") and the card did not land exactly on the popover's target, `CardDetail` sets "This card was changed elsewhere. Its current location is shown." in an always-mounted `role="status"` line under the breadcrumb row (empty, so no layout space, otherwise). A card that lands on the popover's target (another session placed it exactly there) is the user's own outcome: it closes silently. So does a remote edit that leaves the card where it was while the popover still holds its untouched pre-filled targets: nothing the user chose is lost. A remote change that arrives while the user's own move is in flight is deliberately not acted on, so the failure keeps its inline error visible; the version-conflict reload that follows is a newer version and then closes the popover with the notice. A successful forced move shows no notice: the popover's own override (#1772) is in flight when its version bump lands, and it lands on the popover's target anyway; a conflict leaves the notice, and the toast remains. A remote bump with the popover closed clears an older notice. The notice also clears when the popover next opens. Exception to one live region per action (the `move_failed` bullet below states the rule): the conflict toast is announced assertively from the shared toast region (§ Toasts), which floats above the sheet at `z-[55]` but sits outside its focus trap, so this line is the in-sheet record of the conflict; a screen reader may announce both, which is accepted.
- **Never render a navigation affordance to an archived card.** `visiban:open-card` resolves against the board's active cards and silently no-ops, so an archived row renders its title as a `<span>`, not a `<button>`.

## Card detail sheet placement (#1914)

Rules this work surfaced that apply beyond the sheet:

- **The card hover peek is suppressed for every card while the card detail sheet is open (#1918).** A floating peek over the sheet covers the fields being edited, and the sheet already shows full detail. BoardCell passes `peekSuppressed={currentCardId != null}` to CardItem (BoardView threads `currentCardId={selectedCard?.id ?? null}` down through SwimlaneRow; the prop is included in `arePropsEqual`). Any new board CardItem call site must pass it too. Opening the sheet clears any pending peek timer and unmounts a visible peek; closing it does not re-show a peek until the next mouseenter. Any new hover-only floating preview on the board follows the same rule; the aging tooltip and hover lift are not covered.
- **A card hover never outlives the pointer, and never trusts `mouseleave` alone (#2508).** Nothing but `mouseleave` ends a hover: no key press, scroll or window blur dismisses it, and the peek is `fixed` at its opening rect. The demonstrated mechanism: the peek is `position: fixed` and can sit under a resting pointer, where it keeps itself open through its own `onMouseEnter` and nothing but a leave would end it (a Playwright test with the pointer resting on the peek and F pressed fails without the guard). Chromium alone usually self-heals after a layout shift, so a card-only shift is not the cause. A hover ended only by `onMouseLeave` can stick. While a hover is live (`hovered` or `peekVisible`), CardItem registers one set of window capture listeners that all call the same `endHover()` teardown (clears `hovered`, the aging tooltip, the pending peek timer and the peek): a `pointermove` outside both the card and the peek (`[data-card-peek]`, so the peek stays hoverable), a `pointerdown` outside the card (the peek included: it has no controls, so a press on it is meant for the filter row or toolbar it covers), a `scroll` outside the card and the peek (the peek is `fixed` at the rect captured when it opened), any non-modifier `keydown` (Escape is the WCAG 1.4.13 dismiss key; the rest end it too because a key means attention has left the pointer, F opening the filter row being the reported case; Shift and the other modifiers are exempt so Shift+click still lands on the expanded card, #2358; skipped while the card's own quick-edit list is open) and window `blur`. The peek also never slides above the board region: CardItem passes `minTop` (the `[data-board-scroll]` top, read with the anchor rect) and the peek's top is `max(placement, minTop)`, so it cannot cover the toolbar or filter row. The peek's `onMouseLeave` calls the same teardown, never a bare `setPeekVisible(false)`. Any new hover-driven surface on a card ends through `endHover()`, not through its own partial reset.
- **A handler that default-prevents `mousedown` to keep focus where it is must first blur or flush any save-on-blur field it is about to unmount.** React runs no `onBlur` on a node it unmounts, so the edit is silently lost otherwise. Reference: the sheet's outside-click dismissal.
- **A ring around a board card uses `ring-offset-sunken`**, the surface the board paints behind its cards, never `ring-offset-canvas`, so the offset gap matches that surface in both themes. This covers `CardItem`'s keyboard focus ring as well as its open-card (`current`) ring.
- **An outside-click dismisser decides explicitly which classes of target it consumes.** Board space and empty cells are consumed; interactive controls elsewhere in the app pass through. Document the split wherever such a dismisser is added.

The card detail sheet sits next to the card it describes instead of at the far right of a wide monitor. It is the documented exception to the anchored-popover rule (#1455/#1457, § Modals and dialogs).

- **The anchor rule** lives in `computeCardSheetPlacement` (`src/hooks/useCardSheetPlacement.ts`), unit-tested on its own. Width 540px, gap 6px from the column edge, which is 12px from the card on gated and ungated cells alike (the cell's 1px border + 5px padding is 6px, and on a gated cell the sub-column anchor is floored 6px from the card, `SUB_COLUMN_CARD_INSET`, #2540; the 5px notch sits inside that gap), 16px from the viewport's right edge. At `<= 640px` the sheet is full-screen. From 641px to 1279px it docks to the right edge. At `>= 1280px` it goes right of the card's column (on a gated cell, the card's sub-column: `[data-sub-column-drop]`, #2540) if it fits, else left of it, else it docks. It never covers the sticky lane labels and never runs off screen. Anchored: top = the bottom of the board chrome + 8px (the board toolbar, or the filter row or a banner below it when shown: the lower of the toolbar's bottom and `data-board-scroll`'s top), bottom 12px above the viewport edge, `rounded-lg border border-primary-emphasis shadow-2xl` (the 1px brand-blue outline is the cue's other half; docked and full-screen keep `border-line`). Docked: full height, square, `border-l border-line shadow-2xl`.
- **The DOM markers it reads are a contract:** `data-board-scroll` on BoardView's scroll container (the root every lookup is scoped to, so the drag overlay copy never matches), `data-card-id` on the `CardItem` face (not on the `overlay` copy), `data-board-cell` on `BoardCell`, `data-sub-column-drop` on `SubColumnDrop` (#2540), `nav[aria-label="Board toolbar"]`. Renaming any of them breaks placement silently; `boardCell`, `swimlaneRow` and `cardItemCompact` tests pin them.
- **No element, no anchor.** A card with no measurable face (a deep link before render, the command palette, a filtered-out card, a collapsed lane or column) docks with no ring or notch, never centered. It switches to anchored if the face appears later (a few frames of retry at open, then a `ResizeObserver` on the board content). After an in-sheet Move the sheet re-anchors to the new column, or docks if the face is gone.
- **Re-placed** on open, swap and Move (layout effect, before paint), and on window resize and board scroll-end after 150ms. The notch alone follows vertical board scroll every frame. The sheet never follows the card vertically and never scrolls the board. Only a scroll of the board container or the document counts: the sheet's own body scrolling is ignored.
- **Notch (#1937, reshaped #1946):** a speech-bubble tail on the sheet's outer edge, `aria-hidden`, `fill-primary-emphasis` (the open card's blue), on a 1px `border-primary-emphasis` sheet border that exists in anchored mode only. Tracking: an isosceles triangle, 12px base on the edge, 5px deep (`M7 6L1 12L7 18Z` in a 7x24 SVG). Clamped (card scrolled out of the 28px-from-corner range): a right-triangle wedge with the same base and depth whose apex is the end nearest the card (`down: M7 6L1 18H7Z`, `up: M7 6H1L7 18Z`, `data-direction`), so the shape alone shows direction and color is never the only signal. Always on the edge facing the card, same SVG both sides: `side=right` (sheet right of the column) puts it on the sheet's left edge with `-left-[7px]`; `side=left` puts it on the right edge with `-right-[7px] -scale-x-100`, no shadow, no stroke, no connector lines, hidden when docked, full-screen or the card is not rendered. **The sheet root must stay `overflow-visible`** (the tail sits outside it): clipping lives on an inner wrapper `flex h-full flex-col overflow-hidden`, with `rounded-[7px]` only when anchored (a docked or full-screen panel is flush and square). Never use `mask`/`clip-path` on the root: it clips `shadow-2xl`. Anything inside the wrapper that shows a focus ring at its edge must use `focus:ring-inset` (the tabs do), or the clip eats it, and an absolutely positioned overlay inside the sheet whose containing block is a positioned element within the wrapper is clipped too, so it must be `fixed` or fit inside the sheet (the wrapper itself is not `relative`, so an overlay positioned against the root is not clipped). The wrapper's `rounded-[7px]` is the root's `rounded-lg` (8px) minus the 1px border: change one, change the other. The tail's `top` is `notch.y - 13` (the SVG's 12px half-height plus 1px, because absolute offsets start at the padding edge and `y` at the border edge); `-left-[7px]` leaves the base 1px over the border and the apex 5px beyond it. **A decorative pointer that links two surfaces must hold >= 3:1 (WCAG 1.4.11) against both of them in light and dark, computed from the token values, never judged by eye.** `primary-emphasis` clears it against the panel (`surface`) and the board (`sunken`, `canvas`): dark 3.98/4.85/5.48, light 3.68/3.52/3.36. `border-line` (1.4-2.0:1 in dark, 1.4-1.5:1 in light) and `border-line-strong` (1.9-2.7:1 in dark, 2.3-2.6:1 in light) do not, so never use them for a pointer or notch.
- **The open card** gets `current` on `CardItem`: `border-2 -m-px border-primary-emphasis ring-2 ring-primary-emphasis ring-offset-2 ring-offset-sunken` and `aria-current="true"` (the 2px border and `aria-current` mean color is never the only signal). BoardView passes `currentCardId` down through SwimlaneRow and BoardCell, so the ring moves with the swap and clears on close.
- **A plain board click opens this sheet; Shift+click, Shift+Enter, the card-face Show summary button and the menu's Show summary open the card peek sheet (#2273, flipped by #2358).** `CardItem` calls `onClick({ peek: true })` for the peek paths and BoardView's `handleCardClick` routes it (default `setSelectedCard`; peek, or any plain click while the peek is open, `setPeekCardId`). The Show summary button (`aria-label="Show summary"`, `title` naming Shift+click) sits beside More actions: revealed on hover or focus, and on touch with More actions as a 44px target. Card-face overlay controls reserve title padding at every pointer type: the title keeps `pr-14` at fine pointers on every interactive board card and the drag overlay copy, gated on the card (`!readOnly && (onClick || overlay)`), not on the menu, which BoardView drops while a sheet is open, so titles never re-wrap on hover or sheet open/close; the Dense row reserves `pr-12` on `card-dense-row` instead, since its status, chip and avatar sit at the right, and ⋯ reserves its `pr-28` at coarse pointers while shown. The fine-pointer button sits at `top-[7px]` like the checkbox, to clear the dwell-overlay tab. Focus goes to Open card on open (not Close). Last moved of a never-moved card reads "Never moved". The hover popover footer carries "Shift+click for summary".
- **The card peek sheet (#2273).** `CardPeekSheet` is a read-only 400px sheet (status strip, every custom field with "Not set", time in each column, history, Open card and Move). It is placed by the card detail sheet's rule, not its own (#2507): `useCardSheetPlacement(card.id, location, dockedPref, PEEK_WIDTH)` with the width a parameter (540 default for the detail sheet, 400 here), so it anchors beside the card's column (its sub-column on a gated cell, #2540) at `>= 1280px` with the same notch, docks to the right edge (full height, `border-l`, light backdrop) below that or when the card has no measurable element, is full-screen at `<= 640px`, re-places on resize and board scroll-end, and plays the same `cardSheetMotion` transitions (it keys on `peekCardId`, so a swap claims the departing sheet's ghost: same side slides, a side or mode change fades). Never give the peek a placement of its own again: it used to sit `fixed right-4 top-24` over the board's right-most columns and jump between cards. Its header carries the shared `CardSheetDockToggle` (same `card-sheet-dock-toggle` test id, labels and `ActiveUnderline`) before Close, reading and writing the same `useCardSheetDockedPref` as the detail sheet, so docking one docks the other; the toggle is hidden when full-screen; any control sized by full-screen mode keys on `placement.mode === 'fullscreen'` or `max-[640px]:`, never `sm:` (the hook's `<= 640px` and Tailwind's `sm` at 640px disagree at exactly 640px); a second sheet sharing this placement reuses `CardSheetDockToggle` and the shared preference; stage chips are `rounded-md` (not pills), history times are relative (`relativeTime`) with the absolute timestamp as `title`, and the pinned note is hidden when the board has no custom fields; Shift+Enter on a focused card face opens it (Enter or Space open the detail sheet) and `useBoardPan` skips arming on that Space (`defaultPrevented` or a `[data-card-id]` target); it never resizes the grid. It is keyed on `peekCardId` in BoardView, separate from `selectedCard`: Open card sets `selectedCard` and clears the peek, and an effect clears the peek whenever `selectedCard` is set or the activity drawer opens, so the peek, this sheet and the drawer are never open together. Opening the peek closes the drawer through `setDrawerOpen(false)`. While this sheet is open a board card click swaps the peek; the deep link, command palette and relation links open it directly. It follows the open-card rules here: focus to Open card on open, `useFocusTrap` with the same card-face then board-region restore target, Escape at priority 30 (Move form first), a press on board space closes it through the same pointerdown-classified, click-consuming catcher (a text-selection drag from the sheet does not close it; an empty cell's "+ Add card" does not also fire), a card click swaps it, drag-and-drop is suspended while it is open (`noSensors`), the Archived panel is closed when it opens and closes it when the Archived panel opens, an admin gets "Move anyway (admin override)" in its Move form for a soft-limit refusal (the toast's override is outside its focus trap), and the open card carries `current` (the ring and `aria-current`) through `currentCardId`. The `data-card-id` marker is the contract for the click-outside test.
- **Backdrop:** none when anchored or full-screen. Docked: `bg-backdrop/20` that is `pointer-events-none` and `aria-hidden`. It is visual only, never a click target.
- **Click-catcher, not an overlay.** A document-level listener closes the sheet on a primary click outside it. It classifies at `pointerdown` and acts at the following `click`, so a touch swipe, a scrollbar drag or a selection drag that started inside never closes it. What happens to the dismissing click is decided per target class. On board space (anything inside `data-board-scroll`, including an empty cell's "+ Add card") and on anything that is not a control, the click is consumed and the press does not move focus (its `mousedown` is default-prevented), so it never also activates what was under it and focus can return to the card. A control elsewhere in the app (a toolbar, sidebar or navbar button or link, `OUTSIDE_CONTROL_SELECTOR` in `CardDetail`) closes the sheet and still works in the same click, taking focus as usual. Before closing, the handler blurs the focused field inside the sheet, so a save-on-blur edit (the title) is saved. "Inside" is the React tree: the sheet's `onPointerDownCapture` marks the native event, so a dropdown or tooltip portaled from inside `CardDetail` counts as inside. A click on a board card (`[data-card-id]`) is left to the card's own `onClick`, which swaps the open card; a press on the open card's own face is default-prevented so focus stays in the sheet. While a sheet is open `BoardCell` renders no selection checkbox (it would take focus out of the `aria-modal` sheet and raise the bulk toolbar behind it). A popover a card face portals to `document.body` (the custom-field quick edit and its dropdowns, the hover peek, which cannot be open while the sheet is, #1918) is part of the board: BoardView's scroll container marks pointer events from its React tree (`markBoardTreePointerEvent`), and the click-catcher leaves a marked event that lands outside the board's DOM alone. A new body-level portal opened from a board card needs no attribute; one opened from elsewhere that must keep the sheet open uses `data-keeps-card-sheet-open`. The shared toast region carries `data-keeps-card-sheet-open`, so every toast stays usable while the sheet is open (§ Toasts). A click inside another dialog opened over the sheet (`[aria-modal="true"]` or `[role="dialog"]`, such as the command palette) is left to that dialog, neither closing the sheet nor being consumed. Swap-by-click is a pointer convenience: keyboard and screen-reader users press Escape, then pick a card.
- **Drag-and-drop is suspended** while the sheet is open (BoardView passes no sensors to the board `DndContext`). The old full-screen backdrop blocked drags too, so this is no regression.
- **Focus:** on open, focus goes to Close. `aria-modal` and `useFocusTrap` stay. On close, focus returns to the opener (the clicked card, or the most recently clicked one after a swap). If the opener is gone (command palette, relation link) it goes to the card's face, and if that is gone too (archived, deleted or removed remotely in the same commit that closes the sheet), to the board region (`data-board-scroll`, `tabIndex={-1}`), never to the top of the page. The fallback is resolved when the sheet closes, not at render: `useFocusTrap` accepts a function `restoreTarget` for exactly this, because at render time the card's face is still connected.
- **Full-screen (<= 640px):** a "‹ Board" back control (accessible name "Back to board", distinct from the toolbar's Board view tab) on the left and Close top-right, both 44px tall. Back, Close and Escape all close and return focus.
- **Transitions** (`cardSheetMotion.ts`, Web Animations API, feature-detected, so jsdom never animates). Open: 180ms ease-out, fade plus a 12px move toward the card. Same-side swap or re-place: a 220ms `cubic-bezier(.2,.8,.2,1)` slide while the old body cross-fades out (80ms) and the new one in (120ms). Side flip, mode change or Move: fade out 90ms, reposition, fade in 140ms. Close: 140ms ease-in, fade plus 8px away. Under `prefers-reduced-motion` every one of these becomes a 120ms opacity change (a swap is 120ms out, then 120ms in). **Transitions never delay a state change.** The departing sheet leaves a "ghost", an inert, `aria-hidden`, id- and role-stripped clone on `document.body` that removes itself, so close and swap unmount the real dialog at once. A Playwright spec that measures the sheet's box must first wait for `el.getAnimations({ subtree: true })` to finish. Desktop Chrome's 1280px viewport is exactly the anchored/docked boundary, so card specs pin a viewport per mode.
- **Long content (frame 5):** the header (title, breadcrumb, tabs) and the footer stay fixed while the body scrolls. A top and a bottom fade show only while there is more content on that side.
- **Shared demo (frame 7):** the anchored sheet starts below the demo bar and app bar. A `DEMO_CARD_DETAIL_NOTE` line sits at the top of the body. Comments, Relations and the PR/MR link (`CardExternalRefSection`'s `demoReason`: Add `aria-disabled` with the reason, no Edit or Remove) are each refused in place with their own reason. The footer replaces Archive and Delete with a `DEMO_CARD_FOOTER_NOTE` line, so the sheet offers no destructive or removing action. This is a UI restriction: the demo fence would allow the archive itself.

## Card detail sheet: Dock to edge toggle (#1915)

- **A user pin that outranks an automatic placement goes into the pure placement function.** `computeCardSheetPlacement` takes `docked` and ranks it below full-screen (`<= 640px`, toggle hidden) and above the 1280px anchor rule, so the precedence is unit-tested without the DOM. Toggling re-places with `PlacementReason` `"dock-toggle"`, which `classifyTransition` maps to the swap `slide` (reduced motion: the 120ms fades), or `none` when the frame did not move.
- **Storage:** `user:prefs:card-sheet-docked` (`useCardSheetDockedPref`, the `useCardLayoutPref` pattern; absent = `false`, no `User` field). It is read once per sheet mount, so a swap keeps the mode. The card peek sheet reads and writes the same key through the same `CardSheetDockToggle` component (#2507); the two sheets are never mounted together, so a fresh mount is the sync.
- **Header order is DOM order = visual order: Dock, then Close** (A-Q8). Focus on open stays on Close; Shift+Tab reaches Dock. The labels are `Dock to edge` (off) / `Open next to card` (on) as both `aria-label` and `title`, with `aria-pressed`.
- **The pressed state is more than a tint (WCAG 1.4.1):** the button renders `ActiveUnderline` (default `inset`, host is `relative`) while docked, per the #2188 icon-toggle rule, with the icon swap and border (`bg-surface-hover border-line-strong`) as reinforcement. `aria-pressed` stays the state.
- **Test pins:** Playwright specs for placement pin a viewport per mode (1600 anchored, 1024 docked, 640 full-screen); the dock toggle is exercised at 1600 where it changes the mode.

## Card detail tabs and the History type filter (#967)

- **Tabs are Details · Comments · History**, a full tablist (roving `tabIndex`, Left/Right/Home/End with wrap, `focus:ring-inset` for the sheet's clip). A tab with a count shows it in a `ml-1 font-normal text-fg-tertiary` span and gets an explicit `aria-label` of `"<Label>, <count>"`: a visually hidden comma span is padded with spaces by name computation (Chrome and jsdom both give "Comments , 4"). Details has no count. **While a count is unknown, the tab shows its label only, never `0`.**
- **Counts come from data the sheet already fetches**, never a new `CardSerializer` field: Comments from the loaded comment list, History from the first timeline page CardDetail fetches on open with `include_counts=true` (summed `counts`). That page is refetched on `refreshSignal`, on `card.version` change and after this session posts a comment, and is passed to `ActivityTabPanel` as `initialPage` so History opens with no second request.
- **Which tab opens is session memory** (`cardDetailTabMemory.ts`, module scope): last chosen, kept across swaps and closes, never written to storage. A deep link `?card=…&tab=details|comments|history` overrides it (BoardView consumes and removes `tab`); an unknown value is ignored silently. A programmatic switch (Block… selecting Details) does not change the memory.
- **Details ends with the Last activity line**: one `text-xs text-fg-tertiary` button, "Last activity: {who} {what} · {relative time}", whose name ends with a visually hidden ". Go to History". It selects History and focuses the newest entry (`li` with `tabIndex={-1}` and a focus ring). No line when the card has no history or it has not loaded.
- **The History type filter is an independent `aria-pressed` group** (`role="group" aria-label="Show"`), not a tablist and not a menu: one text button per timeline group with `ActiveMark` and its count from `counts` (no number while unknown). All start on. The last button that is on is `aria-disabled`, with `title` and `aria-describedby` "At least one type stays shown", and its handler ignores activation. The group is data-driven (`EVENT_TYPE_OPTIONS`) so a later group (Readiness, #1922) is one entry.
- **The comment composer is pinned to the bottom of the Comments tab** (`sticky`, `bg-surface`, `border-t border-line`), so a note can be written without scrolling the thread. **A control pinned to the edge of a scroll body that has an edge fade must suppress that fade** (or sit above it with a divider): the body's bottom fade is not drawn on Comments when the composer is shown. Posting scrolls the new comment into view; switching tabs resets the body scroll to the top.
- **A filter that changes a list announces the new total** through an always-mounted polite status ("12 events"), and compact toggle chips use at least `py-1`. A toggle chip with a count gets `aria-label` "<Label>, <count>", like the tabs.
- **A control with a desktop and a phone variant under one `role="group"`** (pills on desktop, a native `select` below `sm`) gives the group the concept's name and the inner control a distinct accessible name ("Filter users" group, "User status" select), so a screen reader never announces the same name twice (#2501).
- **A server-paged, server-filtered list fetches its page again when a row leaves the filter or a row is created**, never drops or adds the row locally (a prepended row is out of the server's sort order and makes a page one row too long): a local removal shifts the server's pages (Next skips a row, an emptied last page shows "Showing 51–50 of 50"), so a page that comes back empty steps back one page. Its fetch ignores every response but the latest (a request sequence ref, as in `ActivityTabPanel`), and a refetch that runs after an `await` reads the page, search and filter from a ref set on every render, since the newest request wins and its closure's query may be stale, and focus after a removed row goes to the filter control that is visible at this width (the select on a phone, the pressed pill otherwise, chosen with `useIsPhoneViewport`, the same signal as the layout) (#2501).
- **A settings buffer with an inline error clears that error on `onChange` and validates again on blur**, so a corrected value never keeps showing a stale error (#1572).
- **Constraint text, such as a date limit or a maximum, goes in the field's `hint`**, never only in `title`: a tooltip does not show on touch and is not a reliable accessible description (#1572).
- **A text-only link-like button in the sheet** (the Last activity line) has a persistent non-color cue (`underline decoration-dotted underline-offset-2`) and `py-1`, and wraps rather than truncating, so its end (the time) stays visible.
- **History surfaces share one label helper and fail soft (#2365).** The History tab and the peek History list render a given event through one shared label helper (`cardTimelineLabels.ts`). A secondary fetch that enriches a primary list (gate rows over movements) fails soft: it never replaces the primary rows with an error, it adds a small note. System-caused changes (stage-settings remaps) never use user-action verbs like "Moved" (they read "Now in …"); an imported row replays a person's move, so it reads "Moved to …".

## Destructive action in an editor footer; form error slot; locked attributes (#2194)

- **A destructive action offered from an editor goes in the editor footer, far left.** Use `mr-auto` and the danger button style (`bg-danger-bg hover:bg-danger-bg-hover text-on-danger font-medium rounded focus:ring-danger-emphasis`). DOM order is Delete, Cancel, Save so Tab follows the visual order. It renders only for an existing record (hidden, not disabled, for non-admins and for a new one; disabled only while a save is in flight, a transient state and not a permission), never takes default focus, and opens the same confirmation as the row-level delete: one canonical delete confirmation per resource. Reference: custom field editors (`BoardSettingsFieldsTab`, `BoardSettingsSwimlaneFieldsTab`).
- **A form's reserved error slot is `min-h-4` with `role="status" aria-live="polite" aria-atomic="true"`, never a fixed `h-4`,** because refusal copy can wrap.
- **A locked attribute explains itself in visible text next to the control, never only in a `title`.** The reason is a visible `text-xs text-fg-muted` paragraph directly under the control, referenced by `aria-describedby` on a `role="group"` (or on the control). It names the reason and the way out and states the consequence. The string lives in one shared constant per resource noun (`typeLockedMessage`, `src/constants/customFields.ts`). `title` is a supplement, never the only carrier, because disabled controls don't fire hover or focus.

## Card detail key-facts row and section counts (#1916)

- **The key-facts row is header row 3**, between the title/breadcrumb row and the tabs, outside the scrolling body so it stays put. It is one `<ul aria-label="Key facts">` of `border border-line rounded px-1.5 py-0.5 text-xs min-h-6` buttons (the custom-field chip family, not a new pill exception). The facts are data (`buildKeyFacts`, `utils/cardKeyFacts.ts`): an ordered list of `{key, target, text, label}` where a later fact (Readiness, #1922, between due/urgency and the pinned fields) is one more entry and not a renderer change.
- **A fact that does not apply is not produced**, so nothing is reserved for it. Board-specific facts (deal value, stage) come only from pinned `show_on_card` fields that have a value; never from unpinned fields.
- **Every fact's accessible name ends "Go to <field>"** ("Assignee: Alex Brown. Go to Assignee"). The visible text is the value only; the glyph (▸, ⚑) is `aria-hidden` and never the only carrier of urgency (the text says "Due …").
- **A jump is switch-tab, open, scroll, focus, in that order**: select Details if needed, open a collapsed section, then (after that render) `scrollIntoView({block: "start"})` on the section marked `data-fact-section="<target>"` and focus its first control. The scroll is `behavior: "auto"` (instant) under `prefers-reduced-motion`, smooth otherwise. A new jumpable section needs only a `data-fact-section` attribute and a `KeyFactTarget`.
- **Read-only viewers keep the row.** A fact whose only action is an edit surface (the Column fact opens the Move popover) renders as a non-interactive chip, not a dead button, when the viewer cannot do it (`inertTargets`).
- **Overflow is measured, not truncated**: at most two lines, then a trailing `+N` button (`aria-expanded`, visible text `+N`, with an `sr-only` " more facts") that expands the row in place and becomes "Show fewer". The `+N` itself must land on line two or earlier. Re-measure on width change.
- **Section counts use `Label N`**, in the label's own span (`normal-case font-normal`), with no parentheses (except Custom fields, which keeps its existing `(N)`). Zero is shown ("Relations 0"). An unknown count (still loading, or the fetch failed) shows no number, never `0`. Counts come from the state the section already renders (a refetch keeps the last known count). The Checklist heading is owned by #445 and is not changed here.
- **Label-in-name and inert chips.** A fact's accessible name contains its visible text, first where it is the whole label (abbreviated or truncated text like "Due 11/20/2020" or "Deal value $4…" is never replaced by a different phrase); a truncated chip carries the full value in `title` and the name. A chip that cannot be activated is `role="group"` with the name, never a bare `aria-label` on a `span`. Fact chips stay 24px (`min-h-6`) on a phone too; they are a dense secondary row, and every jump target remains reachable by scrolling.

## Checklist item trailing controls (#445)

- **Always visible.** The checklist row's assignee and due buttons (`ChecklistItemControls`) are never hover-revealed: a second scoped exception to hover-reveal, justified like #371 (an occasional user must find them). Both are `type="button"`, carry the design § 5 accessible names ("Assign {item}" / "Assigned to {name}. Change assignee for {item}"; "Set due date for {item}" / "Due {date}. Change due date for {item}") and the standard focus ring.
- **Face suffix.** At most one suffix after `✓ 3/7`: `· ⚑ N` (overdue items, `text-danger`; the flag is `UrgencyGlyph` (#871)), else `· mine N` (`text-fg-tertiary`). Derive both client-side with `checklistFaceSuffix` from `checklist_open_due_dates` / `checklist_open_assignee_ids`; never feed a checklist due date into `classifyCardUrgency` or the card border (A-Q9).
- **Assignee pickers** in the row use `isAssignableMember`, like every other assignee picker. The picker is a plain list of `aria-pressed` buttons (never `role="listbox"` with a button inside an `option`), marks the current value with `Common/SelectedCheck`, focuses the current value on open, and moves with ArrowUp/ArrowDown. A former member keeps the assignment and the button says "(no longer a board member)".
- **Read-only rows show values, not dimmed controls.** A user who cannot edit the item (viewer, or the creator-only gate) gets no `disabled` button: an empty assignee or due date renders nothing, a set one renders as plain text (avatar or date) with a `title` and an `sr-only` sentence. Never render a dimmed control the user cannot use.
- **Minimum target.** Trailing row controls are `h-6 min-w-6` (24×24px), so the glyph-only state is never narrower than it is tall.
- **One text tone per element.** Never stack two `text-*` / `hover:text-*` utilities on one element (CSS source order, not class order, decides the winner); build the tone string conditionally (`NEUTRAL_TONE` / `DANGER_TONE`).
- **Text-only face indicators need `sr-only` text.** The face suffix glyphs are `aria-hidden` and a sibling `sr-only` span carries the sentence ("1 overdue checklist item"); a `title` alone is not an accessible name.
- **Native date input commit/cancel.** Enter commits (by blurring), Escape abandons the edit; a cancel ref guards the blur that some browsers fire on unmount.


## Card-detail extension sections and parent-item naming (#2212)

- **Extension sections** (`CardExtensionSections`) render plain text only, with no colors, badges or links of their own: label `text-xs font-semibold uppercase tracking-wide text-fg-muted`, value `text-sm text-fg-secondary`, an empty value as "Not set" in `text-fg-muted`, the same anatomy as the custom-field rows. Each section is a `<section role="region">` labeled by its own `<h3>` (`useId`, never the extension id in a DOM id) and renders its own trailing `border-t border-line`. While loading, after a failed fetch and with no sections they render **nothing**: no heading, skeleton, placeholder or reserved space. The payload goes through `parseCardExtensionSections` before rendering. Read-only in v1: no edit affordance.
- **Parent-item name** appears in exactly two places in 1.3: the child-side parent row heading (`CardParentSection`) and the parent picker's "{board} calls these {plural}" helper line (omitted when the plural is empty). It goes only through `utils/parentItemNames.ts` (the "Parent" / "Parents" fallback lives there), and never on the public share. The word "Children", the Children tab, the rollup chip, the Parent filter and the picker title never change.
- **Suggestion buttons** (`ParentNameSettings`): `aria-pressed` is derived from both fields (pressed only when both trimmed values equal the suggestion), never stored; each carries `ActiveMark`, a `border-line-boundary` border and is at least 44px tall.

## One child board per parent, never split (#2208, #2206)

A parent card's children all live on **one** board, and no UI path may split them: not a link, not Add child, not a default-child-board change, not an admin move. Any surface that creates or links a child must honor it:

- **Add child with children already present** uses the board they are on (`child-board-options` → `fixed_board`); it never offers another board. When that board is `{hidden: true}`, Add child is unavailable to the viewer, never re-routed.
- **A default child board change** applies only to parents with no children yet. Copy that explains it says so ("Changing this affects parents with no children yet.").
- **A refusal is the server's `children_on_other_board` code**, rendered as its message; the client never pre-filters it away silently.
- **Different parents on one board may use different child boards** (#2206 decision D): the rule is per parent, not per board.


### Tokens must exist in `tailwind.config.js` (#2208)

An unknown utility such as `text-warning-text`, `text-primary-text` or `bg-primary-bg` compiles to nothing: no build error, no test failure, and the control silently loses its color or fill. Before using a semantic token in new code, confirm it is in `tailwind.config.js` `theme.extend.colors`. Warning text on a tint is `text-warning-on-tint`; link text is `text-info`; a primary fill is `bg-button-primary hover:bg-button-primary-hover`.

A full-screen phone sheet's footer buttons and text inputs carry `max-sm:min-h-11`; the desktop `py-1.5` size is not enough below 640px.

## Child progress footer — segment key (#2210)

A parent card on a board whose cards can have children ends in a footer under a 1px `border-line` hairline (`CardChildrenRollup`). Its segment bar draws one segment per child, `flex-1` and 6px tall with 2px gaps so the bar fills the row, in board order (planned, to do, blocked, doing, done); above 8 children it becomes one proportional meter. The key, which never relies on color alone:

| Segment | Meaning | Look |
|---|---|---|
| Done | the child's column is flagged done | solid `bg-success` |
| Doing | any column between the first and done | 1px `border-info` outline, left half filled (`text-info`; 5.75:1 dark, 5.17:1 light on the card, where `bg-primary` was 2.83:1 in dark) |
| To do | the child board's first column | **solid** 1px `border-fg-tertiary` outline |
| Blocked | manual block or an open `blocks` relation; overrides the column | 1px danger outline plus diagonal stripes |
| Planned (#2551) | planned for a later column and not released; drawn first, before to do | **dashed** 1px `border-fg-tertiary` outline |

Rule: **dashed outline = planned, solid outline = to do.** The blocked count is danger-on-tint text with the filled blocked glyph; only the idle line ("Work idle 9d", `text-warning-on-tint`) uses the clock glyph. Visible movement text uses the short forms ("Work moved 2d ago", "Work idle 9d", "Last work done 1d ago"); the accessible sentence keeps the full words ("work moved 2 days ago").

**Planned children in the footer (#2551).** Planned is its own count (`children_rollup.planned`), never in to do, and the movement line reads only the work needed now (`neededNow`), so a parent whose remaining work is all planned never says "No work started" or "Work idle". Row 2 reads "2 planned · work moved 1d ago", or "2 planned" alone. Two warnings replace row 2 when present, in `text-warning-on-tint` with **no glyph**: "Qualify: 1 child not started" (released by the parent's move, not yet moved) first, then "1 planned date has passed: Dec 4" (the earliest planned date before today, compared in the instance timezone like the child's "passed while planned" line). The sentence adds "N planned" after to do and replaces its movement clause with "; Qualify: 1 child not started" / "; 1 planned date has passed, Dec 4". The footer is one `role="group"` whose `aria-label` begins "Children: …"; its visible rows are `aria-hidden`. A board the viewer can't open shows only "N children on a board you can't open".

## Phone bottom-sheet selects and inactive-date helpers (#2549, #2552)

- **A select that the canvas opens "as the phone's bottom sheet" opts in with `SelectDropdown phoneSheet`.** Below 640px the same listbox renders pinned to the bottom, full width, 44px rows, over a `bg-backdrop/60` scrim (the `ModalWrapper` backdrop token, never `bg-black/N`); a tap on the scrim is the outside mousedown that closes it, and focus stays on the trigger (`aria-activedescendant`, as on desktop). In sheet mode the panel is a `role="dialog"` named from `sheetLabel ?? ariaLabel` (its listbox carries the same name); pass `sheetLabel` to name the sheet alone, because `ariaLabel` also renames the trigger (which has a visible label, so it must not be overridden) with a visible 44px Close row that dismisses it and returns focus to the trigger, `document.body` scroll is locked while it is open (the prior `overflow` is restored on close and on unmount), and the close-on-outside-scroll rule is off because the pinned panel cannot detach from its trigger. Known gap: no focus trap, so Tab can leave the sheet; focus stays on the trigger and the scrim and Close are the dismiss paths (design debt, tracked in #2642).
- **Never toggle `disabled` on a control during its own async save.** A disabled button drops the focus `SelectDropdown` just returned to it; ignore re-entry while saving instead (`CardNeededField`).
- **Inactive-date helper copy:** a bold lead phrase ("Inactive while planned.") then a desktop sentence in `max-sm:hidden` and a short phone sentence in `sm:hidden`, under one `aria-describedby` id (both use `display:none`, so only the visible one is read).

## Children tab and its lens (#2209)

1. **(R-A) A layout threshold is measured on the container it applies to, never assumed from an outer width.** `CardChildrenTab` switches between four side-by-side columns and one column at a time on its own `ResizeObserver` width. That width is the sheet minus its 20px side padding and a scrollbar gutter, so `WIDE_MIN_PX` (800) is set below a hypothetical 880px sheet width with slack. The card sheet is 540px (full screen at or below a 640px viewport), so the side-by-side layout is unreachable in the shipped sheet; the e2e spec asserts one column at 880, 540 and 390 and a Vitest case pins the threshold on a measured container.
2. **(R-B) WIP state is said in words, never by color alone.** The limit line reads "limit N, at limit" or "limit N, over limit"; the meter adds a non-color cue (striped when over, a solid end cap at the limit).
3. **(R-C) A live region re-announces a repeat and clears stale text.** An identical consecutive message alternates a trailing no-break space so the content changes; the text is cleared after 8 seconds (the visible default-not-set notice stays). The write's own message wins: `localWrite` is set at the start of the write (before its await) and the next re-read to land is swallowed (the data still refreshes), because the `card.children_changed` ping carries no actor and the actor's own socket receives it too. **Accepted trade-off:** a genuinely simultaneous remote change whose re-read lands in that window is not announced separately; a ping after the write's re-read has landed is announced once.
4. **(R-D) A filter option list is capped and scrolls** (`max-h-64 overflow-y-auto`), and two options with the same title are told apart by appending the card id: "Title (#12)".
5. **(R-E) Card tap targets are at least 44px on phone.** The child card link, Move and Unlink are `min-h-11` (Move and Unlink also `min-w-11`) below the wide layout.
6. **(R-F) A picker on another board's data honors that board's rules for this viewer, from the payload, never a local guess.** The Move picker reads the child board's `enforce_wip_limits` / `enforce_wip_hard` and the viewer's role there (`moveTargetState` in `cardChildren.ts`): a disabled row is a move the server would refuse for the column's WIP limit (the picker models column WIP limits only; column weight limits and swimlane limits are not in the payload, so the server re-checks them and its refusal is shown on the picker's error line), an admin past an enforced limit moves with `?force=true`, and an advisory limit says "not enforced" instead of disabling. A rule the payload does not carry is added to the payload (additive) before the picker models it; until then the server's refusal is the backstop.
7. **(R-G) A cross-board round trip is carried in the URL and dropped on arrival.** A child opened from the tab gets `from_parent=<parent id>`; its "‹ <parent>" link returns with `tab=children&focus_child=<child id>`. `BoardView` reads all three with `card=` and deletes them in the same `setSearchParams`, so a reload or a shared link never re-applies them. The header shows the Back link only when `from_parent` equals the card's own visible parent, so a hand-edited id names nothing.
8. **(R-H) A removable filter chip outside the board's filter bar is `FilterChip`** (`Board/FilterChip.tsx`), never hand-rolled: it brings the tokens, truncation, the `{tag}: {label}, remove` name and the `max-sm` 44px remove target. The History view's Parent chip uses it. A date's overdue state is also said in words for assistive tech (an `sr-only` "Overdue,"), never by `text-danger` alone.
9. **(R-I) A move that turns a planned date live warns as a status line, never a confirm (#2550).** Both Move popovers (card detail and the Children tab) render `PlannedMoveWarning` (`Card/PlannedMoveWarning.tsx`): `role="status"`, always mounted (`sr-only` and empty when silent, so the live region exists before its text arrives), `text-warning`, no glyph, "Its date, Dec 4, has passed. It will be overdue once moved.", shown only for a planned card with a passed date whose target leaves the first column for an open column; Move stays enabled. A Children tab row reads its planned state from the row's own `planned` (#2553) through `buildPlannedStatusLine`, never `formatDueDate(...).overdue`. After a Move, focus goes to the moved card: the card on the Children tab, the sheet's Move button in card detail, never `<body>`.

## Child progress, live cues and failed reads (#2210, #2448, #2441)

- **Live-change ring.** Only the rollup segments that gained a child ring, for 2s, in `ring-info` (never `ring-primary`: 2.83:1 on the card in dark). It is a non-text cue and needs 3:1 against what it is drawn next to, in both themes. So it is **never `ring-inset`** and never an offset-less ring: on a Doing segment that put it on its own info outline and fill (1:1), on Done 1.03:1 light / 1.46:1 dark. It is `ring-2 ring-info ring-offset-1 ring-offset-surface` (plus `relative z-10` so a later sibling cannot paint over it) on both the segment bar and the meter, which is therefore not `overflow-hidden`; the segment bar uses `gap-1` so the 3px reach never covers an unchanged neighbor. In the flush meter a ringed group's offset and ring do cover up to 3px of the neighboring group and the meter border for the 2s; that is accepted, since the change is also announced in words. `e2e/child-rollup-2210.spec.ts` measures the ring against its offset and the card for a Doing and a Done segment on the 6-child bar and the 12-child meter: 5.17:1 light / 5.75:1 dark. It has no transition, so it is reduced-motion safe. The change is also announced once through an always-mounted polite `sr-only` live region.
- **The rollup footer's relative times** ("Work moved 3 hours ago", "Work idle 9 days") read `useSharedMinuteClock()`: one interval for the whole board, cleared when the last subscriber unmounts. Never add a per-card `setInterval`. The card face's own cues (the recent-move dot, the aging tint and idle days, overdue) still read `Date.now()` once per render and refresh only when the card re-renders; moving them onto the shared clock is not done.
- **A failed read that decides whether a control is usable** (blockers, permissions) shows a one-line `text-warning-on-tint` `role="status"` explanation and a Retry; it never leaves the control looking usable with no word. The Add child chooser's load failure has the same Retry.
- **Cross-board settings links** use router `Link` to `/boards/:id?settings=<tab>`; BoardView opens the tab for admins only and strips the param. The link is 44px on a phone (`max-sm:min-h-11`).
- **`border-line-strong` measures 2.56:1 light / 1.93:1 dark.** Do not use it where a border is the only cue (a lock-row outline, a drop target); use `border-line-boundary` (at least 3:1 on `surface`, `surface-sunken` and `canvas` in both themes) or `border-fg-tertiary`. #2505 moved the two dashed swatches (Automatic in `ChoiceColorPicker`, the empty custom trigger in `ColorSwatchPicker`) to `border-line-boundary`: line-strong measures 2.56/2.45/2.34 light and 1.93/2.36/2.66 dark on surface/sunken/canvas, boundary 4.76/4.55/4.34 light and 3.64/4.45/5.02 dark. Exempt, because visible text names the control (WCAG 1.4.11 applies only where the border is needed to identify it): dashed bordered buttons with a text label (`CardRelationsSection`, `CardExternalRefSection`, `CardDetail` add-link, `LaneTeamAssignee`, `BoardCell` hover edge (decorative hover feedback; the focus ring and the `Add card` label identify the cell), `BoardView` Modified tag), the `ImportBoardModal` and `TrelloImportModal` dropzones (each holds a text label that names it, though the border doubles as the drop area's extent), and disabled controls. A new dashed control with no text label must use the boundary token.


## Field sets (#2570)

1. Field set size toggles (Summary, All fields) use `aria-pressed` plus `ActiveUnderline`. Maximize is an action button (`aria-haspopup="dialog"`), never a pressed state.
2. Field set progress excludes checkbox, dimension and hidden admin-only fields; "missing" must never mean "No".
3. A set that is out of the card's lane never hides a stored value: it renders Collapsed with "Not used in {Lane}".
4. Escape priorities: **30.5** is the field set Maximize layer (above the sheet's 30, below 31–37.5; field inputs at 41 still win); **40.8** is the field-set editor's delete and discard confirms and the "Copy a field set" modal; its Add field and Swimlanes menus use **41**. Both belong in the `useEscapeStack.ts` priority table.
5. The field-set delete and discard confirms are #1367 focus-return sites: Cancel takes focus; on close, focus returns to the control that opened them.
6. A structural live update (a set renamed, deleted, or a field moved) never unmounts a focused field row: keep the old grouping until that row blurs, then apply and announce.
7. The Maximize scroll region keeps `scroll-pb-8` under its `h-8` bottom fade, pinned by a Vitest assertion (`fieldSets2570.test.tsx`), and by the Maximize case in `overflow-fade-focus.spec.ts`.
8. Summary chips never shrink or truncate: missing fields first, then as many whole chips as fit (measured), then "+N". Never a fixed per-viewport count.
