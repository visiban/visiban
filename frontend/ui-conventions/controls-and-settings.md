## Admin table row overflow menu (#1291)

When an admin table row (e.g. Admin → Users) accumulates enough conditional per-row actions that a no-wrap `flex` cell starts depending on the table's `overflow-x-auto` wrapper to absorb the width, fold the low-frequency actions into an `OverflowMenu` rather than letting the row keep growing — the same fold used for the column kebab (§ Column kebab menu below), applied to a table row instead of a column header.

- **Keep inline only the actions used most often** — for Admin → Users that's Deactivate/Reactivate and Make/Demote admin. Everything else (Grant/Revoke all-content, Force reset, Clear lockout, Restart onboarding tour) is a support action reached far less often and belongs in the menu.
- **Trigger:** `OverflowMenu` with `ariaLabel={`More actions for ${displayName}`}` — unlike the column kebab, the admin-table trigger is **not** hover-revealed (`opacity-0 group-hover:opacity-100`); admin tables are keyboard/mouse-scannable lists, not a hover-dense canvas, so the trigger stays visible at rest like the other row buttons.
- **Build the items array inline in the row render** (not `useMemo`, since a table row isn't its own component the way `ColumnHeader` is) — the array is small (at most 4 items) and the row already re-renders on every users-list update.
- `OverflowMenu` itself renders nothing when a row's items array is empty — don't add a separate conditional to hide the trigger.

## Feature parity between self-service and admin-initiated equivalents

**Invite by email (#731, #1444).** `EmailInviteForm` is shared by the site, group and board surfaces; a new surface passes `surface`, `roleOptions` and `showLinkDivider` and must not fork the copy. Its pickers pass `SingleSelectDropdown`'s `ariaLabel` (`"Role"`, `"Expires"`) because the trigger's visible text is only the selected value.

**Board invite links (#439).** The UI noun for a board's shareable link is **"invite link"**, never "share link": the board already has a public, sign-in-free Share link in Settings → Sharing, and the two must never be confused. Invite links live in Settings → Members (the "New link" button sits on the "Pending invites" heading row), never in the Sharing tab. A board invite link **always expires** (1, 7 or 30 days, default 7) — the create form never offers "Never". Since #1727 the same holds for group invite links, and neither form offers the Admin role (a shareable link is a bearer credential); the group *email* invite form still offers Admin. Rows created before #1727 can still show "Never" and Admin, so the list keeps rendering both. When the site's `registration_mode` is not `open`, the create form says so (`New users can't sign up from an invite link on this site. Only people who already have an account can join with it.`), because a shareable link never creates an account on an invite-only or closed site.

**Inline revoke in an admin table row (#439).** In a `<table>` (Admin → Board Invites), the inline Confirm/Cancel prompt renders as an inserted `<tr><td colSpan={columnCount} className="px-4 pb-2.5">` directly below its row, never inside the Actions cell (which would stretch one column). The trigger's `aria-label` names both the item and its container (`Revoke invite {prefix} for {board}`), since many rows share the "Revoke" label.

When a feature has both a self-service control (Settings) and an admin-initiated equivalent (Admin panel) — e.g. "Restart onboarding tour" in `SettingsPage.tsx` and the matching per-user action in `AdminPage.tsx` — both use **identical action copy** and **the same success/error feedback pattern** (inline `text-success`/`text-danger` message, same auto-clear timing). Do not let the two surfaces drift into different wording or different feedback mechanisms for what is, from the affected user's perspective, the exact same state change (#1280).

## Color swatch pickers

- **Use the shared `components/Common/ColorSwatchPicker.tsx` for any row of color swatches (#1893).** Do not hand-roll a `.map()` of swatch buttons. It owns `type="button"`, `aria-pressed`, the standard `focus:ring-2 focus:ring-primary-emphasis` focus ring and the sizes (`md` 28px in modals, `sm` 20px inline). Adopters: `AddColumnModal`, `EditColumnModal`, `AddSwimlaneModal`, `EditSwimlaneModal`, the `CardDetail` new-label row and the `GroupDetail` shared-label row. **Reuse of board colors (#2098):** the custom popover can show an "On this board" row of the colors the board's columns, swimlanes and labels already use (`boardColors`, built once in `BoardView` by `utils/boardColors.boardColorsInUse` and passed to the four column / swimlane add and edit modals). Presets are dropped by the picker, the row is hidden when empty, each swatch is named by its source (`Use color from column To Do`), never by hex. Custom-field choice colors are palette keys, not hex, so they are not offered. The row is the board's own data: do not label it as popular or recommended.
- **Selected = a themed token, never `border-white`.** The shared component uses `border-fg ring-2 ring-fg ring-offset-2 ring-offset-surface` (plus a `scale-110` bump that is only a secondary cue). A white border disappears on the light-theme `bg-surface` panel, which left a 10% scale as the only cue. Keep at least `gap-2` between swatches so the offset ring is not clipped, and give a scrolling host about 6px of padding around the row. Focus shares the one box-shadow with the selected ring, so a focused selected swatch shows the focus color: `border-fg` and the scale bump carry "selected" while focused.
- **Custom colors: `allowCustom` adds one trigger, last in the row, inside the group (#2095).** Empty it is a dashed circle with a plus (`border-dashed border-line-boundary text-fg-tertiary hover:text-fg`, same size as the swatches, with a larger `before:` hit area on a coarse pointer), named `Choose custom color`. A custom value, persisted ones included, fills the trigger with the selected classes and no glyph, named `Custom color, selected`; there is no separate swatch for it. A value matching a preset selects that preset and leaves the trigger empty: comparison is on canonical hex (`normalizeHex`), so a stored `#3b82f6` is Blue, and Apply emits the preset's literal string. `title="Custom color"`, `aria-haspopup="dialog"`, `aria-expanded`.
- **A touch hit area never covers a neighboring control (#2095).** A `before:` hit-area pseudo-element stops at each neighbor's edge: it paints above the neighbor, so reaching further steals its taps. Check every host's gap, not just the row's own, and counter a selected `scale-110` on the pseudo-element. Insets measure from the padding box, so add the border width. The custom color trigger is 44x44 at `md` (`before:-inset-2.5`, 8px each way) and 34x44 at `sm` (8px left, 6px right to `CardDetail`'s `gap-1.5` cancel button, 10px up, 14px down), rather than a flat `-inset-3`.
- **`CustomColorPanel` is body only and fires `onChange` only on Apply (#2095).** It holds a draft and has no positioning or Escape logic, so a host can place it in a popover or inline; a host passes `applyLabel` where Apply does more (`Create label` in `CardDetail` once the label is named, whose row creates a label on every change it hears). Import `HexColorPicker` and `HexColorInput` from `react-colorful` only in this file, and do not lazy-load it. Enter in a field or slider applies and must never submit a host form. The panel root stops `keydown` propagation except Escape and Tab, so document-level shortcuts never see an arrow key pressed in a slider; `shouldIgnoreShortcut` also treats `role="slider"` as owning its keys. Pointer styling lives in `index.css` under `.custom-color-panel`, and the pointer's white ring with a dark outline is a deliberate literal, since it sits on arbitrary colors in both themes.
- **One press dismisses one layer for the custom color popover, matching Escape (#2095).** The popover carries `data-dismiss-layer` (`DISMISS_LAYER_ATTR` in `utils/dismissLayer.ts`). While it is mounted, a press on its host's dismiss surface (`ModalWrapper`'s backdrop, `CardDetail`'s click-catcher) closes the popover and leaves the host and its fields alone; the next press closes the host. Hosts ask `hasOpenDismissLayer(panel)` at press time, so no registry or listener can outlive the popover, and the backdrop press-origin rule in § Modals and dialogs above still applies. **The `RichTextEditor` text-color popover is the second opt-in (#2097)**, so a press on the card sheet's click-catcher closes it first. **`ChoiceColorPicker`'s popover is the third (#2096)**, so a press on the Board Settings backdrop closes only the popover and keeps the field edits. **No other popover opts in yet**, so for those one press still closes both. A portaled one (`SelectDropdown`, `MultiSelectDropdown`) cannot opt in with the attribute alone, because `hasOpenDismissLayer(panel)` searches the host's DOM and cannot see it. A press on a real control still does what it does, and a press on another card's face still swaps the sheet (panels replace, never stack), so a half-typed label name goes with it.
- **Dismissal of the swatch popover (#2095).** It uses non-portaled `useAnchoredPlacement`, so it stays inside the host modal's focus trap. Escape (59.5), Cancel and Apply return focus to the trigger. A click outside or Tab out discards silently with no refocus. **A blur with a null `relatedTarget` is not a dismissal**: that is an app switch or a Safari button click, and an outside click has its own `mousedown` listener. Any popover that closes on blur follows the same rule. While open, the trigger's `mouseDown` calls `preventDefault`, so pressing it toggles closed instead of blurring the panel and reopening. **A press on a non-control part of the panel (the preview swatch, the padding, a label) is default-prevented (#2224)**, or focus moves to the nearest focusable ancestor (a host modal's `tabIndex=0` scroll region) and the blur closes the panel and drops the draft. The "is this a control" test is scoped to the panel (`closest("input,button,select,textarea,[tabindex]")` plus `e.currentTarget.contains(control)`), the same rule as the `RichTextEditor` panel (#2223): an unscoped `closest()` matches that ancestor and lets the press through. Any popover that closes on blur needs the same scoped guard. The `ChoiceColorPicker` popover (the field editor's choice colors) was the same class, reproduced in a browser against the settings modal's `tabIndex=-1` dialog, and carries both guards since #2240: the press `preventDefault` above and the null-`relatedTarget` blur rule (outside clicks go through its document `mousedown` listener).
- **The accessible name is the color name, never the hex.** `aria-label="Select color Blue"`, from `COLOR_NAMES` / `colorName()` in `src/constants/colors.ts`. Add a name there when you add a palette color; a hex tells a screen-reader user nothing. A caller that needs different wording passes `getAriaLabel` (the `CardDetail` label row says `Create "X" with color Blue`).
- **Not migrated, and why.** `ChoiceColorPicker` (§ Custom fields) is a popover `radiogroup` with roving focus and a check glyph, a different pattern. Its custom color (#2096) reuses the shared `CustomColorPanel` inline, not `ColorSwatchPicker`'s custom popover: see § Custom-field choice color picker. The `RichTextEditor` text-color panel is a **permanent exception**, not a pending migration: its preset swatches must select on `onMouseDown` with `preventDefault()` so the editor keeps its text selection (a click would blur it; a keyboard press is a `click` with `detail === 0`, handled separately so a mouse press never runs twice). The Custom swatch takes a different path (#2097): it captures `{from, to}` when the panel opens, hosts the shared `CustomColorPanel` inline (non-portaled, inside the editor container, so the editor's blur check and `hasOpenDismissLayer` both see it), and on Apply runs `chain().focus().setTextSelection(range).setColor(hex)`. react-colorful calls `.focus()` itself on pointer-down, so the panel `preventDefault`s mousedown on its non-focusable surfaces (the "is this a control" test is scoped to the popover with `e.currentTarget.contains(control)`, because `closest()` also matches the card sheet's `tabindex=-1`, and the press would then focus the sheet and close the panel, #2223), and it carries a "Default" entry whose value is the empty string, which the shared component's hex palette does not model. It applies the same selected-token (`border-fg ring-2 ring-fg ring-offset-2 ring-offset-surface`), `aria-pressed` and name-label rules by hand. The `ring-offset-2` used here for modal rows intentionally differs from `ChoiceColorPicker`'s `ring-offset-1` in its tighter popover grid. **Stored text colors are theme-adjusted at render, never rewritten (#2097):** view mode maps each color span through `RichTextColorSpan` (`readableTextColor`, 4.5:1 against the worse of `--surface` and `--surface-sunken` per theme, delivered as `--rt-fg-*` properties picked by `[data-theme]` in `index.css`), and a color it cannot normalize renders raw. The sanitizer pattern (`COLOR_STYLE_PATTERN`, `utils/richTextSanitize.ts`) admits hex, named colors and the exact `rgb(r, g, b)` form because browsers serialize the stored hex to that form on save; tests import the pattern rather than copying it. **The editing view gets the same adjustment (#2099)** through `richTextEditColor.ts`, a ProseMirror inline decoration (`.rt-color` plus the same `--rt-fg-*` pair) layered on the `Color` extension, so the stored hex and `getMarkdown()` output are never changed and a theme toggle needs no re-render. Never adjust editor colors by rewriting the mark or the document. The toolbar "A" underline and the picker swatches intentionally keep the raw stored color (they are samples of the value and the `sameColor` selected-state match depends on it); only rendered text is theme-adjusted. Popover details (#2097): ten swatches in `w-40` (5+5); the Custom body widens to `w-max` and shifts to stay inside the editor container; Escape stays at priority 33; Tab out of the open popover discards it; Apply, Cancel and Escape return focus to the editor selection, not the trigger (the named exception to the shared picker's focus return, because Apply recolors that selection); the 20px swatches have no coarse-pointer hit-area extension (existing debt, the 10px gap forbids 44px targets).

## Board settings layout (#2436)

`BoardSettingsModal` is a left sidebar plus one panel, not a horizontal tab strip. Spec: artboards "2 · Board settings" and "4 · Swimlane fields" of the Board Redesign canvas.

- **Header:** the title "Board settings", the board name in `text-fg-tertiary` under it, the **Find a setting** input (`ModalWrapper`'s `headerExtra`), then Close.
- **Sidebar (232px, `border-r`):** a vertical tablist (`role="tablist" aria-orientation="vertical"`, each section a `role="tab"` button with `aria-selected`, `aria-controls="board-settings-panel"`, roving `tabIndex`). Group labels (Board, Fields, Access, Integrations, Data) are `role="presentation"` captions, not tabs. ARIA allows no group wrapper inside a tablist, so assistive tech does not hear the grouping on desktop (the phone select does, through `optgroup`); accepted. The selected section is clamped to the visible ones, falling back to Members, so a deep link to an admin-only section never renders a blank panel. The panel's focus ring is `focus:`, never `focus-visible:`. Sections: Display, Rules & limits | Card fields (n), Swimlane fields (n) | Members (n), Sharing | Webhooks, Issue lens | Export, Danger zone. The selected section takes `border-l-2 border-primary-emphasis` plus a tint, so tint is never the only cue.
- **Keyboard:** Up/Down/Home/End move focus (wrapping); Enter or Space selects. Activation is manual, not on focus, so the #863 webhook close-guard is asked once per switch, not on every arrow. The panel is `role="tabpanel" tabIndex={0}` with `aria-labelledby` the selected tab, so Tab from the sidebar lands on it.
- **Phone (`useIsPhoneViewport`):** the sidebar is replaced by a `<select>` labeled "Section" above the panel (grouped with `<optgroup>`). Render one or the other, never both. With no tab rendered, the phone panel is `role="region"` named for its section (`aria-label`, e.g. `Members (2)`), never a `tabpanel` whose `aria-labelledby` points at a missing tab. The select goes through the same webhook guard as the tabs.
- **Non-admins** see the same sections the old tabs showed: Sharing, Webhooks (never in demo mode), Issue lens (flag on) and Danger zone are admin-only and absent from the DOM.
- **Deep links:** `initialTab` keeps `members`, `display`, `rules`, `fields`, `swimlane-fields`, `sharing`, `webhooks`; `data` is a legacy alias for `export`; `lens` and `danger` are new. The #1458 focus-the-tab effect applies to the selected sidebar tab.
- **Find a setting:** the static index lives in `boardSettingsSections.ts` (`SETTINGS_INDEX`: section, label, keywords, and the `aria-label` or heading text to scroll to). **A new setting adds one line there.** "Setting" means every control, not just headings (#2436): each `h3`/`h4`/`legend` and each named switch, checkbox, select/combobox or text/number input in a section needs an entry whose target resolves to it, so typing its visible label finds it. The "every heading and labelled control" tests in `boardSettingsModal.test.tsx` (one per section, so no single test renders them all, #2509) walk every section's rendered panel (admin, flags on) and fail on a control with no entry; their exemptions are fixture board data only (a column and a lane name). Plain action buttons are not walked; give the ones people look for (`Recompute now`, `Add webhook`) an entry anyway. A section already indexed under its own name gets no second, synthetic section result (`settingKey` dedupes). Results are a `role="listbox"` under the input (the input is a searchbox with `aria-controls` and `aria-activedescendant`; ArrowUp/Down move, Enter or click jumps). A jump selects the section (through the webhook guard), scrolls the control into view and rings it for about 1.8s with `ring-2 ring-primary-emphasis`. No match reads `No setting matches ‘q’` in a `role="status"`. Escape clears the query (priority 41) before it can close the modal. The results close on blur or an outside press. A jump also announces `Jumped to <label>` (and results announce `N settings found`) through a polite sr-only status, since focus stays in the input. The input stays a searchbox, not an ARIA combobox: a `role="combobox"` there breaks every test that counts the modal's comboboxes, and the listbox/`aria-activedescendant` pairing still announces. Every `SETTINGS_INDEX` target must be a heading text or `aria-label` that exists in its section; rename one and its jump silently falls back to the section top. Sections the viewer cannot see are never offered.
- **Summary boxes and inline control rows (#2716):** a multi-column summary box top-aligns (`items-start`), never `items-end`, so headings share a baseline; give a lone control column `sm:self-end`. An inline row of label + select + counter is `flex flex-wrap items-center gap-x-2 gap-y-1` with `whitespace-nowrap` on the label and counter and `shrink-0 w-16` on the select, and the grid tracks are `minmax(0,1fr)`. A native `<select>` sizes to its widest `<option>`, including long disabled-option text, so cap the closed select's width (the popup keeps the full text) and keep the label and counter `whitespace-nowrap`; wrapping is only the narrow-width fallback.
- **Export section order:** the section opens with a title "Export" and a one-line description. Then the first card, headed "Export board" (JSON and CSV cards, the primary Export button, "Also on the board toolbar · ⌘⇧E"); the JSON/CSV radios sit in a fieldset with an sr-only legend "Export format". Then Export permission (its select's accessible name is "Who can export"), then Export history. Danger zone and Issue lens are their own sections, not part of Export.

## Board Settings tab bar (#1140)

- **Field-list type labels never wrap (#1391).** The type label cell in Board Settings → Card fields and Swimlane fields is `w-20 whitespace-nowrap shrink-0`. `w-16` truncated "Multi-select" onto two lines and pushed the row taller than its siblings; size the cell for the longest type label, and widen it again (in both tabs) rather than abbreviating a new one.

- **Label tabs by scope as soon as two of them configure the same kind of thing.** `Fields` became `Card fields` when `Swimlane fields` landed. Two tabs named for *what* they configure and not for *what it attaches to* is a coin flip on first encounter, and the cost of the wrong guess is an admin defining a field on the wrong object and only finding out when it fails to appear. Whenever a new tab configures a sibling of an existing tab's subject, rename **both** to carry the scope noun. Never disambiguate with an icon, a tooltip, or a help line under an otherwise identical label. Keep the pair adjacent in the tab array — a renamed pair split across the strip does none of the work the rename was for.
- **Use the product's own noun.** "Swimlane fields", not "Row fields": `EditSwimlaneModal`, `AddSwimlaneModal`, the collapse `aria-label`, and the Display tab all say *swimlane*, and a label is the wrong place to introduce a synonym.
- **The tab strip scrolls; it never wraps — and the panel is sized so it rarely has to.** The strip is `flex border-b border-line px-6 gap-1 overflow-x-auto` with `shrink-0 whitespace-nowrap` on every tab button, which is what actually prevents a second row of tabs appearing under the border; that guarantee holds at any panel width. The panel's `max-w-2xl` is a separate, weaker call: at `max-w-lg` the seven current labels overflow and the strip scrolls on first open, which reads as a broken tab bar rather than an affordance, and `Members (N)` grows with the member count. So the width buys breathing room, not correctness — do not justify it as a wrapping fix, and if a future change makes the label set short again, narrowing it back is safe.
- **A board-wide boolean display setting is an admin `Toggle` row with a read-only state line for everyone else (#1418).** Use `flex items-center justify-between py-2 border-b border-line/60` with a `text-sm text-fg` label, a `text-xs text-fg-muted` helper tied to the switch via `aria-describedby`, and a `<label htmlFor>`. Non-admins, or a caller with no write callback, get `text-sm text-fg-secondary` "{Setting}: shown/hidden". Never a native checkbox for a board-level setting.

## Entry requirements (#1923)

Board settings › Rules & limits › Entry requirements (`BoardSettingsEntryRequirementsSection`): a stage strip of one marker per column, one editor below it, one replace-all save.

- **Modes and severity are shown by shape, glyph and color together, never color alone.** Off = plain ring; Warn = dashed ring + `⚠`; Block = `bg-warning-bg` + `🔒`; Hard = `bg-danger-bg` + `⛔` (`MARKER` in `utils/entryRequirementsEditor.ts`). The strip marker is 28px. A legend line under the strip spells the four out.
- **Card-style radio rows may use `rounded-lg` (the recorded exception to § Buttons' `rounded`) and must show selection with more than hue.** The stage-strip buttons and the mode cards take a 2px border when selected (1px otherwise, padding compensated so nothing shifts), and a mode card also shows a `✓`; both survive forced-colors. A mode card dims to `opacity-60` while its fieldset is disabled.
- **Lane scope is derived from the condition's field set and shown read-only** ("Applies to every swimlane." / "Applies in swimlanes where MEDDIC shows: ..."). It is never a user choice and never a control.
- **A number bound reads like a value of its field (#2718).** The operand box of `is more than` / `is at least` / `is less than` / `is at most` shows the field's `number_prefix` / `number_suffix` as visible `text-sm text-fg-secondary` text beside the input, wired into its `aria-describedby`; the input keeps its "Condition N value" name, and you type the bare number. Every place the bound is shown (the non-admin summary, the "Needs:" line in the move and Warn toasts, the inline create/restore message) adds the field's prefix and suffix to the exact operand (`formatComparisonOperand` for the unmet label; pass the board's `custom_field_definitions`). It never rounds the bound to the field's `number_decimals` or to 3 fraction digits (up to 6 decimals show, as the server stores them), and the sign sits before the prefix ("-$50"): a bound of 19.5 reads "19.5%", not "20%", beside a card at 19.7 that is refused. `has at least N choices` is a count, never formatted.
- **Unmet entry-requirement signals use `text-warning-on-tint`, never danger.** A card that does not meet a requirement is not in error; the refusal is amber (§ Move-blocked toast) and the words carry it.
- **A dirty-draft discard prompt uses `InlineConfirm` (§ Inline confirm), at Escape 40.65.** `InlineConfirm` takes focus on Cancel when it opens and is a labeled group. A hand-rolled prompt must have a live region and a named focus target; after Discard focus goes to the newly selected marker, after Cancel or Escape back to the selected one, never `<body>`. The prompt clears itself when the draft stops being dirty.
- **A switch on with zero conditions says why it will save as off** in the status line ("Add at least one condition to turn requirements on."); the save is the server's no-op `null`. With no card fields at all the editor shows "Add card fields first (Board settings › Card fields)." and hides "+ Field condition".

## Withheld row actions and refusal reasons (#1785)

When an action is withheld from a row for a policy reason (group owner, last admin), keep the reason visible on the row (for the owner, an `Owner` pill in the inherited-badge style `text-xs bg-surface-hover text-fg-tertiary px-1.5 py-0.5 rounded`) rather than silently omitting the control. When the server refuses an action with a 400, show its `detail` string in the nearest `role="alert"` `text-danger text-xs` line; use a generic fallback only when `detail` is absent or not a string.

## Radio groups

Never render browser-default radio circles. Use `sr-only` native `<input type="radio">` inside a `label` container — this preserves native keyboard navigation (arrow keys, Tab, Space) while hiding the visual control.

Represent selection state on the container:
- Selected: `border-primary-emphasis bg-primary-emphasis/10` — **never `bg-info/10`**; the `primary-emphasis` token tracks the active theme, `info` does not, so an `info`-tinted fill reads off-brand in dark mode
- Unselected: `border-line-strong hover:bg-surface-hover/40`
- Keyboard focus: `focus-within:ring-2 focus-within:ring-primary-emphasis rounded-lg` on the `label`
- Transition: `transition-colors duration-150`

Option text: `text-sm text-fg font-medium` for the label, `text-xs text-fg-muted mt-0.5` for the description line below it.

**Compact / chip-style radio groups** — a 2-4 option inline segmented choice (e.g. the relation-type picker in `RelationCardPicker`) may use `rounded` instead of `rounded-lg` on the option container, matching its smaller `px-2 py-1 text-xs` chip sizing. The `rounded-lg` guidance above assumes the larger card-with-description-line layout (e.g. the export format choice). Both variants keep the same selected/unselected token pair and the same `focus-within:ring-2 focus-within:ring-primary-emphasis` treatment — only the corner radius and text sizing shrink. A chip row also takes `flex-wrap`: three short chips fit at 320px today, but a longer translation or a fourth option would clip silently without it, and there is no action button to push the overflow onto.

**Popover radio cards (#1133).** A radio group inside an anchored popover (the health status popover, `HealthStatusPopover`) keeps the card variant above (`rounded-lg border px-3 py-2`, the same selected / unselected / `focus-within` tokens) with a leading `aria-hidden` shape in its on-tint color, and one deliberate deviation: the description line is `text-xs text-fg-tertiary`, not `text-fg-muted`, because `fg-muted` is sub-AA on `bg-surface` (#1862). Arrow keys move only the draft (native radio behavior); Enter on a radio and the primary **Save** submit; an unchanged draft closes with no request. Save stays in the tab order while unchanged or saving (`aria-disabled`, `opacity-40`), and activating it with an unchanged draft closes the popover with no request; the always-mounted error slot is a polite live region.

**Focus on closing a non-modal anchored popover (#1133).** Return focus to the trigger on Cancel, Escape and a successful save. On an outside mousedown or focus leaving the panel, close without moving focus: the user has already moved. On window resize and outside scroll, return focus to the trigger only if it is still inside the panel. No close path may drop focus to `<body>`. An admin trigger that opens such a popover shows `cursor-pointer` and a `hover:ring-1 hover:ring-line-strong` ring (never a stronger fill behind on-tint text); a demo-mode trigger that never opens drops `aria-haspopup` / `aria-expanded`.

**Inline add/edit rows (#2036).** Every exit of an inline input (Cancel button, Escape, successful commit) returns focus to the control that opened it; set a `focusTriggerRef` flag and focus in an effect keyed on the editing state, and test all three exits. A blur-commit (clicking elsewhere) must not set the flag, or it steals focus back from wherever the user went (`ColumnHeader`, `SwimlaneRow`, `InlineBoardName`, `BoardCell`, #2087; the `GroupDetail` group rename and description, #2170). When fixing focus rings or focus return on one control, audit its siblings in the same row (pills, tabs, ✕ buttons) in the same commit. The card description `RichTextEditor` follows the same rule but cannot return focus to its trigger (the pencil has `onFocus={enterEdit}` and would reopen the editor), so Escape, Cancel and Save call `focusEnclosingDialog` before unmounting (#2182), and its blur-save is suppressed for that exit. Save and Cancel act on `mousedown` (to beat the editor blur) and on keyboard `click` only when `event.detail === 0`, so a mouse click never fires twice.

**`SingleSelectDropdown` marks its selected option without color (#2108).** The selected option gets an `aria-hidden` check icon (`singleselect-selected-mark`) in a reserved `w-3` slot, plus `aria-current="true"` on the default `menuitem` role or `aria-checked` with `optionRole="menuitemradio"`. `text-info` alone fails WCAG 1.4.1. A new select-like menu must carry a non-color cue too. **Every other select-like surface follows the same rule (#2171, WCAG 1.4.1):** `SelectDropdown` puts the same check in a reserved `w-3` slot (`select-selected-mark`, with `aria-selected`); the `MoveBoardModal` destination rows are `role="radio"` `aria-checked` inside a `role="radiogroup"` with the check in a reserved slot (`move-board-selected-mark`); the `CreateBoardModal` template cards, native radios, show a check (`template-selected-mark`) beside the name. A tint, border or text color is never the only cue. The selection slot reserves its width so selecting never shifts text. The `MoveBoardModal` radio rows follow the WAI-ARIA radio group pattern (#2184): the checked row is the only radio Tab stop (the first enabled row when it is hidden in a collapsed subtree), while each expand/collapse toggle stays its own Tab stop so the tree remains reachable. Arrow keys and Home/End move focus through every row with wrap-around, and move the selection with it except on a blocked row: a blocked row (`aria-disabled`) stays focusable per § Blocked rows in pickers, so arrows land on it to show why it is unavailable, but selection stays on the last enabled row and Enter/Space do nothing. Prefer a native `input type=radio` where the layout allows, as `CreateBoardModal` does.

**Segmented, chip and toggle controls mark the active state with a check, not fill alone (#2185, WCAG 1.4.1).** A button group whose active member differs only by fill, tint, border or text color fails the same rule as a select. Use `components/Common/ActiveMark` (the #2171 check, `aria-hidden`, `data-testid="active-mark"`) as the first child of every button in the group, inside an `inline-flex items-center gap-1` button; the slot is a fixed `w-3` on every button of a segmented control or row, so toggling never shifts the label (standalone chips: see the exception below). Keep the semantics honest: `aria-pressed` for toggle buttons (the analytics mode/period toggles, the Chart | Table switch, the activity drawer kind and window filters, `SavedFilterTabs`, the group allowed-priorities chips); a table row selected by click gets the mark in its first cell plus `aria-current` (`MovementHistoryView`); only a real ARIA tabs widget (roving tabindex, arrow keys) uses `role="tab"` and `aria-selected`. Every inactive button carries the empty slot (about 16px with the gap), the accepted cost of no layout shift; never swap an icon in and out. Tests assert the mark and the ARIA state move together. A hand-rolled Save/Cancel pair gives both buttons the identical `focus:ring-2 focus:ring-primary-emphasis` set, because the keyboard click path (`detail === 0`) is now a real path (#2182). Icon-only toggles take the underline cue in the next paragraph instead (#2188). The FilterBar "My cards" and "Blocked only" chips carry the mark when active (standalone chips, see the exception below). **Exception: standalone pill chips whose idle name must read as centered** (the `CardDetail` label picker, #2618, and every other content-sized chip: the board-settings parent-name suggestions, `SavedFilterTabs` pills, the card history type chips, the analytics `GroupLegend` chips, the `CardDetail` "Hide completed" toggle, the activity drawer Kind and Window filters and the FilterBar "My cards" and "Blocked only" chips, #2673; mechanism in § Badges and labels). Render `{active && <ActiveMark active />}` and move the slot's room (`w-3` + the gap, halved onto each side) into idle padding: `gap-1` chips use active `px-N` against idle `px-N` plus 0.5rem, and a `gap-1.5` chip adds 0.5625rem (FilterBar: `px-2` active, `px-[1.0625rem]` idle; the leading icon or avatar stays). Equal-width `flex-1` segmented controls and left-aligned list rows keep the reserved slot. The chip width stays fixed, but the name moves by half the slot on toggle. Do not add `ActiveMark`'s empty slot there, and do not use this exception to drop the reserved slot in segmented controls or button groups.

**Binary connector toggle (And / Or, #2205).** A join between two rule rows is a two-button segmented group on its own line, left-aligned with the field column: `<div role="group" aria-label="Join filter {i} and filter {i+1}">` (`group {k}` for a group), `inline-flex rounded overflow-hidden border border-line-strong`; buttons with visible text **And** / **Or** (the accessible name is the text, so label-in-name passes), `aria-pressed`, `min-h-6 px-2 text-xs`, the `ActiveMark` check above, and `font-semibold` on the pressed one as a second non-color cue. Selected `bg-primary-emphasis/20 text-info`, unselected `text-fg-tertiary hover:text-fg-secondary hover:bg-surface-hover`. No chevron, no menu; both buttons are tab stops. Reference: `JoinToggle` in `LaneFilterPopover.tsx`.

**An item that leaves a filtered set after a data edit hides immediately (#2205).** Do not keep it visible until the next filter change: the count and any "Reads as" text would disagree with the screen. When it concerns the user (this client made the edit, keyboard focus was inside it, or its card is open in the panel; an item this client just created always), show an in-place notice between the filter row and the board (`flex items-center gap-2 px-3 py-1 text-xs text-fg-secondary bg-surface border-b border-line`) whose text goes in the always-mounted polite region, with a secondary action and an icon-only `aria-label="Dismiss notice"` ×. No timeout; it clears on any filter change, focus-mode change, or dismiss. Anything else (a teammate's edit elsewhere) hides silently and only the count changes. If keyboard focus was inside the item, a `useLayoutEffect` sends it to `BOARD_SCROLL_SELECTOR` before paint, never to the notice. Reference: `useLaneFilterNotice`.

**Icon-only toggles mark the active state with an underline bar, not tint alone (#2188, WCAG 1.4.1).** An inline check has no label to sit beside on an icon button, so a standalone `aria-pressed` toggle renders `components/Common/ActiveUnderline` as its last child: a 12px by 2px `bg-fg` bar centered under the icon (`aria-hidden`, `data-testid="active-underline"`), rendered only while active and absolutely positioned, so the host button adds `relative` and toggling never shifts layout. `bg-fg` reads on both themes whatever tint the active state also carries; keep the tint as reinforcement and keep `aria-pressed` as the state. `placement="inset"` (default, `bottom-px`) sits in the bottom padding of a padded button, clear of the line box (`p-1.5`, `px-2 py-1`); `placement="below"` hangs 4px under a bare glyph button with no padding (the swimlane focus and collapse toggles), so the bar never covers the icon. Apply it to every such toggle, including ones whose glyph also flips (collapse chevrons, the sidebar toggle), so the rule has no exceptions to judge. Sites: the BoardView and `LensToolbar` Row 2 icon toggles (card layout, Archived, activity drawer, keyboard shortcuts), the `SwimlaneRow` and `LensSwimlaneRow` focus and collapse toggles, and the `RichTextEditor` toolbar marks. Tests assert the bar and `aria-pressed` move together. **Color swatches are the one exception and take the ring, not the bar:** a swatch is itself a color, so its selected state is the themed `ring-fg` ring in § Color swatch pickers (`ColorSwatchPicker` and the `RichTextEditor` text-color panel), with `aria-pressed` and a color-name label. A labeled button group still uses `ActiveMark` above; never put both cues on one control. A menu trigger that displays a set value (the `RichTextEditor` "Text color" button) is not a toggle, so it takes no `aria-pressed` but renders the same `ActiveUnderline` while a value is set.

Group the options in a `<fieldset>` with a `<legend>` (`sr-only` when there is no visible heading for it) — never put `role="radiogroup"` on a `<fieldset>`, which already carries group semantics.

The action button following a radio group uses the primary variant (`bg-button-primary hover:bg-button-primary-hover text-on-primary`) and its label should reflect the current selection (e.g. "Export JSON" / "Export CSV") to eliminate ambiguity.

## Subordinate settings blocks (toggle/checkbox-gated)

When a block of settings is only relevant while a toggle or checkbox directly above it is on (e.g. the Rules & limits section's Hard-WIP-mode options gated by "Enforce WIP limits", or the Display section's personal density radio group gated by "Use my own density"), indent and rule off that block with exactly:

```
ml-6 border-l-2 border-line pl-4
```

**Do not invent a per-instance variant** — no custom border color (`border-line-strong`), no opacity modifier (`border-line-strong/40`), no different indent/padding pairing. This is the one sanctioned treatment for "a settings block that visually belongs to the control above it," established by the Rules & limits section's Hard-WIP-mode block (`BoardSettingsModal.tsx`) and reused as-is by the Display section's personal density override block. `RoleTooltip`'s `pl-3 border-l-2 border-line` is a pre-existing, unrelated exception (tooltip content formatting, not a gated settings block) — do not treat it as a third variant to reconcile against.

## Board-level field chooser settings row (#2275)

A board setting that picks one of the board's custom fields (first instance: **Board Settings → Rules & limits → Swimlane rollup**, `BoardSettingsModal.tsx`) is one settings row, the same shape as the toggles around it: `flex items-center justify-between gap-3 py-2 border-b border-line/60`, a `<label htmlFor>` (`text-sm text-fg`) over a help line (`text-xs text-fg-muted`, wired to the control with `aria-describedby`), and a `SelectDropdown` on the right. Never a native `<select>` or a radio list of fields.

- **Options are `None` first, then only the eligible fields** (for the rollup: number fields) in the Fields tab order. Saving goes through `onUpdateBoardSettings` like every other Rules control; `None` sends `null`.
- **No eligible field: the dropdown is disabled with a reason** (`disabledReason`), and the help line appends what to do (`Add a number field in the Fields tab first.`). Do not hide the row: an admin has to learn the setting exists.
- **Stale choice: say why and how to clear it.** When the stored id points at a field that is no longer eligible (retyped away from number), the dropdown shows `None`, stays enabled so the admin can pick another field, and the help line says the bands show no total and that choosing None clears the setting. A deleted field cannot be stale: the server clears the id and broadcasts `board.updated` (#2275), so every open dialog updates.
- **Non-admins get a read-only line** in the Rules & limits section's read-only part (`Swimlane rollup: {field name}` or `none`, `text-sm text-fg-secondary`), never a disabled control.
- **The same shape picks a column** (**Flow metrics → Cycle time starts at**, #2050): the default first, then the board's not-done columns in board order. When a read-only value replaces the control for non-admins in the same row, never leave a `<label htmlFor>` pointing at a control that is not rendered: render the name as plain text and give the value its name (an `sr-only` prefix) and the help line (`aria-describedby`).

**Not every control-plus-dependent-fields layout is toggle-gated.** The rule above applies when the dependent block is *inert* while the controlling toggle is off — there is nothing useful to do with it. It does **not** apply when the dependent fields stay independently meaningful whichever option is selected, because the safe path to switching requires filling them in *before* the switch. Admin Settings → Email is the reference case (`EmailSettingsSection.tsx`): the SMTP host/port/credential fields stay unindented and fully editable whether "Environment variables" or "Database" is selected, because indenting or disabling them under an unselected radio would force an admin to switch mail configuration blind. When leaving a block unindented for this reason, add an inline status line saying whether it is currently in effect (e.g. "Saved, but not in use — {other option} is selected above"), sourced from the **last-saved server state, never the in-progress draft** — do not assert a saved fact about a selection the user has not committed.

**Render-and-disable instead of conditional render is permitted only for a single dependent toggle whose existence is itself the thing being advertised (#356).** The default stays "conditionally render an inert block" (Hard-WIP options, personal density radio). But when the dependent control is *one* switch, the controlling toggle defaults to off for most users, and hiding the switch would make the capability undiscoverable — Sam checks in twice a week and would never learn per-event email notification exists — render it always inside the standard `ml-6 border-l-2 border-line pl-4` block and set `disabled`. Four requirements, all of them load-bearing:

1. The block carries a **visible, always-rendered reason line** whose `id` is passed to the switch via `aria-describedby` (`Toggle` supports that prop), and whose text changes with state — including a distinct state for a stored-ON value under an off parent. A helper that reads as a claim ("Sends a copy…") must not appear under an off switch.
2. The stored value is **never auto-cleared**. Clearing it needs a second write that can half-fail, and it discards a choice the user will want back the moment they re-enable the parent. The disabled switch stays visibly ON and the reason line says it is paused and kept.
3. Dim the label to `text-fg-muted` only. No new opacity modifier — the switch's own `disabled:opacity-40` is the sole dimming.
4. Never use this for a **multi-control** block. Those stay conditionally rendered.
5. **Use `ariaDisabled`, not `disabled`, on the switch whenever the reason line is the "why is this off" case rather than a transient in-flight save (#1159).** Native `disabled` removes the control from the tab order, so a sighted keyboard user never reaches the reason text a screen-reader browse-mode user sees. `Toggle` supports `ariaDisabled` as an opt-in: the switch stays focusable, click and keyboard (Space/Enter) activation are both ignored, and the same disabled visual styling is kept. Keep plain `disabled` for genuinely transient states (e.g. a save in flight) that have no reason line to reach.

Reference implementation: `NotificationRow` in `SettingsPage.tsx`.

**The same `aria-disabled` + `aria-describedby` principle extends to a plain `<button>` whose action is blocked for a reason (#1314).** The rule above is written for `Toggle`, but any standalone action button that can be legitimately blocked (e.g. "Disconnect" on a connected-accounts row when it is the user's last remaining sign-in method) follows the same shape, by hand: `aria-disabled={condition}` (never native `disabled`, for the same tab-order reason), `aria-describedby` pointing at a reason `<p>` rendered **only while the condition holds** (the hint and the block share one gate), and `onClick` set to `undefined` while blocked rather than guarded inside the handler. Keep the control's own semantic focus-ring color (e.g. `focus:ring-danger-emphasis` for a destructive action) in both states. Reference implementation: `ConnectedAccountRow` in `SettingsPage.tsx`.

**A row containing two controls is never wrapped in a single `<label>` (#356).** A click on label text forwards to the first labelable descendant, so text belonging to the second control would toggle the first. Give each control its own `<label htmlFor>` around only its own text block, wrap the pair in `role="group" aria-label="{event}"` so each control has context, and give the repeated visible label a unique accessible name that *begins with* that visible text (`aria-label="Also send by email: {event}"`) so label-in-name holds and `getByRole('switch', { name })` stays unambiguous.

## Inline description fields (non-RTE)

For plain-text description fields that are inline-editable by admins:

- **Idle / view state**: a `relative` wrapper holds a `<button type="button">` (`block w-[calc(100%+1rem)] text-left border border-transparent hover:border-line-emphasis cursor-text rounded px-2 py-1.5 -mx-2 transition-colors`, standard focus ring) whose children are `<span className="block ...">` text (no `<p>` inside a button). This button is the single keyboard tab stop. The hover-reveal pencil is an overlay sibling (`absolute top-1 right-1`, `tabIndex={-1}`, `focus:opacity-100 focus:ring-2 focus:ring-primary-emphasis`) so it adds no height (reference: `GroupDetail`)
- **Edit state**: `bg-sunken border border-primary-soft rounded px-2 py-1.5 focus:outline-none focus:ring-2 focus:ring-primary-emphasis focus:border-transparent` on the `<textarea>`; `resize-none`; Escape cancels, blur saves
- **Error slot**: always render `<p className="text-xs h-4">` below the field unconditionally; place error text in a `<span className="text-danger">` inside it — never conditionally render the container itself
- **Non-admin, non-empty**: render plain `<p className="text-sm text-fg-tertiary whitespace-pre-wrap">`
- **Non-admin, empty**: render nothing (`null`) — do not show a placeholder the user cannot act on

## Composite inline editors — explicit Save/Cancel (#371)

The pattern above (and the single-value autosave pattern used everywhere else — Weight, Due date, priority, labels) commits on blur or on selection with no separate save step. That pattern only holds for a **single interdependent value**. It breaks down once an editor has **two or more sub-fields that depend on each other** — e.g. Board Settings → Fields' add/edit panel, where the `field_type` selector changes which other sub-fields are relevant (dropdown needs a `choices` list; other types don't) and requires cross-field validation ("a dropdown field needs at least one choice") before any of it is safe to persist.

**Rule:** an inline editor with ≥2 interdependent sub-fields, or any cross-field validation that must pass before a partial state is safe to write, uses explicit `Cancel` / `Save {noun}` text buttons (secondary + primary variant, standard focus rings, `gap-3`) instead of blur/immediate-commit. A single-value inline editor (one text field, one toggle, one dropdown with no dependent fields) stays on blur/immediate-commit — do not add a Save button to a field that doesn't need one; that adds friction without a matching risk.

Reference implementation: `BoardSettingsFieldsTab`'s `FieldEditPanel` (name + type + choices + help text + pin toggle, all validated together in `handleSave`).

**Exception: filter builders apply complete rules live with a Done close (#2205).** The Save/Cancel rule covers persisted data. A filter is reversible view state, `FilterBar` already applies live, and an incomplete rule never filters, so a multi-field rule builder such as `LaneFilterPopover` applies each complete rule as it is built and closes with a primary **Done** (and Escape / outside click) instead of Save/Cancel. A saved filter is still saved explicitly through the Saved dropdown.

## Paired numeric settings fields

When two related numeric inputs belong to the same conceptual setting (e.g. threshold + warning percentage):

- Group them in a single `<section>` with a shared `<h3>` heading
- Render each as its own `flex flex-col gap-1.5` block (input row + helper text), stacked in a `flex flex-col gap-3` container
- Each input row: `flex items-center gap-2` with a `w-20` number input and a `text-sm text-fg-tertiary` unit label
- Helper text: `text-xs text-fg-muted` — explain the relationship between the two values with a concrete example
- Non-admin read-only view: single `text-sm text-fg-secondary` line combining both values (e.g. "14 days · 50% warning")
- `onBlur` saves each field independently via `patchBoard`; clamp values client-side before patching

## Conditional admin-only elements

- Admin-only nav items and UI elements must be **hidden entirely** for non-admin users — never greyed out or rendered with reduced opacity. Use `{user.is_site_admin && ...}` (or the equivalent condition) to omit the element from the DOM entirely.
- Never use `disabled` or `opacity-50` to signal lack of permission for a navigation link — if the user cannot access it, it should not be visible at all.
- **Card-detail sub-section gating.** The collapsible sub-sections in `CardDetail` (Custom fields, Relations, Checklist, Attachments) follow one three-way rule, all outcomes being *omit from the DOM*: **board-config-gated** — the board has nothing to show (no custom field definitions): omit the section and its divider; **permission + empty** — a reader with no rows: omit the section and its divider; **permission + non-empty** — a reader with rows: render the rows read-only with every control omitted, never disabled. **Never render a header that a resolving fetch will then remove** — render nothing until the data is in; a section that appears late is better than one that appears and vanishes.
- **Permission + load-error is treated the same as permission + empty: omit.** A reader has no remedy for a failed fetch — no retry worth offering, nothing to act on — so a dead error message is worse than silence, and the section stays absent. This is deliberate, not an oversight in the rule above. A future sub-section that genuinely needs a reader-visible retry is a new exception to argue for, not an extension of this one.
- **Collapsing hides rows, never controls.** A sub-section that collapses itself when empty must keep its add affordance outside the collapse gate, or creating the first item would require expanding a section that looks empty. It must also expand itself when an item is added, or the new row lands in a hidden list and reads as a silent failure.
- **Permission-gated and context-gated are distinct reasons to hide, with the same outcome: omit from the DOM.** *Permission-gated* — the user's role forbids the action (admin-only delete, site-admin nav). *Context-gated* — the action is valid for this user but meaningless in the current surface (e.g. the "Refresh board" affordance on `ConnectionStatus` is omitted on the group page, which has no single board to refresh). In both cases render nothing rather than a disabled/greyed affordance; do not show users a control they cannot act on, regardless of *why* they cannot. Named exception: a row in a choice picker (e.g. the Move board group list) stays visible and blocked with its reason, so the user sees why a known option is unavailable (see *Blocked rows in pickers*).
- **An omitted row action the actor would otherwise expect may leave a one-line reason (#1644).** On an admin surface, when the actor holds the role for this kind of action but the server refuses it on this row (a site admin on a superuser row), omit the controls and render one `text-xs text-fg-tertiary` sentence in their place, naming who can act. Visible text, never a `title` or tooltip, so keyboard and screen-reader users reach it without hover. Tell the two cases apart by whether the reader has a remedy: this one does (ask a superuser). A reader who lacks the role altogether gets silent omission, as above.
- **A server-omitted value is omitted, not explained (#1140).** `is_admin_only` on a swimlane custom field strips the value from the payload a member or viewer receives; the frontend has nothing to hide, because it was never sent. Do **not** render a placeholder chip, a count of hidden fields, or a "some fields are only visible to admins" note on the board for that user. It is a dead end with no remedy, and it advertises that structured entity data exists on a row whose contact details the same visibility split already hides. This is the permission+load-error rule above, applied to data the client never received. The admin-side signal for the same fact belongs in Board Settings → Swimlane fields — a surface only admins can open, where it has context and an action attached.

## Externally-sourced URLs (#1087)

- **Every externally-sourced URL is gated by `isSafeHttpUrl()` (`utils/safeUrl.ts`) before it reaches an `href` or `window.open`.** "Externally sourced" means anything a third party influenced: lens/provider JSON, imports, integration payloads, other API-sourced links. `href` is an XSS sink, so `javascript:`, `data:`, `vbscript:`, relative and garbage values must never be bound; the helper allows `http:`/`https:` only and rejects surrounding whitespace and control characters.
- **Fail closed, render text.** When the check fails, render the value as plain text (no `<a>`, no `href`) or make the handler a no-op. Never fall back to the raw value, and never show an error for it.
- **Precedence:** use `isHttpUrl` (`externalRef.ts`: also a length cap, no credentials) where it already applies (card external refs, URL custom fields, extension panel links); `isSafeHttpUrl` is the minimum for everything else. Both enforce http(s) only and no embedded credentials; `isHttpUrl` adds a length cap. Either satisfies this rule.
- **Exempt:** server-constructed same-origin URLs (attachments, export endpoints, `oauthUrl`) are not externally sourced.
- A new `<a href={...}>` or `window.open(...)` bound to API data without one of these guards is a review finding.

## Long URL display fields

- Truncate long URLs in read-only display inputs: `truncate overflow-hidden text-ellipsis whitespace-nowrap`
- The full value must remain in the clipboard on copy — only the display is truncated
- Add a `title` attribute (or tooltip on hover) showing the full URL

## Click handlers need keyboard parity (#1376, Sonar S1082)

A click handler never goes on a non-interactive element (`div`, `span`, `p`, `h1`) without keyboard parity. Pick the first option that fits:

1. **Make it a `<button type="button">`** — inline-rename text (column/swimlane/board/group names), file dropzones, and "click the text to edit" regions. Tailwind preflight already resets button chrome; add `text-left`, `block`, or `max-w-full truncate` as the original element needed. A truncating button inside a `<p>` needs `block`. Add the standard `focus:outline-none focus:ring-2 focus:ring-primary-emphasis rounded`. For a heading, put the button *inside* the `<h1>` so heading semantics survive. Do not nest block elements (`div`/`p`) or inputs inside the button — use `<span className="block">` and render hidden file inputs as siblings.
2. **Put the handler on the focusable control** — an overlay `<input type="date">` owns its own `onClick` (picker fallback) instead of a wrapper `div`; a `<label htmlFor>` forwards clicks on label text to its switch (see `ToggleField`).
3. **Decorative pointer-only backdrops** — `aria-hidden="true"` when the backdrop is a sibling of the panel (drawers, tour spotlight, bulk-add overlay), `role="presentation"` when it is the panel's parent (`ModalWrapper`). Both require that Escape (via `useEscapeStack`) and a visible Close button already exist.
4. **A `stopPropagation`-only wrapper is a smell** — delete the wrapper handler and move the guard into the parent handler (e.g. `closest("[data-column-drag-handle]")` in the collapsed `ColumnHeader`).

**Pencil policy:** when a text button is paired with a hover-reveal `✎` pencil that starts the same edit, the text button is the single keyboard tab stop and the pencil is `tabIndex={-1}` (keep its `aria-label`, `focus:opacity-100`, and ring). Never two tab stops for one field.

**Allowed shapes that are not a real button:**
- `CardItem` forwards the dnd-kit `listeners.onKeyDown` explicitly. This is the one sanctioned bare `onKeyDown` on a `div`: the div already has `role="button"` and `tabIndex` from dnd-kit `attributes`, and the restatement only makes the handler visible to static analysis.
- `SelectDropdown` options use the `aria-activedescendant` shape: the combobox trigger owns keyboard selection, and each `role="option"` gets `tabIndex={-1}` plus an Enter/Space handler for parity.

Otherwise never add a bare `onKeyDown` to a `div` just to silence the rule; if the element is operable it should be a real control.

## Hover-reveal controls

When an action button is hidden until hover (`opacity-0 group-hover:opacity-100`), it **must** also include `focus:opacity-100` and a focus ring so keyboard users can reach and activate it. Without `focus:opacity-100`, the button is unreachable by keyboard. This applies to all hover-reveal controls (comment delete, swimlane edit, RTE pencil icon, etc.).

**A sortable list's drag handle is a real `<button type="button">` (#1739).** Spread dnd-kit's `attributes` and `listeners` onto the button, name it `Drag to reorder <name>`, give it the standard focus ring plus `focus:opacity-100` when hover-revealed, and wrap the glyph (`⋮⋮`) in an `aria-hidden` span. A `<span>` with `focus:opacity-100` and no ring is not a keyboard control. The `<name>` is the item's visible text, or its 1-based position when that is empty, never dnd-kit's internal id. A handle may be hover-revealed (the field lists) or always visible (the choice rows, which are short, dense and touch-reached, so no `opacity-0` and no `focus:opacity-100`); either way the glyph is `text-fg-tertiary hover:text-fg`, not `text-fg-faint`, which is too faint for the row's only drag affordance. The keyboard reorder path is dnd-kit's `KeyboardSensor` (`useDragSensors({ keyboard: true })`: Space or Enter lifts, arrows move, Space drops, Escape cancels), so the handle must be a named, visible tab stop. Reference: the Board Settings card-field and swimlane-field lists, and their editors' **choice rows** (#2190, `SortableChoiceList`), which also show three details a sortable list inside a modal needs: (1) **Announce by name, never by dnd-kit's internal id**: pass `accessibility.announcements` (and `screenReaderInstructions`) that read the item's name and `position N of M`; the default reads the sortable id. (2) **Focus follows the moved item.** Rows keyed by index leave the focused handle in place after a keyboard drop, on a different item; move focus to the handle at the new index once the reordered list renders. (3) **Escape that cancels a drag must not also close the host modal**: register an escape-stack entry above the modal (`CHOICE_DRAG_ESCAPE_PRIORITY` / `FIELD_DRAG_ESCAPE_PRIORITY`, 40.7) that consumes Escape only while a drag is in progress and returns `false` otherwise. It works because the escape stack's document listener is registered before dnd-kit's (added at pick-up), so it still sees the drag; any such entry needs a test that Escape mid-drag cancels the drag and leaves the modal open, and that the next Escape closes the modal (`e2e/choice-keyboard-reorder.spec.ts`). The field lists share the same wiring through `useSortableFieldDrag` (#2190); focus-follow does not apply to them because field ids are stable. Known exception: the board grid's column and swimlane handles have no keyboard dragging by design (cards move through the card-detail Move popover). Do not copy that pattern into a new list.

## Toggle buttons (icon-only)

Icon-only buttons that toggle a persistent mode (e.g. focus mode, collapse) must include:

- `aria-pressed={boolean}` — exposes toggle state to screen readers; color-only treatment is invisible to assistive technology
- `aria-label` reflecting the current state (e.g. `isFocused ? "Exit focus" : \`Focus on ${name}\``) — an icon-only toggle's SVG is `aria-hidden`, so `title` alone is **not** a reliable accessible name (Firefox/VoiceOver skip it). Always pair the state-reflecting `title` with a matching `aria-label`
- Updated `title` attribute when active (e.g. `isFocused ? "Exit focus" : \`Focus on ${name}\``) — tooltip text must reflect the current action, not the initial one
- The active tint (e.g. `text-info !opacity-100`) is **not** sufficient on its own (WCAG 1.4.1): an icon-only toggle also renders `ActiveUnderline`, a labeled button group renders `ActiveMark` (see § Radio groups, "Icon-only toggles mark the active state with an underline bar", #2188). `aria-pressed` covers assistive technology; a button hosting the bar or any absolutely positioned indicator dot is `relative`
- A glyph, letter, or symbol child (e.g. `◀`, `B`, `✕`, `A`) is **not** a substitute for `aria-label`, even though it produces some accessible name — screen readers announce the bare character ("bee", "ex"), not the action. `aria-label` must describe the action (e.g. `aria-label="Bold"`, not relying on the visible "B"). This applies to every icon/glyph-only button, not only toggles (#1240)

## User preference persistence

**Instance-level flags** never go on the TS `User` / `CurrentUserSerializer` (frozen, #1664) — add them to `SiteConfig` (`/auth/site-config/`); see `docs/api/authentication.md#frozen-instance-flags-on-authuser`.

**User-scoped UI preferences** (toggles reflecting a reading habit or display style not tied to a specific board) use a single flat localStorage key in the format `user:prefs:{preference-name}`. Do not embed a board ID. Do not extend `useViewPrefs`. Create a dedicated hook following the try/catch + fallback pattern in `useViewPrefs.ts`. Never store UI-only preferences in the backend `UserSerializer` unless cross-device sync is an explicit requirement.

- **Board-scoped keys:** `board:{boardId}:{pref-name}` — for preferences that are per-board (hidden columns, filters, column widths)
- **User-scoped keys:** `user:prefs:{pref-name}` — for preferences that apply across all boards (reading habits, display toggles)

**Renamed keys are not migrated (#1859).** 1.2 renamed the sidebar and theme keys to the `user:prefs:*` form and shipped a one-time read-old, write-new, remove-old shim; 1.3 removed it, along with the old-name fallback in `public/theme-init.js`. A browser upgrading from 1.1 or earlier straight to 1.3 starts with defaults once. When renaming a persisted key in the future, ship a shim for one release cycle, remove it under a tracked issue, and say so in the changelog and `docs/administration/upgrade.md`. Any new persisted key must use the `user:prefs:` / `board:` prefix from the start.

Each key in either namespace requires a `load()` function with try/catch + fallback-to-default, and a `save()` function that fails silently.

**Not every "show once" surface is a client-side preference (#1314).** The `user:prefs:*` / `board:{boardId}:*` namespaces above are for reading habits and display choices, where "has this device seen it" is the right question. A one-time prompt gated on **server state** — e.g. `pending_connect_provider` on the current user, driving `ConnectProviderModal` — stays server-owned: render it from the field's presence, and dismiss it with a real API call ("Not now" calls `dismissPendingConnect()`), never a localStorage/sessionStorage "seen" flag. A client-side marker would re-show the prompt on every other device and tab. Close optimistically; if the dismiss call fails, let the prompt reappear on a later load rather than blocking the user.

## Write-only secret fields ("leave blank to keep")

**Stored URLs that may embed a token are masked (#863, Part 8 departure 21).** After save, an admin-entered URL that can carry a credential in its path or query (a webhook address) is shown only as `host/…/last4`, the server's `url_display`. The full value is never fetched again; changing it means entering a complete new one ("Change address…"), the same idea as the write-only fields below.

**Webhook announcements never name the address (#863, a 1.3 UI spec Part 9 departure).** Every webhook announcement and event payload omits the URL, host, masked `host/…/last4`, secret and signature material, including an announcement only the acting admin hears: `role="status"`/`aria-live` text, an inline confirm that sits in a live region, a toast's live text, and any board event or socket payload. Name the webhook by position (`webhookPosition`: "Webhook 2 of 3 turned off.") or say "this address". The host is part of the URL, and "doesn't reach other admins" is a judgment call that stops being true when a live region is later reused for a shared refetch or event. Static labels on visible content (a row's `url_display`, a heading, a `Manage webhook …` `aria-label`) are not announcements and may show the masked address.

For an admin-editable secret the server never returns in cleartext (SMTP password, webhook signing secret, API key), use this pattern rather than inventing one per field. Reference: `EmailSettingsSection.tsx`'s password field.

- The input is `type="password"`, `autoComplete="new-password"`, starts empty, and its `placeholder` communicates **current state** rather than an example value: `"Leave blank to keep the current password"` when one is stored and usable, no placeholder when none is stored, and an explicit re-entry prompt (`"Enter the password again"`) when a stored value exists but cannot be decrypted.
- The unrecoverable-secret state is surfaced, never silent: `border-warning/50` on the input plus `text-warning` helper text naming the likely cause and the remedy.
- Two helper lines beneath the input say what is stored and what typing or leaving blank will do. Reserve them unconditionally (`h-8` for two `text-xs` lines, or `min-h-` if the copy can wrap).
- A `Clear` bare-text button appears in the label row **only** when a secret is stored and Clear has not already been pressed. It stages the removal — input disabled and empty, `text-warning` "will be cleared when you save", and an `Undo` bare-text button. The clear commits with Save, never on click.
- **On the wire, omit the key entirely unless the user typed a value (send it) or pressed Clear (send `""`).** "Leave blank" must never resolve to an empty string on the wire, or an unrelated edit silently wipes the secret.
- A validation error touching the secret **replaces both helper lines**, never just the first. Rendering "Leave blank if your server doesn't require a password." directly beneath "A password is required when a username is set." shows two contradictory instructions at once.
- Give each field's helper copy its own wording. Reusing one sentence across two fields (username and password, say) makes the UI read as boilerplate and makes text-based test queries ambiguous.

## Verification actions against a saved configuration

When a surface lets an admin verify a stored configuration against a live external system (send a test email, ping a webhook):

- **It tests saved state, never the draft.** Disable the action while the form is dirty and say why in both a `title` and the result region's first line ("Save your changes before testing."). Testing a draft would require sending an unsaved credential for a side-effecting action, and would not tell the admin what is actually live.
- Place it below the form's Save/Cancel footer behind a `pt-3 border-t border-line-subtle` divider. The physical separation is what makes "this tests what is live, not what you typed" legible without a paragraph of explanation. Use the **secondary** button variant — the form's Save is the primary action.
- The backend returns an **opaque error code from a closed set**, never a raw upstream error string. The frontend owns the copy: map each code in one lookup table to a `{ headline, remedy }` pair — headline in the tone color (`text-danger` / `text-warning` / `text-success`), remedy in `text-fg-muted` beneath it — and treat an unrecognized code as the generic failure rather than rendering it.
- Both lines live in reserved `text-xs h-4` containers inside a single `role="status" aria-live="polite" aria-atomic="true"` wrapper.
- A throttled response (429) is `text-warning`, not `text-danger` — nothing is broken, the admin is just early.
- Rate limits and retry windows are backend-owned numbers; interpolate them from the response where the API provides them rather than hardcoding them in the copy table, or the string goes stale silently when the limit changes.

## Disambiguating repeated button labels

When one page or tab can simultaneously render more than one bare-text button with the same visible label — most often `Cancel` or `Save` across two independent inline-confirm or composite-editor blocks — give each a distinguishing `aria-label` and keep the visible text generic (e.g. `aria-label="Discard email settings changes"`). Two controls accessibly named only "Cancel" are ambiguous for screen-reader rotor navigation and for `getByRole`/`getByText` queries alike. This is not hypothetical: it broke `adminPage.test.tsx` in #306, where the Email section's footer Cancel collided with the maintenance-mode confirm's Cancel.

## Read-only mode for interactive components

Any component that calls `useDraggable`, `useSortable`, or registers interactive event handlers must accept a `readOnly?: boolean` prop. When `readOnly={true}`:

- Skip the DnD hook call entirely (avoids errors when the component is rendered outside a `DndContext`)
- Replace `cursor-grab` with `cursor-default`
- Remove `hover:-translate-y-0.5` and any other drag-affordance hover effects
- Turn `onClick` into a no-op (or omit the handler entirely)

This applies to `CardItem` and any future draggable component used in unauthenticated or view-only contexts (e.g. share board page, print view).

## Read-only composite editors (#2090)

A multi-field form that some roles may view but not change (the admin Email settings section) shows its values with the fields `disabled` and the action buttons (Save, Cancel, Clear) omitted. A single `text-xs text-fg-muted` note near the top says who can change it, and `aria-describedby` on each control points at the note's `id`. Copy that tells the user to type, re-enter or clear a value is replaced with "ask a superuser" wording.

This is a deliberate exception to "omit controls, never disabled" (Withheld row actions, and the card-detail sub-section rule) and to the plain read-only text line used for single-value settings. Those rules cover a control that does nothing for the viewer. Here the stored values are the content the viewer came for, and bare text lines would drop the labels and layout they rely on. Do not use this pattern for a navigation link or a single action; omit those.

## One-time token reveal

When a token or secret is shown exactly once after creation (e.g. invite links, PATs), use an inline expanded state on the newly created row — never a modal or toast:

1. After creation, replace the creation form area with:
   - `text-xs text-warning` notice: "Copy this link now — it won't be shown again."
   - Monospace display field: `font-mono text-xs bg-sunken border border-warning/50 rounded px-2 py-1.5 text-fg truncate` with `title` attribute for full value
   - Copy button (primary variant)
   - "Done" button (Quiet variant) that collapses the row to prefix-only display
2. Row collapses to prefix-only display after the user copies or clicks Done
3. Never store the full token client-side after the reveal state is dismissed
4. Use `transition-all duration-150` on the expanded row so it does not pop in
5. **Focus and announcement (#1935).** When the reveal mounts because of an action whose trigger then unmounts (Create, Rotate, Generate), move focus to the Copy button, and give Copy `aria-describedby` pointing at the warning note so the one-time warning is read on arrival. When Done dismisses it, move focus to the next logical control (for example Rotate link), never `<body>`. The surface's status slot is `role="status" aria-live="polite" aria-atomic="true"` so create, rotate and copy results and failures are announced. Add `select-all` to the display field so the "copy it manually" fallback is one click.
6. **A secret that exists but can no longer be shown (#1935).** Render a plain-language "is active" line, its expiry (`text-warning` once expired, with the word "Expired" so color is not the only signal), and a Rotate action. Put Rotate in the `ml-6 border-l-2 border-line pl-4` subordinate block under the toggle that enables the secret, grouped with any select that configures the replacement (described by the rotate helper, not by an unrelated helper). Rotate may skip a confirm only while revoking the same secret also has none, and its helper states the consequence ("the current link stops working") before the click. Reference: the Sharing tab in `BoardSettingsModal.tsx`.
7. **Withdrawing a reveal because the secret changed elsewhere (#1967).** When a socket event shows that the revealed secret was revoked or replaced by someone else (another admin, another tab, or the server), remove the reveal, clear any stale error about it in the same step (a failed-copy message), and put one neutral sentence in the surface's existing status slot (`text-fg-secondary`, shown after the error and copied states). The sentence says what happened, then what still works or what to do next ("The link shown here was replaced elsewhere and no longer works. Rotate the link to get a new one."). Clear it on the next local action and when the secret's state changes again. Move focus only if it was inside the reveal, and then to the section heading (`tabIndex={-1}`, `focus:outline-none`), never to Rotate or the enabling toggle: a reflexive Enter there would destroy the secret the other person just created. Tell a replacement from your own change's echo with a non-secret value your own request returned (`share_token_issued_at` against the event's `issued_at`), never by arrival timing. Withdraw only for a LATER issue, so a delayed frame about an older secret cannot remove a newer reveal, and check again when your own response lands, because the other person's frame can arrive first. Size the status slot with `min-h-4`, not `h-4`, so a longer sentence wraps instead of overflowing. A late async result (a copy that resolves after the withdrawal) must not report success for the dead secret.
8. **Acknowledged one-time reveal (#863, a 1.3 UI spec Part 8 departure).** For a secret whose loss breaks an integration (a webhook signing secret), the reveal adds an "I've stored this secret somewhere safe" checkbox. Done is `aria-disabled` (not `disabled`, so it stays focusable) until it is checked, with an `aria-describedby` hint ("Tick the box once the secret is stored to finish.") visible while it is inert; an inert click moves focus to the checkbox instead of doing nothing. Until then Escape (the host's top claim), the modal's Close button, its backdrop and any navigation out of the view open an inline prompt, "Close without storing the secret? You'd have to rotate it to get a new one.", with Confirm (does what was asked) and Cancel (focus back to Copy). The value is a read-only `<input>` that selects all on focus, so a keyboard user can copy it when the clipboard API is blocked. Reference: `WebhookSecretReveal`.

## Blocked rows in pickers (#1692)

- A picker row the caller may not choose (e.g. a group they cannot place boards in) stays visible and focusable, whether or not it has selectable descendants: the user sees why a group they know about is unavailable, and in a tree picker the row is also the path to its children. This is the named exception to the *Permission-gated and context-gated* hiding rule above. Block it with `aria-disabled="true"` (never native `disabled`), no `onClick`, `cursor-not-allowed`, and the label in `text-fg-muted`.
- The reason is always visible inline as `text-xs text-fg-tertiary` and tied to the row with `aria-describedby`; do not duplicate it in `title` (put `title` on the truncated label instead).
- A row that would be blocked but is the current value keeps its selected styling and says "Current ..." instead of the block reason. It stays selectable, because choosing it again means "leave it where it is" and sends no request.
- Ancestors of selectable or selected rows start expanded.
- Every tree-toggle chevron carries an `aria-label` (`Expand|Collapse <name>`), `aria-expanded` and the standard focus ring. Leaf rows render a non-focusable spacer (`<span className="w-5 shrink-0" />`), never an invisible button.
- Selection is exposed with `aria-pressed` on the row button. Reference: `MoveBoardModal`.

## Choices a select can't offer yet stay in it, disabled, with why (#2719)

The `SelectDropdown` form of *Blocked rows in pickers (#1692)* above. When a choice the user would expect (a board they can add cards to, a board they administer) fails a rule they can fix, it stays in the select as a disabled option, never dropped silently and never moved to a separate list beside it.

- Pass `{ value, label, disabled: true, description }`. `description` is the reason, sentence case, saying what to fix ("Add a swimlane first", "Its first column doesn't allow new cards"); it renders as a second `text-xs text-fg-tertiary` line and is tied to the option with `aria-describedby`, and the option is named by its label alone. The row carries `aria-disabled="true"`, `cursor-not-allowed`, a `text-fg-muted` label and no hover fill. Reference: `unavailableOption` in `components/Card/childBoardOptionsCap.ts`, used by the Add child and Default child board selects.
- Disabled options go after the choices that can be picked, in the server's order (by name), so the list opens on something usable.
- Keyboard skips them: arrow keys, Home/End and type-to-jump move only between enabled options, a disabled option is never the initial highlight, and click, Enter and Space on one do nothing (the menu stays open). This differs from #1692's focusable tree rows because a select's keyboard path is for choosing, and an unreachable row costs nothing there. Because keyboard and screen-reader users therefore never land on them, `SelectDropdown` adds a visually hidden "Unavailable: <label> (<reason>); ..." to the trigger's `aria-describedby`, after the caller's own ids.
- The current value is never disabled (#1692). A current value that would now be blocked keeps its name, stays selectable and says "Current ..." as its description instead of the block reason (the Default child board select's "Current default").
- When those choices are the only ones, render no select: a select that opens on nothing choosable is a dead end that hides the reasons. This is the one deliberate exception to "never moved to a separate list" above (owner decision 2026-11-27). Say so in the empty-state sentence ("No board can take new children from <board> yet. Fix one of these first, or ask a board admin to.") and list each one with its reason under it (`UnavailableChildBoards`, Add child's empty state only).

## Multi-step import wizards and file uploads (#456)

Established by the Trello import wizard (`components/Board/TrelloImportModal.tsx`, `components/Board/trello/`). Reuse these for any future import/creation wizard.

- **Wizard shell.** A multi-step flow inside `ModalWrapper` uses `maxWidth="max-w-2xl" noPadding headerBorder`, with `subtitle="Step X of N · {step name}"` as the only step indicator — no stepper graphic. Each step renders an `h3` (`text-sm font-medium text-fg-tertiary uppercase tracking-wide`, `tabIndex={-1}`) that receives focus on every step change, because the button that triggered the change unmounts; skip it on first open (`ModalWrapper` focuses the panel). Any step with variable-height content, **and the in-flight state that follows it**, uses the fixed panel height `h-[85vh] max-h-[640px] min-h-0` so the panel never collapses and re-expands mid-flow. Footer: bare-text Back on the left (`justify-between`), Cancel + primary grouped right with `gap-3`, `flex-wrap` for narrow widths. While a non-cancelable write is in flight the footer is not rendered and the modal is `dismissable={false}`.
- **One live region per wizard.** Exactly one `role="status" aria-live="polite" aria-atomic="true"` element, placed between the scrolling body and the footer (so errors stay next to the buttons when the body is scrolled). It holds an `sr-only` announcement span plus the visible error callout. Show an error **only** in the callout — set the sr-only text to `""` — or screen readers read it twice and RTL `getByText` finds duplicates. Callout tones: danger `bg-danger/10 border-danger/30 text-danger`; rate limits (429) use warning `bg-warning/10 border-warning/30 text-warning`.
- **A blocked primary action explains itself.** When the primary button is blocked by a field that may be scrolled out of view, use `aria-disabled` (with `aria-disabled:opacity-40 aria-disabled:cursor-not-allowed`) instead of `disabled`, point `aria-describedby` at an `sr-only` reason, and on click focus the offending field instead of submitting.
- **Upload progress bar.** Track `h-2 rounded-full bg-sunken overflow-hidden`; fill `h-full bg-button-primary transition-[width] motion-reduce:transition-none`; the track carries `role="progressbar"`, `aria-label`, `aria-valuemin/max`, `aria-valuenow`. At 100% the bytes are sent but the server is still working, so switch to indeterminate — omit `aria-valuenow`, full-width fill with `animate-pulse` (under `motion-reduce`, a static one-third fill — never full; see § Motion and reduced motion above and the Reduced motion bullet in § Import Board sample gallery) — and change the paired text (and the busy button label) from "Uploading… N%" to the server-phase copy. Announce progress through the live region in 25% buckets only. An in-button spinner on a primary fill uses `border-on-primary border-t-transparent` (the `border-primary` spinner in § Loading assumes a neutral background).
- **Dropzone-as-button.** A file dropzone is one full-width `<button type="button">` (native Enter/Space) wrapping nothing but text, with a sibling `<input type="file" className="hidden">`. The field title is a `<p id>` referenced by the button's `aria-labelledby` — never a `<label htmlFor>` pointing at the hidden input. Style: `w-full border border-dashed rounded-lg p-6 text-center`; idle `border-line-strong hover:border-line-emphasis` (exempt from the #2505 boundary-token rule because the text label names the control; see the rule on `border-line-strong`'s contrast near the end of this file), drag-over `border-primary-emphasis bg-primary-emphasis/10`; inner text spans are `pointer-events-none` so `dragleave` does not flicker. This is the **one sanctioned exception** to the `rounded`-only button rule. The button's `aria-labelledby` lists the title id **and its own id**, so the chosen file name stays in the accessible name ("File board.json"); locate it in tests with a regex, not an exact string (#1440). While busy use `aria-disabled` (not `disabled` — a disabled button stops receiving drop events) and guard the handlers. The dropzone **and the enclosing wizard body** both `preventDefault` on `dragover`/`drop`, so a stray drop never navigates the browser to the file. Reset `e.target.value = ""` after a pick so re-picking the same file fires `onChange`. Validate the file **type** on pick, show the message in the live region, and disable Continue rather than rejecting the pick. Never hard-code a server-configurable size limit as a blocking client check: at most show it as advisory copy ("25 MB by default"), and on a `413` show the server's JSON `detail` when present, falling back to generic "too large for this server" copy for a non-JSON proxy `413`.
- **Review-summary tiles.** `grid grid-cols-2 sm:grid-cols-4 gap-2`; tile `bg-sunken border border-line rounded-lg px-3 py-2`; value `font-mono text-lg` (`text-fg-secondary`, or `text-fg-muted` when zero — render `0`, never an em-dash, which reads as "unknown"); caption `text-xs text-fg-muted`, singular when the value is 1 (no "(s)").
- **Matched-user privacy in import previews.** An import preview shows matched existing Visiban users **only as a count** — never names, usernames, emails, or avatars — and lists only the unmatched external identities by the name in the uploaded file. The copy states that matching is limited to people the importer can already see. This is a security requirement (user-enumeration), not a style preference.
- **Focusable scroll regions.** Any inner `overflow-y-auto` region given `tabIndex={0}` so keyboard users can scroll it needs an accessible name (`<ul>`/`<table>` with `aria-label`, or a `div` with `role="group"` + `aria-label` — not `role="region"`, see the landmark cap) and a focus ring: `focus:outline-none focus:ring-2 focus:ring-inset focus:ring-primary-emphasis`.
- **Import options (#119).** Choosing what an import includes is a `<fieldset className="min-w-0">` with a `<legend>` styled as a field label (`block text-xs font-medium text-fg-tertiary uppercase tracking-wide mb-1.5`), a `text-xs text-fg-muted` line naming what is always imported (the fieldset's `aria-describedby`), and native checkboxes (the `EditColumnModal` idiom) in one `space-y-2 bg-sunken border border-line rounded-lg px-3 py-2.5` box. Mount it only once a supported file is chosen, and reset every choice on each new pick. An option that depends on another is indented `ml-6 border-l-2 border-line pl-4` and uses native `disabled` (so it leaves the tab order) while its parent is off; turning the parent off unchecks it, turning it back on restores the value from just before (memoize it — never reset a deliberate choice to the default). Each row has an always-rendered `text-xs text-fg-muted mt-0.5 ml-6 min-h-4` consequence slot wired with `aria-describedby` (rest copy, the short "… are skipped" consequence, or "Requires {parent}"), so a row keeps its height as long as its copy fits one line; the slots are not live regions — one polite `sr-only` status region announces only the parent cascade. Consequence-slot copy must fit one line at `max-w-md` (about 45 characters for a dependent row); if it cannot, reserve `min-h-8`. Under the fieldset an "Importing: …" summary line (`text-xs text-fg-muted min-h-8`) reads "Importing: everything" or lists what is selected, and is the primary button's `aria-describedby` (dropped while submitting). Never send contradictory options (a dependent `true` with its parent `false`), and send nothing at all when every option is at its default. Report what was skipped afterwards in an informational-tone notice (`bg-primary/15`, never amber — skipping was a choice, not a failure): only non-zero counts (cards, comments, checklist items, card labels, and movements plus activity entries as "history entries"), singular for one, at most three then "and N more". Its live region is an sr-only `role="status"` child, mounted empty with the text set one tick later (see § Post-import notice). The notice mounts bottom-center like `MoveBlockedToast` and must not render while a move error is showing (the warning wins). Give it an explicit width (`w-max max-w-[min(24rem,calc(100%-2rem))]`) because an absolutely positioned `left-1/2` element otherwise collapses to half its container at narrow widths. It auto-dismisses after 8s and pauses while hovered or focused, except that a notice carrying `import_summary.warnings` persists until dismissed (see § Post-import notice). This is a sanctioned exception to § Subordinate settings blocks' single-toggle limit and its `ariaDisabled` guidance: the dependents are a fixed, tiny set whose existence is the thing being advertised, the "Requires {parent}" reason is also in the always-rendered slot, and the parent's cascade announcement tells screen-reader users why they are gone from the tab order. Dim an unavailable dependent's label text with `text-fg-muted` on the label `<span>` only; do not put `opacity-*` on the `<label>` (it double-dims the native disabled control).
- **Neutral state pill.** A neutral status pill (e.g. "Archived", "Skipped") is `px-2 py-0.5 text-xs rounded-full border border-line text-fg-tertiary`. Never `text-fg-muted` on `bg-surface-hover` (see § De-emphasized controls). The state is always spelled as a word, never carried by tone alone.

## Import Board sample gallery (#1452)

`SampleGallery` ("Start from a sample") sits above the dropzone in `ImportBoardModal`. It is named *sample*, not *template* (`BoardTemplate` is a different concept) and owns no import logic: it takes `onSelect`, so user-defined templates (#442) can add an entry point beside it.

- **Modal shell.** `max-w-[640px]` (was `max-w-md`) so two cards fit side by side; the panel is `max-h-[calc(100dvh-2rem)]` and the *body* scrolls (`flex-1 min-h-0 overflow-y-auto`, `px-4 sm:px-6`) so the header and footer stay fixed. Below 560px the grid is one column and the collapsed view shows 3 samples, not 4. Below ~672px of viewport the panel is the viewport minus the backdrop's `p-4`, so no separate "sheet" shell exists.
- **Fold budget.** At 1280x768 the collapsed gallery must leave the dropzone and footer in view (`e2e/import-samples.spec.ts` pins it). Cards are ~133px; any chrome added to a card or above the gallery spends that budget.
- **Cards.** A `<ul>` of `<li>`; the only focusable element is the card's button, whose `::after` stretches over the card (`relative` card, `after:absolute after:inset-0`), so a click anywhere selects it without a handler on a `div` (§ Click handlers need keyboard parity). The card shows the focus ring (`focus-within`), never the button. Text comes from the manifest; secondary text is `text-fg-tertiary` (`text-fg-muted` fails AA on the dark surface). Accessible names contain the visible label (WCAG 2.5.3): `Use this sample: {Title}`, and `Try again, {Title} sample` after a failure.
- **Includes badges render once when every sample is identical** ("Every sample includes" under the helper text) and per card as soon as any sample differs — derived from the data, never hand-toggled.
- **One Tab stop.** Roving `tabindex` (the focused card is `0`, the rest `-1`); the last-focused card is remembered. Arrow keys move in two dimensions without selecting, Home/End jump, Enter/Space select. "Show all" moves focus to the first revealed card (card 5, or card 4 in one column); "Show fewer" leaves focus on the toggle, and the tab stop falls back to the last visible card while the remembered one is hidden.
- **Focus is never stolen.** On open, focus goes to the first card (or **Retry** when the list is unavailable) only if it is still on the dialog or lost. A failed card moves focus to its **Try again**. An Esc-canceled load and **Change** return focus to that sample's card, expanding the list first if it sits behind "Show all".
- **Announce each message once.** The modal's one persistent polite live region (mounted empty) announces "Loading the {Title} sample." and "Loading canceled."; the card's "Loading sample…" is `aria-hidden` visual text. A per-card failure is its own `role="alert"` only and never reaches the submit error banner. Do not add a second `role="status"` for the gallery.
- **Other samples while one loads** are `aria-disabled` (not `disabled`, so the roving focus survives), and the dropzone stays usable: choosing a file aborts the request.
- **Abort for real.** A new pick, Escape, a file choice and unmount `abort()` the in-flight `AbortController`; a late response from an aborted request is ignored. Escape runs at `useEscapeStack` **48** (see the modal allocation list) and returns `false` when nothing is loading; the board-name input has no Escape handler of its own (#1973), or it would close the modal first.
- **Reduced motion.** The indeterminate bar pulses; at `motion-reduce` it is a static one-third bar, never a full one that reads as "done".
- **Unavailable list.** The grid is replaced by the neutral notice banner with **Retry**, the divider reads "Upload your own file" (no "or"), and an empty list counts as unavailable — the section never disappears silently.
- **Upload notes follow the dropzone.** The size-limit notice and the Trello link moved below the dropzone to pay for the fold budget; both are hidden while a sample is the source.
- **Next step.** A fetched sample replaces the dropzone with a "From sample: {Title} · ~{n} cards" row and **Change** (no footer Back); the import sends `shift_dates_from` so the board is not mostly overdue, and never a `name`, so "Imported: <title>" numbering still applies.
- **Dates (#1949).** A **Dates** fieldset follows the Include summary only when the import would shift: a sample, or a chosen `.json` whose top-level `date_anchor` the modal reads client-side (display only; the server reads the same key and shifts by default). It holds one checkbox, **Move dates to today** (on; unticking sends `shift_dates: false` and never `shift_dates_from`), with an always-rendered `min-h-4` hint slot, and an **Adjust dates** disclosure (`aria-expanded`/`aria-controls`, closed by default so occasional users never meet the date field) revealing a `type="date"` input labelled "Date the board around", defaulting to the browser's today with `max` today. The day is sent as `shift_dates_to` only when it differs from today; an unchanged or cleared field sends nothing and the server uses today (UTC). A raw anchored file with every default sends no options at all, keeping the two-argument `onImport` call. A new file or sample resets all three (checked, closed, today).
  - **The checkbox label stays static** ("Move dates to today") so its accessible name never changes mid-interaction; the hint slot is the one element that restates a custom day, formatted with the user's `date_format` (`formatDateStr`, passed in as the `dateFormat` prop), never raw ISO. The disclosure keeps the name **Adjust dates** (the wording the owner approved for #1949). The default path sends no day and the server dates it to today in UTC, so near local midnight "today" in the hint can be a day off from the server's; that is accepted because sending the browser's local today would be refused as "in the future" for zones ahead of UTC.
  - **A disclosure's `aria-controls` is set only while its panel is mounted**, never pointing at an absent id.
  - **A `type="date"` input's `max`/`min` is not self-validating.** `max` only limits the native picker; a typed out-of-range day is treated as invalid in the payload logic (the Adjust dates field shows `Pick today or an earlier day.` in an always-mounted `role="alert"` `min-h-4` slot, `aria-invalid`, `aria-describedby` only while shown, `border-danger` + `focus:ring-danger-emphasis`, and blocks submit with focus moved to the field). A cleared value falls back to the default, and the hint says so.
  - **An always-rendered hint slot whose copy swaps reserves the height of its longest variant** at the narrowest modal width: `min-h-8` unless every variant is verified single-line (the Dates hint is `min-h-8`, like `#import-summary`).
  - **The Import button describes the date choice too:** with Dates shown its `aria-describedby` is `import-summary import-dates-hint`.
  - **A chosen file over the 10 MB upload limit is never read client-side** for its anchor; submit refuses it.

## Local input buffers and timers (#1319)

1. **Never seed a local input buffer from fetched or prop data in a `useEffect`.** An effect runs only after the commit that first shows the input, and it runs once on mount too. An edit that lands in that window is queued ahead of the late seed and silently overwritten by it. A loaded CI runner hits the window reliably; a user can hit it too. Seed in the fetch's `.then` together with the data (`EmailSettingsSection`'s `load`), or during render with the "adjust state when a prop changes" pattern: keep the last synced value in state and, when the prop differs, update both in the render (`AdminPage` `SettingsTab` maintenance notice, `CustomFieldValueInput`, `LensFilterBar`). Key the sync on the one field the buffer mirrors, never on the whole object, so an unrelated save does not discard an in-progress edit. A buffer component gets a regression test that types inside the window (see `docs/development/testing.md` § Flake-resistance checklist (Vitest unit tests)).
2. **A timer with a delay holds its id in a ref and is cleared on unmount.** A discarded id cannot be cleared, so the callback can fire after the component is gone (a ProfileTab save once navigated during a later test). ESLint `no-restricted-syntax` (in `src/components`, `src/pages`, `src/hooks`, `src/context`, `src/contexts` and `src/App.tsx`) rejects a `setTimeout`/`setInterval` call, bare or on `window`/`globalThis`, with a delay other than a literal `0`, when its return value is visibly discarded: the call is a whole statement, the expression body of an arrow (`.then(() => setTimeout(...))`), or the operand of `void`. Zero-delay hops (focus after render, resetting a ref) are allowed. It does **not** catch an id that is stored but never cleared (`const t = setTimeout(...)` with no `clearTimeout(t)`, or a ref whose unmount cleanup is missing, the #1304/#1305 shape), nor a call discarded another way (`cond && setTimeout(...)`). So review checks for the unmount cleanup, and the component gets a test that unmounts with the timer pending.
3. **Focus that replaces a removed control moves in `useLayoutEffect`, never `useEffect` or `requestAnimationFrame` (#2608).** When an async write's commit removes the focused control (Unlink, Save, a picker's Link) and an effect moves focus to its successor, the browser has already dropped focus to `<body>`; a passive effect or a frame callback leaves it there past paint, and on a loaded machine a screen reader (or a test resuming from `findBy*`) lands on `<body>`. A layout effect runs in the same commit. Key the effect on the state change that removes the control, not on the request answering: a socket re-read can remove it first (`CardChildrenTab` records the intent before the `await`; `InviteLinkPanel` checks for lost focus when the list changes during a revoke). When the successor may not be mounted yet (a card in its new cell), use `useFocusWhenPresent` (`hooks/useFocusWhenPresent.ts`, #2632): a layout effect plus a scoped MutationObserver, never a frame-polling retry. References: `CardParentSection.tsx`, `CardExternalRefSection.tsx`, `CardChildrenTab.tsx` (Unlink, Move), `InviteLinkPanel.tsx` (revoke), `CardPeekSheet.tsx` (every close of the Move form, the offline pause included, except after a write once focus has left the form; and a forced move's failure that removes the link), `CardDetail.tsx` (override hard refusal), `BoardSettingsWebhooksTab.tsx` (re-enable), `GroupDetail.tsx` (Load more), `EditColumnModal.tsx` (Save stage, #2609). An action on a toast that removes its own button before the successor exists (Undo) first parks focus on a surviving container (`tabIndex={-1}`), before `dismiss` (`CardChildrenTab` Undo, #2611). Test it by reading `document.activeElement` inside the `waitFor` callback that finds the successor (see `cardParentChildSide1104.test.tsx`).
