## Analytics page structure and URL state (#2457, #2318)

- **The Overview is four question sections, in this order:** "What is happening?" (bottleneck and headline tiles), "How fast does work move?" (Throughput, Cycle time), "Where is work stuck?" (How work flows, Cumulative flow, WIP age) and "Why is it stuck?" (Why cards get blocked, Needs attention). A new panel goes under the question it answers; do not add a fifth section for one panel.
- **Headings are flat `h2`, on purpose:** the page title, each question heading and each panel heading are all `h2`. The shell owns the `h1` (#2473) and the sections are peers, so do not nest panels at `h3` to look hierarchical, and do not change the level without updating the e2e `level: 2` assertion in `flow-metrics.spec.ts`.
- **An empty panel never renders `null`.** A panel with nothing to show (no blocks in the period, no flagged cards) keeps its frame and says so, so the grid row does not collapse and the reader can tell "none" from "failed to load".
- **`a_*` URL state uses history replace, and defaults are never written.** Period, Swimlane, Label, Break down by and the Overview/Swimlanes choice live beside `?view=analytics` and are written with `{ replace: true }` (a filter change is not a page, so Back leaves Analytics). A parameter at its default (`a_days=90`, no lane, Overview) is deleted, not written. Leaving the tab clears every `a_*` parameter.
- **Swimlanes "Group lanes by" and "Sort" are `a_group` and `a_sort` (#2546).** `a_group` is a swimlane custom field id and `a_sort` is one of `slowest` (default), `fastest`, `blocked`, `name`, `board`. They follow the rule above: replace not push, the default never written, and an unknown value (a field the board lacks, a bad sort) falls back to the default. They are owned by `AnalyticsView` and passed to `AnalyticsSwimlanes` as controlled props; parse and write them only through `analyticsUrlState.ts`.
- **The Overview's requests are sent in sequence, never in parallel (#2428).** The overview request goes first and the heatmap request after it settles (success or failure, each reporting its own outcome), because a server admits one analytics request per process by default. Results still swap in together once both settle, the previous answers stay dimmed on screen, and skeletons show only before the first answer. Do not wrap Overview requests in `Promise.all`; a new request joins the chain, and its latency is weighed against the single slot. A busy refusal is retried once after `Retry-After`; a too-large refusal is never retried and has no Retry control.
- **An id the board does not have is dropped, not sent.** A swimlane or label id in the URL that is not in the board's lists (including when the list is empty) becomes "none" before any request, because the API 400s on an unknown `label_id`.

## History labels that quote user text

A History row is one `truncate` line with the full text in `title`, so a label that quotes user-entered text (an item name, a title) caps that text, then puts the values after it: `Checklist item "<name, at most 40 characters, then …>" assignee: old → new` (#2199, `checklistItemLead` in `utils/cardTimelineLabels.ts`). The from → to values are what the row is for and must not be pushed out of view by the quoted name.

## Summary and analytics table layout

- Any table in a Summary or Analytics view that may exceed the viewport width must **pin its first column** sticky-left: `sticky left-0 bg-sunken` (matching the column's own background token)
- New metric columns grouped under a common section must use a two-row `<thead>`: first row `colspan` spanning the group with a `text-xs text-fg-muted uppercase tracking-wide` group label, second row with individual headers
- Numeric metric cells: `font-mono text-fg-secondary`; zero or null values render `—` in `text-fg-muted`, never `0`

## Extension panels (Summary tab)

- `SummaryView` renders enterprise `extension_panels` directly after the swimlane `</table>`, inside the same scroll container, via `ExtensionPanels`. Render nothing (no wrapper, heading, or margin) when there are none.
- The array is untrusted: always run it through `parseExtensionPanels` (`parseExtensionPanels.ts`); never render raw entries.
- A panel supplies text and numbers only, never classes, colors, styles, HTML, Markdown, or links. Render every string as a React text node. A future link field must pass `isHttpUrl()` from `utils/externalRef.ts`.
- Each panel is `role="group"` labeled by its `<h3>`, per § Inline summary panels. Derive the heading id from `useId()`, never from the payload id.
- A real numeric `0` renders as `0` (a producer's zero is data, unlike the swimlane metric columns); only `null` renders the muted `—`. Panel tables are exempt from the pinned first column rule: they are narrow (at most 12 columns) and scroll inside their own `overflow-x-auto`.
- The payload shape is a public, additive-only contract (`docs/api/boards.md` "Extension panel payload"): add optional fields or a new `type` name, never change an existing one.

## Analytics / split-panel scroll layout

When a panel contains a fixed reference section (toolbar + table) and a scrollable list below it:

- Use `flex-1 overflow-hidden flex flex-col` on the outer container — **no `overflow-auto` on the outer container**
- Pinned section: `shrink-0 flex flex-col` — grows to natural height; add `overflow-x-auto overflow-y-auto max-h-[40vh]` on the table wrapper if it can overflow vertically (many rows)
- Scrollable section: `flex-1 overflow-y-auto min-h-0` with an explicit `minHeight: "8rem"` floor so the section is never a zero-height peephole
- Separate the two regions with the standard engraved double-`<div>` separator (`h-px bg-sunken` / `h-px bg-surface-active/50`) — never a plain `border-t` alone; the engraved pattern is used everywhere else in the design system
- Add a count label inline with the section heading (`flex items-center gap-2`) using `text-xs text-fg-muted` — e.g. "N cards stalled" or "N items". Use a ternary for singular/plural (`"1 card"` / `"N cards"`), never the `(s)` parenthetical form
- Sticky first-column cells inside a horizontally-scrolling table must carry `bg-sunken` to match the scroll container's background; verify this is not broken when the outer `p-4` moves to inner sections

## System event visual treatment in timeline views

Apply this consistently in `ActivityTabPanel` and `MovementHistoryView`:

| Event type | Timeline dot | Card left border |
|---|---|---|
| Column move | `bg-primary-emphasis` | none |
| Activity (comment, assign) | `bg-fg-muted` | none |
| Archived | `bg-surface-active` | `border-l-2 border-line-strong` |
| Reactivated (restored) | `bg-activity-reactivated` | `border-l-2 border-activity-reactivated` |

- System event label text (`text-fg-tertiary italic` for "Archived", `text-accent-violet` for "Reactivated") is visually distinct from column-move text (`text-fg-secondary font-medium`)
- Do not collapse system events by default — Jordan's audit trail use case requires them visible

**Custom trigger (#2317).** `OverflowMenu` accepts `triggerIcon`, `triggerClassName`, `triggerAriaLabel`, `triggerTitle`, `triggerTestId` and `align`. A custom `triggerClassName` must carry the standard focus ring and gets no open-state tint (`aria-expanded` is the cue). `align="left"` panels flip to right-aligned when 240px would pass the viewport edge. Callers must keep `items` referentially stable across renders with the same content (memoize on content, not on a prop array that a board reload replaces): the focus-first-item effect re-runs when `items` changes identity, so an inline `.map` or a memo keyed on fresh objects yanks focus back during arrow-key navigation. A color dot in the item icon slot is decorative (the slot is `aria-hidden`); the label must carry the meaning.

### Imported history attribution (#1675, #1702)

A movement or activity created by a board import with history, and a comment created by a JSON or Trello import, carries `imported_from_username` (`null` = recorded or posted on this board, or imported by an earlier version that did not keep the name). Render it only through `src/utils/importedHistory.ts` so every surface says the same thing:

- **Card timeline (`ActivityTabPanel`)** — the right-hand by-line becomes `historyAttribution(actor, imported_from_username)`: `by Kelly · imported, originally alice`, `by Kelly · imported` when the file named nobody, or just the note when the importer account is gone. Same `text-xs text-fg-tertiary` span as the plain by-line, plus `max-w-full truncate` and the full text in `title` — a source name can be 150 characters.
- **Card comments (`CardDetail`)** — the avatar and name stay the comment's `author` (the importer); `importedNote(imported_from_username)` follows the time in the comment header as its own `text-xs text-fg-muted min-w-0 truncate` span with the full text in `title`: `imported, originally Ada Lovelace`. Nothing is added for a comment posted on the board. In the comment header the time stays `shrink-0 whitespace-nowrap`; the author name and the imported note are the only spans that truncate, and both carry the full text in `title`. The delete control keeps `ml-auto`.
- **Board History view (`MovementHistoryView`)** — the note goes on its own `block truncate text-fg-muted` line under the mover's name in the table cell (with `title`), and after the name as ` · imported, originally alice` in the slide-in panel.
- **Never** render the source name as a user (no avatar, no `userDisplayName`, no link): it is text from a file, not an account on this instance. Never use a badge or color for it — the note is metadata, not status.
- Checklist-group collapsing must not merge an imported entry with a recorded one (or two different source names): the group has one attribution line, so it has to be true for every item.

## Charts (#448, #2028)

Every chart is hand-rolled SVG on the shared primitive, `components/Common/Chart.tsx` with `utils/chartScale.ts`: `ChartFrame`, `ChartPanel`, `ChartReferenceLines`, `ChartPointHit`/`ChartBandHit`, `ChartTable`. No chart library, and no second set of axes. #1774's `series` panel renders through it too, so keep it free of flow-metric knowledge.

- **One hue with alpha steps.** Strokes and fills are `CHART_HUE` and `chartTint(alpha)` (the `primary-emphasis` token). **One column is one shade everywhere (#2311):** the time bar, its legend, the flow-row squares and the cumulative flow's in-progress bands all take `columnAlpha(index, total)` from `flowRowData.ts` (board order; floor 0.55, rising to 1.0; a single column 0.7). Never write a second ramp for Analytics flow marks (the Summary view's different 0.4 + 0.6 opacity scale in `SummaryView.tsx` is separate). The floor is 0.55 so the lightest segment is 1.97:1 (dark 2.16:1) against the panel, up from 1.62:1; a segment's number sits in an opaque `bg-surface` chip with `shadow-sm`, and the gutter between segments is `bg-surface`, not `bg-line` (1.09:1). Band separators in the cumulative flow are `rgb(var(--surface))` strokes. No categorical palette, and no status colors: red, amber and green stay reserved for system signals. **Three exceptions, all on the Analytics tab (#2257, #458; full mapping in `docs/development/analytics-redesign.md` § Chart colors):** (1) the bottleneck column is drawn in `warning` and hatched wherever it appears (the cumulative flow band, the time bar, the flow row), and a slower-than-board swimlane's bar uses `warning`; (2) aging marks past the 50th percentile use `warning` and past the 85th `danger`, next to the ring and square, because age is the same system signal as the card aging tint, and blocked-time bars and over-limit outlines use `danger`; (3) a breakdown by swimlane, label or custom field colors marks with the five `--chart-cat-*` tokens plus a neutral "Other". A group color always comes with a legend whose chips isolate one group and with a group column in the table view. Nothing else gets a categorical palette, and no `--chart-cat-*` token is orange, red or green.
- **Named colors only.** The exceptions are `CHART_COLORS.warning` / `danger` / `neutral` (`chartScale.ts`), passed by name through `ReferenceLine.color` and `ChartPointHit`'s `color`, with `neutralTint` and `warningTint` for fills; never write an ad hoc status color in a chart. Aging marks take `ageMarkColor` (neutral to P50, warning past it, danger past P85); the Done band is neutral.
- **Chart color contrast (#2264).** Measured from `index.css` with the WCAG formula against `--surface` (the panel face), dark / light, and pinned in `onTintTokens.test.ts`: `CHART_HUE` (`primary-emphasis`) 3.98 / 3.68, `warning` 6.46 / 5.18, `danger` 5.29 / 4.83, `neutral` (`fg-tertiary`) 5.71 / 7.58. Every stroke and mark clears the 3:1 graphical-object floor (WCAG 1.4.11) in both themes. **Recorded exception:** `neutralTint`, the Done band's fill, is built on `--border-strong` and measures 1.93 / 2.56 before alpha (lower once tinted), so the fill is decoration only. The Done band is labeled directly at its right edge, and that label carries it (its top-edge stroke is the panel surface like every other band separator since #2311). Never use `neutralTint` for a mark that has no stroke or label, and never raise `--border-strong` for a chart: it is a shared token. The `--chart-cat-*` tokens named above are not yet in `index.css`, so no ratio is recorded for them; add one with the token.
- **A shape that tells two series apart needs a legend in the same shape** (the throughput diamond vs. dot); the hollow started diamond uses the `neutral` token at 1.5px or more (other hollow marks, such as the reopened cycle-time point, keep the chart hue). An SVG hatch line sits inside its tile (not at x=0, where the edge clips half the stroke) and is paired with a text note. Warning and danger marks carry a non-hue cue (ring, square, table row).
- **Empty-state recovery controls** (filter chips, "Show last N days", "Clear all filters") move focus to a stable target (the page heading) before the change unmounts them, carry `min-h-6`, truncate long names, and derive N from `DEFAULT_DAYS`. The persistent status line announces the state.
- **Color is never the only carrier.** Bands get 1px separators and a direct label at their right edge. Overlapping lines get a dash pattern from one vocabulary: 50th percentile dashed, 85th solid and heavier, 95th dotted, medians dashed. The bottleneck band is hatched (`<pattern>` from `HATCH_SVG`). A blocked card is a square, a card past P85 is ringed, a reopened sample is hollow. When a shape means something, say so in a `ChartPanel` note, and only when that shape is on screen.
- **Direct labels, in the margin.** Reference lines are labelled in the right margin (`REFERENCE_LABEL_MARGIN`), outside the plot, so a label cannot overprint a mark; labels of nearly equal lines spread with `spreadLabels`.
- **Text stays 12px.** `ChartFrame` measures its width and keeps the `viewBox` 1:1 with pixels. A fixed `viewBox` scaled into a narrow panel would shrink axis text below the `text-xs` floor. Axis text is `fill-fg-tertiary`, labels `fill-fg-secondary`, never `fg-muted`.
- **The server owns percentiles.** Draw what the API returns. A `null` draws no line and a note that names no number ("Too few cards to draw percentile lines."). Never compute a percentile in the browser.
- **Two layers.** The `role="img"` SVG holds read-only marks and is named by the panel's heading and summary. Interactive marks live in a sibling SVG, because `img` has presentational children and assistive technology may not reach a button inside it.
- **Hit targets are 24px whatever the mark's size,** with a ring on hover and focus. Marks are `tabIndex={-1}` by default: a chart can hold hundreds, so the table is the complete keyboard path. Only marks a design names as tab stops pass `tabbable` (the aging dots).
- **A bottleneck is named in text, not only in color.** A column or segment marked as the bottleneck carries a visible text label and an accessible-name suffix as well as the warning hue.
- **The bottleneck hatch is applied to every drawn instance,** including square glyphs and HTML boxes (`HATCH_SPEC` in `components/Board/flowMetrics/hatch.ts` is the one definition of angle, stripe, gap and opacity; `HATCH_CSS` and `HATCH_SVG` derive the gradient and the `<pattern>` from it, so never write a hatch by hand). The values are 45deg stripes, 2px stripe, 4px gap, a 20% warning ground; a hatched HTML box sits on an opaque `bg-surface` so the ground reads the same on any panel. The empty-state example bar uses it too.
- **Warning orange means the bottleneck or a slower swimlane.** A "currently selected" highlight uses the chart hue plus a non-color cue (bold name).
- **Limit-breach text is `text-danger`,** and the hollow over-limit squares use the `danger` outline. A WIP limit is the board-wide count, so a filtered view shows the count only and a limit of 0 means no limit.
- **A semi-transparent chart tint drawn in HTML sits on an opaque `bg-surface` underlay** so it matches its legend swatch.
- **A segmented HTML bar scrolls at narrow widths, never clips with `overflow-hidden`,** and its scroller is a focusable `role="region"` with an `aria-label`.
- **An interactive box whose `aria-label` replaces its content exposes the omitted stats with `aria-describedby`.**
- **A chart note names a shape only when it is on screen.** A legend swatch for it (`FlowLegends.tsx`) follows the same rule, is drawn from the shared definition (`HATCH_SVG`, `CHART_COLORS`) in the shape the chart draws, carries a text label, and is omitted under a breakdown when marks take group colors (#2284). A swatch adds no decoration the chart does not draw (no outline), the blocked square is keyed whenever one is drawn, and sibling legends on one page carry distinct `aria-label`s (`Throughput legend`, `Cumulative flow legend`, `WIP aging legend`), never a bare "Legend".
- **Every chart has a table.** Pinned first column, `font-mono` numerics, `—` for null and zero per § Summary and analytics table layout, scrolling in a focusable `role="region"`. Each drill-down mark has a button in its row.
- **Layout.** Two columns from `lg` (1024px), one below; a frame never grows past 760px.
- **Breakdown group colors (#2268).** `--chart-cat-1` to `-5` (via `GROUP_COLORS` / `groupColor()` in `chartScale.ts`, never a raw Tailwind color) color marks only while a breakdown is on. A group's color is its index in the response's `groups`; the collapsed "Other" group (`key` null) is always `CHART_COLORS.neutral`. Each token clears 3:1 on `surface`, `surface-sunken`, `canvas` and `surface-hover` in both themes (pinned in `analyticsBreakdown.test.tsx`); recheck all of them before changing a value. The spec's light `--chart-cat-5` is yellow-700 (hue about 35 degrees, close to amber): it is spec-mandated, so it is separated from the `warning` tint by contrast alone: a group's name never relies on color (legend, summary and table name it), and the color is not the only cue even where a group's mark shares a row with a warning mark. A card in no group is drawn neutral, not in an age color.
- **Isolating a group dims marks, never text (#2268).** A legend chip isolates one group: its marks stay at full strength and the rest drop to 20% (`markOpacityAttr` / `markOpacity`, which read `ISOLATED_OPACITY` from `chartScale.ts`; with no isolation, marks carry no `opacity` attribute). Dim the dot, bar or glyph only; names, totals and value labels stay readable. The isolation is an index into the groups on screen, so it is cleared when the breakdown or the returned groups change. A card in several groups (labels) takes the isolated group's color so its mark agrees with the selected chip.
- **Color under a breakdown is never the only carrier (#2268).** The summary names what the color means, the group legend has chips that name each group, and every table view has a group column showing the name beside its dot. The ring, square and hollow reopened dot keep their meaning.

The Analytics tab scrolls as one page since #448: it no longer pins the heatmap, so § Analytics / split-panel scroll layout does not apply to it. Dropdowns on that page pass `portalMenu`, because the page is a scrolling ancestor. `AnalyticsView` has one return, with the heatmap's states inside one slot: a child that fetches on mount must not change position when a sibling changes state, or React remounts it. Here a remount was four history replays and lost every filter. Since #2261 the filter state lives in `AnalyticsView` (`useAnalyticsFilters`) and `AnalyticsOverview` renders every region into an always-present `RegionSlot` that shows its own skeleton or failure inside its own frame (one exception, kept by #2264: the whole-page "Nothing has moved yet" / "No cards match these filters" block (`FlowEmptyStates.tsx`) replaces regions 5 to 9 when the data itself is empty, not when a sibling changes state, so going from empty to data remounts the charts; the no-match block carries a removable chip per filter, "Show last 90 days" when the period is shorter, and "Clear all filters"); a refetch keeps the previous answers on screen (`aria-busy`, `opacity-60`, an sr-only "Updating" status) and never keys a region on the filters. **A group of `h3` items that follows another region (the headline tiles) carries its own `h2`, visible or `sr-only`,** so its headings do not nest under the previous region's heading.
- **Inset list rows use `bg-sunken`, never `bg-canvas`, when they have a hover fill (#2263).** Light `--canvas` and `--surface-hover` are both slate-100, so `bg-canvas hover:bg-surface-hover` shows no hover. An age or severity carried by color alone (Needs attention age: `text-danger` past the 85th percentile, `text-warning` otherwise) must also be stated in text or an `aria-label`.
- **Headline tiles and flow-row callouts (#2311, Analytics tab).** A headline tile's label is `text-xs font-semibold uppercase tracking-wide text-fg-tertiary`; its number is `text-3xl font-bold text-fg tabular-nums`, so the number dominates; its unit is `text-sm text-fg-tertiary`; the footnote is unchanged and a warning or danger span in it is `font-semibold`. Over-limit is `danger` everywhere on the Analytics tab (the board column header keeps its own rule, § above; flow-row text, the Work in progress tile); `warning` is for cards past P85 on the tile and for the bottleneck. Flow-row column boxes use `border-line-strong`; the bottleneck box keeps `border-warning`, and so does the Bottleneck panel, which adds `ring-1 ring-inset ring-warning` for a 2px edge. **Queue growth:** only the bottleneck column's "Queue +N" is `text-warning font-semibold`; every other column's is `text-fg-secondary font-semibold` with a leading `▲` (`aria-hidden`, the text states it too), so orange keeps meaning "the bottleneck". Flow-row connectors are `bg-line-emphasis` (4.76:1 light on surface, up from 2.56). When two figures on the Analytics tab measure the same noun with different statistics (mean vs median), each label names its statistic (#2307): the flow-row connector reads "N avg / wk" (a mean over the range) and the Throughput tile reads "/ week" with "Median of N weeks." beneath. Never label a mean or a median with a bare "/ wk". Connector rate labels are `whitespace-nowrap` in a fixed-width box, so size the box for the longest label (e.g. "1,234.5 avg / wk"), not the typical one.
- **A refusal that retrying cannot fix shows its own cause-and-next-step copy and no Retry control on every surface that can receive it, and the advice must be actionable on that surface (#2428).** `analytics_too_large` is the case in point, and `analytics_timeout` follows it (#2645: the same request would run as long again): the Overview's failure line, the Swimlanes table (first load and refresh), the cumulative-flow day drill-down and the Summary tab each show `analyticsErrorMessage(kind)` from `api/analyticsErrors.ts` and hide Retry (`analyticsErrorRetryable`), because the same request would be refused again. The advice is per surface: "Try a shorter period" only where the request's held history follows the period (the charts and the Swimlanes table); the day drill-down reads every card whatever the period, so it says only "Ask your administrator" (`{ wholeHistory: true }`), and so does the Summary tab, which has no period (`{ noPeriod: true }`). A refusal that retrying can fix (`analytics_busy`) is retried once after `Retry-After`, with the pending retry canceled on unmount or a filter change (`withAnalyticsBusyRetry(..., cancelableWait, signal)`), and keeps Retry. A Retry that unmounts itself when the reload starts first moves focus to an element that survives the reload (the Overview's heading; the root region, `tabIndex={-1}`, of the Summary tab and of the Swimlanes view; the drill-down drawer's dialog, for both the card list's Retry and a card's transitions Retry, #2568), so keyboard focus never drops to `<body>`. The same holds for every Retry or Try again in the app (#2575): hand focus to the section's heading, toggle or region first; where only a landmark, dialog or card survives, use `focusSurvivor` (`utils/focusSurvivor.ts`), which lends it a `tabindex` until focus leaves; where nothing survives the reload (the share page), keep the button mounted and `aria-disabled` until the answer, then focus the new view's `main`. Pin each with a test that asserts the focused element. A new surface that can receive either code gets both behaviors and a test for each.

- **Swimlanes view (#2267).** A row's bars are `aria-hidden` decoration and every figure they draw is also text in the same row, except the board-median tick, which the legend names. A comparison status (slower, faster) is always words, and `warning` or `success` only repeats it. The view switch is a `<nav>` of links (`aria-current="page"`, bold plus underline), uses `focus:ring-2` (never `focus-visible:`), and its `onClick` calls `preventDefault` only for a plain left click. A section of `h3` groups under a finding panel carries its own `sr-only` `h2`. A failed refetch with data on screen shows a `role="alert"` line with Retry, so stale numbers never look current. The legend renders only when rows do.
