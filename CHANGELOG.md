## [1.2.0-alpha.4] — 2026-10-02


### Added
- Added a 7th try.visiban.com showcase board, "Sales Territory (Overlay)", demonstrating an enterprise overlay sales coverage model (primary AE plus overlay AE/SA specialists and an admin-only Account Director, shared across accounts with one deliberate coverage gap) alongside the existing Sales Territory board (#1412)

### Changed
- The stable-vs-pre-release classification that decides whether a release tag updates `backend:latest`/`frontend:latest` is now a single, self-tested script (`scripts/classify-release-tag.sh`) instead of duplicated regex logic, and a new tag-pipeline check (`latest-tag-stability-check`) fails the pipeline if `:latest` on either registry ever drifts from the newest stable release again. `scripts/release.sh` also now states what the upcoming tag will do to `:latest` before anything is tagged or pushed.

### Fixed
- OpenAPI schema for `POST /api/v1/auth/password/change/`, `/auth/password/reset/`, `/auth/password/reset/confirm/`, and `/auth/login/` now documents the real `{"detail": ...}`/`{"key": ...}` response instead of the request body's fields — a client generated from the published schema previously built the wrong response parser for these endpoints (#1408)
- Pinned custom-field chips on the card face no longer overlap or bleed into the due-date pill, label chips, or assignee avatar on narrow columns — they now clip cleanly with an ellipsis instead (#1411)
- Sales Territory (Overlay) demo board now has a nine-stage pipeline (Identify, Discover, Qualify, Shape, Validate, Commercial, Commit, Won / Lost) with cards and movement history in every stage, shows the account director (AD) as the first pinned lane field, and adds an SA field (one solutions architect per two AEs) and an SVC services-lead field per AD. The per-board cap on pinned swimlane fields rises from 3 to 8. The swimlane label column now opens at a width that fits the longest lane name and pinned field values (drag the separator to override), and pinned fields stack one per line.
- The swimlane label panel no longer turns transparent on hover, so cards scrolled underneath it no longer show through the lane name and field chips.
- Fixed the `backend-manifest`/`frontend-manifest` CI jobs re-pointing `backend:latest`/`frontend:latest` (on both the GitLab registry and GHCR) at every pre-release tag's build, including alpha/beta/rc builds. An unpinned `docker pull` now keeps resolving to the last stable release; only a stable `vX.Y.Z` tag updates `:latest` (and `:MAJOR.MINOR`). A pre-release tag publishes only its own exact version tag.

### Security
- Accepted the `braces` stack-exhaustion advisory (GHSA-vfj7-8cjw-p6xm) in `frontend/osv-scanner.toml` with an expiring ignore (until 2026-11-30), unblocking the `dep-scan-osv` gate. No patched release exists; `braces` is a dev-only, build-time transitive of Tailwind and is not shipped in the production bundle.
## [1.2.0-alpha.3] — 2026-10-02


### Added
- CI now drills the documented docker-compose production path (`docker-compose.prod.yml` + `init-prod.sh`) on a schedule and on any MR that touches it, the Compose counterpart to the existing Helm install/NetworkPolicy drills: it asserts the init step completes, the backend clears its import-time boot guards, a placeholder `DJANGO_SECRET_KEY` is rejected, `/api/health/readiness/` reports ready through nginx, and the stack survives `docker compose restart backend` (#1152).
- Helm: the bundled Valkey can now require a password. Set `valkey.auth.enabled=true` with either `valkey.auth.password` or `valkey.auth.existingSecret` (plus `existingSecretPasswordKey`). The password reaches Valkey and the backend only through that Secret, never through a ConfigMap or a plain environment value, and it can contain any character, including `/` and `@`. Auth stays off by default, so existing installs are unchanged on upgrade. Before this change, `valkey.auth.enabled=true` was refused at render time because it never produced a working deploy. See [Valkey password](docs/getting-started/kubernetes.md#valkey-password) (#1211).
- Site admins can now click **Restart onboarding tour** next to a user in the Admin panel's Users tab to clear that user's `has_completed_tour` flag, so the [onboarding tour](docs/getting-started/onboarding-tour.md) shows again on their next board visit. Previously this was only possible through the Admin API. The button only appears for users who have already completed the tour (#1280).
- Settings → Profile now offers **Resend link** and **Cancel change** for an email change waiting for confirmation (`EMAIL_VERIFICATION=mandatory`), backed by the new `POST /api/v1/auth/me/pending-email/resend/` and `DELETE /api/v1/auth/me/pending-email/` endpoints.
- Added an **Also send by email** option to the **Comment on a watched card** notification in Settings → Notifications, backed by a new `email_notif_comment_added` user preference (off by default, writable via `PATCH /api/v1/auth/me/`).
- Signing in with Google, GitHub, GitLab, or SSO using an email that already has a Visiban account now explains what to do instead of failing: the login page asks you to sign in with your password (or the provider your account already uses), then offers once to connect the new provider for next time. Settings → Security has a new **Connected accounts** section to connect or disconnect providers, which never lets you remove your last way to sign in. Backed by the new `pending_connect_provider` and `pending_connect_identity` user fields and `GET`/`DELETE /api/v1/auth/me/connected-accounts/` and `DELETE /api/v1/auth/me/pending-connect/` endpoints.
- Hosted demo (`seed_demo_data --demo-site`): the demo now seeds six boards, each a different workflow with a different swimlane entity, so visitors see swimlanes as real entities with their own fields within one click. Software Team stays; Property Management (one row per property, with the unit on each card and issue-type labels), Construction (per project, with permit links), Sales Territory (per account, with deal value and CRM links on cards), Content Moderation (per content queue, with multi-select report reasons) and Logistics Exceptions (per shipment, with ETAs and tracking links) replace Marketing Campaigns and Hiring Pipeline. Each new board pins three row fields that the visitor account can see, and mixes fresh, aging and stale cards. Every link points at an `example.com` address (#1389)
- Custom fields gain a **URL** type, for both card and swimlane fields. Values must be absolute `http://` or `https://` addresses (the web UI adds `https://` to a bare domain; the API rejects `javascript:`, `data:`, and every other scheme with a `400`) and, like every custom field value, at most 500 characters. Values render as links that open in a new tab — the full address in the card detail panel, the hostname on pinned card-face and swimlane-row chips — and URL fields filter by substring. The API change is additive: `field_type` accepts the new value `"url"` (migration `0063` is a no-op at the database level), the TypeScript `CustomFieldType` union gains `"url"`, and enterprise `CUSTOM_FIELD_VALIDATORS` hooks may now see `field_type="url"`. Clients that do not know the type should render the value as plain text (#1390).
- Dropdown and multi-select custom fields can now give each choice a **color**, for both card and swimlane fields: pick one of eight palette colors (Slate, Blue, Green, Amber, Red, Violet, Pink, Teal) from the swatch in front of each choice in Board Settings, or **Reset to automatic**. A colored choice renders as a tinted badge, with its text label always shown, on the card face, in the swimlane label panel and in card detail, meeting WCAG AA contrast in light and dark themes; choices with no color keep their automatic dot, so existing boards look unchanged. Renaming or removing a choice resets its color. The API change is additive: `choice_colors`, a `{choice: palette_key}` map (default `{}`), on both custom field definition endpoints, their WebSocket events, and the JSON export's field schema (migration `0066`, a defaulted column); `choices` stays a plain list of strings. Keys that are no longer choices are pruned on save, an unknown palette key or a non-empty map on a type without choices is a `400`, and retyping a field away from dropdown/multi-select clears it (#1391).
- Number custom fields gain optional, display-only **number formatting**, for both card and swimlane fields: a **Prefix** and **Suffix** (up to 10 characters each, spaces kept — e.g. `$` or ` h`) and a fixed number of **Decimals** (0–10, with thousands grouping), set in a new **Format** block with a live preview in Board Settings. Values show formatted on the card face, card detail, hover peek and swimlane row chips (`$1,234.50`, `-$5.00`); the value editor keeps a plain number box with the prefix and suffix shown beside it. The stored value is unchanged — still the raw number string on the wire, in CSV and JSON exports, and in filters. The API change is additive: `number_prefix`, `number_suffix` (default `""`) and `number_decimals` (default `null`) on both custom field definition endpoints, their WebSocket events, and the JSON export's field schema (migration `0065`, nullable/defaulted columns only). Setting any of them on a non-number field is a `400`, and retyping a field away from number clears them (#1391).
- Custom fields gain a **Multi-select** type, for both card and swimlane fields: pick any number of a field's choices from a searchable checklist that saves once when it closes. Values show as small chips (two on the card face, three on a swimlane row, with a `+N` overflow) and the filter bar matches cards holding any of the checked choices. Renaming or removing a choice keeps existing values as plain entries, listed under "No longer a choice" in the editor. The API change is additive: `field_type` accepts `"multi_select"` (migration `0064` is a no-op at the database level); the value stays a **string** on the wire — a canonical, deduplicated JSON array string in choice order such as `"[\"web\",\"ios\"]"` — and writes may also send an array of strings. Every entry must be a current choice or one already stored on that card or swimlane, and the encoded value is capped at 500 characters. CSV export joins entries with `"; "`. Enterprise `CUSTOM_FIELD_VALIDATORS` hooks and the `custom_field_value_changed` signals now see the JSON array string for multi-select fields. The `400` message for choices sent on a type that cannot carry them changes from "Only a dropdown field can have choices." to "Only a dropdown or multi-select field can have choices." Clients that do not know the type should render the value as plain text (#1391).

### Changed
- Internal: `backend-schema-fuzz`'s accepted-failure baseline (`backend/schemathesis-baseline.json`) pruned from 41 to 12 entries — #1119 and #1123 closed without their schema-drift entries being removed, so two full-length `st run --baseline-update --baseline-prune` passes (different seeds) confirmed which entries no longer reproduce. Every surviving entry now documents why it's accepted in a `reason` field. No application behavior change (#1170)
- Internal: the `allowed_priorities` length cap (100 entries) is now a single shared constant in `visiban.utils`, imported by both `GroupSerializer` and `BoardSerializer`, instead of being independently declared in each — no behavior or API change (#1186)
- Internal: extended the `to_attr` prefetch pattern from #1212 to `CardSerializer.labels`, `CardQuerySerializer.labels`, and `SwimlaneCustomFieldValuesField`, avoiding the Python cost of re-cloning a `RelatedManager` queryset on every `.all()` call against a prefetched relation on `/full/` and other board read paths — response shape, OpenAPI schema, and query counts are unchanged. Also fixes a bug found while making this change: `PATCH .../swimlanes/{id}/` could echo a swimlane's pre-write custom field values back in the same response instead of the values just submitted (#1223)
- Board member removal and group invite link revocation now use the canonical inline-confirm pattern: full-sentence prompt with Confirm/Cancel buttons (#1238).
- **Behavior change:** `PATCH`/`PUT` on a card, column, or swimlane that changes `position` now returns `400 Bad Request` instead of silently applying it. Reordering bypassed the WIP/weight limits, the `CardMovement` audit trail, and the reorder broadcast that only the dedicated endpoints evaluate. Use `POST .../cards/{id}/move/` for cards, or `POST .../columns/reorder/` / `POST .../swimlanes/reorder/` for columns and swimlanes. A request that echoes the current `position` back unchanged (e.g. a full-object round-trip) is still accepted. (#1275)
- Removed the dead `/_allauth/` nginx proxy location from `nginx/app.conf.template`, `nginx/app-http.conf.template`, and the Helm frontend nginx configmap — no backend route (`allauth.headless` is not installed) ever served that path; OAuth callbacks go through `/accounts/` (#1281)
- Admin → Users row actions: Deactivate/Reactivate and Make admin/Remove admin stay inline; Grant/Revoke all-content, Force password reset, Clear lockout, and Restart onboarding tour now live behind a per-row "More actions" overflow menu, so the row no longer depends on horizontal scroll to fit every action (#1291)
- **Behavior change:** `PATCH` on a checklist item that changes `position` now returns `400 Bad Request` instead of silently applying it — the same class of bug as #1275 for cards/columns/swimlanes. A plain PATCH bypassed the reorder broadcast that only the new dedicated endpoint evaluates. Use `POST .../cards/{id}/checklist/reorder/` to reorder checklist items instead. A request that echoes the current `position` back unchanged (e.g. a full-object round-trip) is still accepted. (#1292)
- **Behavior change:** `POST /api/v1/auth/registration/verify-email/` now returns `409 Conflict` with `code: "email_in_use"` when the key is valid but another account has already verified the address. Previously it returned `200 {"detail": "ok"}` without confirming anything. This applies to email-change and signup confirmations alike. The SPA's confirmation page now explains that the address is already in use. (#1293)
- The card hover peek now labels its custom-field line "Other fields" when the board pins fields to the card face, so peek values are no longer mistaken for a conflicting value of a pinned field; hovering a field shows its full name and help text.
- **Forgot password** now sends a real reset link to an account that has no password yet but a verified email address, so someone who can no longer sign in with the provider they signed up with can set a password and get back in. The same rule applies on allauth's own reset-request page at `/accounts/password/reset/`. Accounts whose address was never verified still get the "sign in with your provider" email instead.
- A **Forgot password** link sent to an account that has no password yet is tied to the email addresses verified on that account: it works only while the address it was sent to is still verified, and any change to which of the account's addresses are verified makes it stop working — request a new link. Another verified address on the account does not keep the link valid. Reset links for accounts that already have a password are unaffected.
- Hosted demo (`seed_demo_data --demo-site`): the showcase boards now show off checklists, card and swimlane custom fields, card relations (including an active blocker) and, on Software Team, linked merge and pull requests. The published visitor starts with an unread notification inbox (mentions, assignments, card moves, a new comment, and stale and due-soon alerts). Card ages and due dates now form a deliberate mix of fresh, aging and stale, and overdue, due-today and upcoming work, so the boards no longer read as almost entirely stale after each reset (#1363)

- Internal: extended frontend unit test coverage on `RichTextEditor.tsx` and `useBoard.ts` (toolbar actions, save/cancel, blur-save, value-resync, move/reorder failure and rollback paths, member/field-definition mutators) and raised the `frontend/vitest.config.ts` coverage thresholds (lines 70→83, statements 70→80, functions 60→77, branches 60→77) to match. Also removed `backend/management/commands/benchmark.py` from `backend/.coveragerc`'s omit list — it already has dedicated tests (`test_benchmark_command.py`, ~92% coverage) and was only omitted from the backend's own gate, not from SonarCloud's, making it look untested there. The one-off `backend/boards/seed_data/generate_seed_data*.py` fixture generators (no Django/DB dependency, run by hand, never imported at runtime) are now excluded from SonarCloud's coverage denominator via `sonar.coverage.exclusions` instead. No application behavior change (#1371)
- Added a `lint:sonar-exclusions` CI guard (`scripts/check-sonar-exclusions.sh`) that fails when a SonarCloud suppression glob matches no tracked file, the criteria index and definitions disagree, or a `*.ts` glob sits in a directory that also holds `.tsx`; documented the suppression policy in `sonar-project.properties`. (#1380)

- Removed the Contributor License Agreement. Contributions are now accepted under the project's Apache 2.0 license on inbound=outbound terms (Section 5 of the license), documented in `CONTRIBUTING.md`; the default MR template's CLA checkbox is replaced by an Apache 2.0 acknowledgment.

### Fixed
- Fixed a production Docker Compose deployment bug where the backend-init container could fail `collectstatic` with `PermissionError: [Errno 13] Permission denied: '/app/staticfiles/admin'` on a fresh install. The image never created `/app/staticfiles` before `docker-compose.prod.yml`'s named `staticfiles` volume mounted over it, so Docker seeded the new volume as `root:root` instead of the non-root service user — caught by the new `compose-prod-drill` CI job (#1152), which was the first time this path had ever actually executed end-to-end.
- Email-based login (`email__iexact` lookups against `users.email`) no longer does a full table scan on PostgreSQL — added a concurrently-built expression index matching the exact `UPPER(email)` form Django compiles for `iexact` on that backend (#1222)
- Converted four dotted-source `CharField(default=None)` serializer fields (`GroupBriefSerializer.parent_name`, `GroupInviteLinkSerializer.created_by_username`, `NotificationSerializer.card_title`/`board_name`) to `SerializerMethodField` so they can't be silently dropped if a serializer is ever bound `partial=True` (#1166 pattern). Response shape and OpenAPI schema are unchanged.
- The published OpenAPI schema now describes the real response shape for card movements, the card/board movement history, the unified card timeline, checklist item updates, archived-card listings, card status, and several group endpoints (subgroups, boards, descendant boards, shared labels, and members) instead of falling back to the wrong `$ref` (#1227)
- Raised sub-12px text in InviteLinkPanel, BoardActivityDrawer, CommandPalette, and GroupDetail's inherited-role badge to the `text-xs` typography floor.
- Fixed badge and chip token drift where several state/count indicators (the saved-filter-count badge, the swimlane collapsed card-count badge, the "View only" board badge, the active filter chip, and the "Admin" role pill in the Admin panel's user table) used `bg-info/20` instead of the documented `bg-primary-emphasis/20` fill, so they didn't track the active theme. Also corrected the saved-filter-count badge's padding to the standard `px-2` (#1239).
- Fixed missing accessible names on icon/glyph-only buttons that relied on `title` alone: the column collapse button, the rich-text toolbar's Bold/Italic/Inline code/Bullet list/Numbered list/Heading/Blockquote/Text color controls (which also now expose `aria-pressed` for the toggleable marks), and a further sweep of card, board-settings, and swimlane controls (close card, clear date, remove checklist item, delete attachment, remove invite, edit/delete custom field, edit swimlane) that had the same gap (#1240).
- Fixed the Django admin bypassing WebSocket broadcasts when editing or deleting a Swimlane, Label, Board, BoardMembership, CardComment, or CardChecklist — connected clients viewing the affected board now see admin-site mutations live, matching the existing Card/Column admin behavior. Board admin mutations also now broadcast to the board's group channel (not just the board channel), so the dashboard/boards-list view stays live too.
- `scripts/release.sh`'s version-consistency checks (against `.env.example`, `frontend/package.json`, `README.md`, the `docs/getting-started/` pages, `docker-compose.prod.yml`, and the Helm chart) now abort the release on failure instead of only printing a `WARN` and continuing to commit, push, and open an MR anyway. Nothing has been committed at the point these checks run, so the abort fully rolls back the release branch (`git reset --hard`, checkout `main`, delete the branch) — the same cleanup already used when the release-notes confirmation is declined (#1269).
- Docs site version dropdown no longer shows a stray unprefixed pre-release build above the actual latest version — a `v`-prefix inconsistency let one version identifier silently outrank every correctly-prefixed one in the sort order (#1270)
- `AdminIPRestrictionMiddleware` now matches CIDR ranges in `DJANGO_ADMIN_ALLOWED_IPS` (e.g. `10.0.0.0/8`), not just exact IPs, for both IPv4 and IPv6 — bringing it in line with the Nginx allowlist that accepts the same `backend.settings.adminAllowedIPs` Helm value (#1274)
- Invalid, host-bits-set (e.g. `10.0.0.5/24`), and very broad (including `/0`) `DJANGO_ADMIN_ALLOWED_IPS` entries now log a warning at startup (#1274)
- Creating or renaming a swimlane with a name already used on the same board now returns `400 Bad Request` naming the `name` field instead of `500 Internal Server Error` — the #1166 fix for duplicate column/label names had missed swimlanes (#1276)
- The **Comment on a watched card** notification preference now works: with it turned on, you are notified in-app when someone else comments on a card you created or are assigned to. Previously the toggle was saved but no notification was ever created. You are not notified about your own comments, twice for a comment that also @mentions you, or after losing access to the board. A new `comment_added` notification `action_type` is added. Commenting with an @mention on a card whose title is near the 500-character limit no longer returns a server error on PostgreSQL (#1277)

- The keyboard shortcuts overlay now lists the `G` then `U` chord (open the user menu) and the `L` shortcut (switch to Lens view, shown only when a lens is configured on the board), matching the documented shortcuts. (#1279)

- Card drag-and-drop now works on touch screens (tablets and phones): press and hold a card to pick it up, while a quick swipe still scrolls the board. Column, swimlane, and custom-field reordering use the same gesture, and the card panel's Move button is larger and labeled on touch screens. (#1287)
- Deleting a board that holds only archived cards now requires typing the board name, the same as a board with active cards. Archived cards are deleted along with the board, and all three board-delete confirmations (dashboard, board switcher, and Board Settings Danger Zone) now say so and show how many archived cards will go. Board payloads gain an additive `archived_card_count` field; `card_count` still counts active cards only (#1289)
- Board member role controls now use the same site-admin signal as the server: the Members settings lock the role dropdown and remove button for a member who is a site admin (unless you are one too), and no longer lock a member who only has all-content access. Board member rows gain an additive `is_site_admin` field for board admins and site admins, on `/full/`, the members endpoint, `member.*` WebSocket events, and the change feed (#1290)

No API behavior, request/response bodies, or permissions changed — only `@extend_schema` documentation was added (#1294).
- `scripts/check-serializer-ts-parity.py` now compares array item types, not just the outer `array`/`array` family — it follows a schema array's `items` `$ref` and checks it against the TypeScript element type wherever both sides name a mapped interface. This caught a real drift it previously couldn't see: `BoardPublic.swimlanes` was typed `Swimlane[]` in `frontend/src/types/index.ts`, but the share-link API actually returns `PublicSwimlane[]`, a deliberately narrower shape that omits `custom_field_values`, `contact_email`, and `notes` (#1140). `PublicSwimlane` is now a dedicated TypeScript interface matching `PublicSwimlaneSerializer` exactly, `BoardPublic.swimlanes` is typed `PublicSwimlane[]`, and the pair is mapped in `COMPONENT_MAP` (#1296).
- **Behavior change:** `POST .../columns/reorder/` and `POST .../swimlanes/reorder/` now reject a partial, duplicate, foreign-board, or (on a board that has columns/swimlanes) empty `order` list with `400 Bad Request` instead of applying it. Previously a partial column list could either collide into `unique_together(board, position)` (returning `500`) or leave a gap, and a partial swimlane list could silently leave two swimlanes sharing a `position`; a duplicate ID let the last occurrence silently win. `order` must now be exactly the board's full set of column/swimlane IDs, matching the rule `POST .../cards/{id}/checklist/reorder/` already enforces (#1292). Clients that always send the full list (the Visiban web app's drag-and-drop already does) are unaffected. (#1302)
- Admin Settings → Users' search-debounce timer is now cleared on unmount, matching the existing cleanup for the tour-restart action message (#1304)
- Fixed a class of `setTimeout`-based debounce/delay timers (card weight-save debounce, card hover-peek delay, tooltip hover-delay, autosave status fade, plus invite-search and offboarding member-search debounces) that were left running past component unmount instead of being cleared, which could fire state updates against torn-down components (#1305)
- Fixed a further set of SVG-icon buttons found relying on `title` alone for their accessible name during the #1240 sweep: the group boards list's "Move to another group" button, the dashboard and board-switcher "Move to group"/"Delete board" buttons, the swimlane focus-mode toggle (which had `aria-pressed` but no state-reflecting `aria-label`), the group tree's "Add subgroup" button, the bulk-selection toolbar's "Deselect all" button, and the app sidebar's collapse/expand toggle and its collapsed-rail Favorites/Recent boards/Groups/Personal boards flyout triggers. All now expose an `aria-label` alongside the existing `title`, naming the affected board, group, or swimlane where applicable (#1307).
- Checklist, comment, attachment, and relation changes made by another session now appear live on an open card detail panel instead of requiring a manual refresh (#1310)
- Raised the stage-distribution segment initials in `SummaryView` and the avatar-initials override in `FilterChip` to the `text-xs` typography floor (#1237 sweep gap).
- The **Continue with SSO** button for a generic OIDC provider now goes to allauth's actual OIDC login path (`/accounts/oidc/oidc/login/`), and an invite token passed to it is carried through sign-up like the other providers'.
- OAuth signup attempted while registration mode is set to Closed now redirects to the frontend with `?auth_error=signup_closed` instead of rendering allauth's stock, unstyled `signup_closed` template.
- Visiting or submitting the server-side `/accounts/signup/` page while registration is closed or invite-only now redirects to the app's login page with a clear message instead of showing an unstyled stock page.
- Fixed `manage.py benchmark` silently reporting a false "✅ OK" (0 queries) when a restrictive `ALLOWED_HOSTS` rejected the test client's request with `DisallowedHost` before any query ran. The command now scopes `testserver` onto `ALLOWED_HOSTS` for its own requests, and any non-2xx response from an endpoint under test is a hard failure (`CommandError`, non-zero exit) instead of a stderr-only warning.
- Fixed `LensConnectionSerializer.created_by` (Git Lens) not declaring `allow_null=True`, which caused the published OpenAPI schema — and the documented `lens_connection.configured` WebSocket payload — to describe `created_by` as always present, when `LensConnection.created_by` is a nullable (`SET_NULL`) foreign key that is `null` once the user who configured the lens is deleted. The field is read-only; the live response was already `null` in that case. The frontend `LensConnection.created_by` type is widened to `BoardUser | null` to match.

Response shape, OpenAPI schema, and query counts are unchanged (#1333)
- `GET /api/boards/{id}/full/` now prefetches the board's `custom_field_definitions` and `swimlane_custom_field_definitions` instead of reading them with a live query each — closing a gap against the "every relation on `BoardFullSerializer` needs a matching prefetch" rule from #1212. Scoped to the `/full/` load only, so no other endpoint that shares `get_board_for_user()` pays for it.

### Fixed
- Fixed real-time board updates silently stopping on connections idle for more than 5 seconds. `backend/requirements.txt` left the `redis-py` client unpinned, so fresh installs pulled redis-py 8.0.0, which enforces a 5-second socket read timeout on the block-forever `BZPOPMIN` that `channels-redis` uses in its receive loop — killing every idle WebSocket. `redis-py` is now pinned to `>=4.6,<6`.
- Restored `linux/arm64` container image publishing on release tags, alongside `linux/amd64`. `:<tag>`, `:latest`, and (for stable releases) the `:MAJOR.MINOR` alias are multi-arch manifest lists on both the GitLab registry and GHCR again. arm64 publishing had regressed silently since 2026-06-26 and was dropped from the release pipeline entirely when the amd64 push jobs moved to kaniko (#1084). If the arm64 build ever fails on a release tag, the amd64-only image is never published under the real tag names — the pipeline fails loudly instead of silently shipping a single-arch image under a multi-arch tag. The on-demand manual GHCR push jobs, which had no such safeguard, were removed.
- Fixed the issue lens board 500ing when a provider sends non-string `milestone_due`/`milestone_state` metadata (int, dict, or unexpected shape). These fields are now coerced to `None` at the GitHub/GitLab normalization boundary, and the lens board view degrades to the last cached copy on any remaining unexpected parse error instead of failing with an internal server error (#1085).
- Fixed the OpenAPI schema (`/api/schema/`) misdescribing the `move`, `comments`, `checklist`, column/swimlane `reorder`, `share`, and `members` custom actions — these previously fell back to the viewset's default serializer and documented the wrong request/response shape (e.g. `move` appeared to accept/return a full `Card` object instead of its real `{column_id, swimlane_id, position, version}` request and `{card, movement}` response, including its `version_conflict` / WIP / weight-limit error bodies). Also fixed related nullable-field gaps in `CardSerializer` and `CardMovementSerializer` (`assignee`, `moved_by`, `last_moved_at`, and several `SerializerMethodField`s) that a schema-vs-response contract test for `move` surfaced. A client generated from the schema (e.g. the MCP REST-client package, or any other external consumer) now gets accurate types for these endpoints.
- Helm: a fresh `helm install` with the chart's default values now succeeds. Database migrations moved out of a `pre-install`/`pre-upgrade` hook Job and into a `migrate` init container on the backend Deployment. Helm runs pre-install hooks before it creates any release resource, so on a fresh install the hook tried to reach the bundled PostgreSQL before its StatefulSet and Service existed and the install never returned; `helm upgrade` was unaffected, which is why this survived. Concurrent backend replicas are serialized by a session-scoped PostgreSQL advisory lock (`manage.py migrate_with_lock`), so `backendReplicaCount > 1` remains safe, and a replica that loses the race waits rather than starting against a half-migrated schema. The hook-managed bootstrap Secret is gone with the Job; a `checksum/secret` annotation on the backend pod template now carries `secret.djangoSecretKey` rotations into the same `helm upgrade`. Because the chart no longer declares any install hook, `helm uninstall` removes everything it created. New tunables: `backend.migrate.connectTimeout` and `backend.migrate.lockTimeout`.
- Fixed the OpenAPI schema (`/api/schema/`) misdescribing five `Group`/`GroupDetail` fields: `subgroup_count`, `board_count`, and `member_count` were documented as `string` but are actually `integer`; `is_starred` was documented as `string` but is actually `boolean`; `parent_name` was documented as a non-nullable string but is `null` for a root group. Also fixed `GroupDetail.ancestors`, documented as `string` but actually an array of `{id, name}` objects. Schema-only change — no runtime behavior or response body change. A client generated from the schema now gets accurate types for these fields (#1119).
- Fixed two more unhandled `500`s and a schema-accuracy gap the now-blocking `backend-schema-fuzz` job (#1120) caught on its first real CI run:
- `POST`/`PATCH /api/v1/groups/{id}/labels/...` crashed with an uncaught `IntegrityError` on a duplicate label name within the same group — the `(group, name)` uniqueness constraint isn't visible to DRF's automatic validator because `group` is injected after validation rather than being a serializer field. Now returns a clean `400`.
- `POST /api/v1/groups/{id}/star/` documented the full `Group` response shape but actually returns a lean `{"starred": bool}` (by design, to avoid re-serializing the whole group) — the OpenAPI schema now matches.
- `GET /api/v1/cards/?updated_since=` crashed with an uncaught `DataError` on PostgreSQL when the timestamp carried a UTC offset of 16 hours or more (valid ISO 8601, but out of range for `timestamptz`). Now returns a clean `400`.
- `avatar_url` (on `BoardUser`, `CurrentUser`, and the user-search response) was documented as `format: uri`, which a blank avatar (a valid, common value) fails — corrected to a plain string field, since fixing the underlying schema was less fragile than baselining every endpoint that happens to embed a user.
- `PATCH /api/v1/auth/user/` accepted a username containing an astral-plane Unicode code point (outside the Basic Multilingual Plane) — Django's own `UnicodeUsernameValidator` allows it, but it violates the documented `username` schema pattern for every consumer that (like JSON Schema and JavaScript) treats the response as UTF-16, breaking every subsequent response embedding that user for the rest of the run. Added a shared, stricter `UsernameFormatValidator` (`accounts/validators.py`) and applied it everywhere a username is written — self-profile update, registration, admin-created accounts, and choose-username — rather than baselining the resulting cascade of schema-conformance failures one endpoint at a time.
- Fixed several unhandled `500`s the `backend-schema-fuzz` CI job's baseline triage (#1120) turned up:
- A non-numeric id in a request (board id, group id, board/group member user id, group invite-link id, group label id, or — defense in depth alongside a related routing-level fix — card/comment/attachment/checklist-item id) crashed instead of returning the documented `404`. `boards/views/_helpers.py` and six other view modules resolved these with `django.shortcuts.get_object_or_404`, which doesn't catch the ORM's `ValueError` on an invalid pk the way `rest_framework.generics`'s version does.

- Personal access tokens now carry explicit, non-hierarchical **scopes** (`read`, `write`, `admin`, `mcp:read`, `mcp:write`), so a token issued to a script, a CI pipeline, or an AI agent can be given less authority than the account that created it. Previously every token carried its owner's full read/write authority on every endpoint, including the admin API. No scope implies another — `admin` does not grant `read` or `write`, and nothing grants the `mcp:*` scopes — and requirements compose, so an admin write needs both `admin` and `write`. Scopes only ever narrow a token; board membership and role checks are unchanged.
- **Upgrade notes:**
- Tokens that already exist keep working unchanged across the entire REST API — the migration adds a nullable column and backfills nothing.
- Pre-existing tokens are **refused by the MCP server**, which now requires `mcp:read`. Create a new token with that scope to reconnect an MCP client.
- `POST /api/v1/auth/tokens/` accepts an optional `scopes` list and **defaults to `["read", "write"]`** when it is omitted. API callers that relied on a newly created token carrying admin authority must now request `admin` explicitly.
- A scoped token can no longer create or revoke tokens; without this a `read` token could mint itself an `admin` one. Tokens created before this release keep the old behavior.
- `scopes` is exposed on the token list and create responses.
- `POST /api/v1/auth/ws-ticket/` (the WebSocket ticket endpoint added in this release) requires the `write` scope, because minting a ticket is a `POST` and the scope baseline is resolved from the path and method. A `read`-only token cannot currently open a WebSocket.
- Also fixes three pre-existing gaps found while auditing the authentication and permission chain as scope-enforcement sites:
- The `/api/v1/admin/*` endpoints omitted the `MustNotHavePendingUsernameChange` gate, so a site administrator with a forced username change pending could still reach them.
- `POST /api/v1/auth/password/change/` (the dj-rest-auth route) did not revoke the user's personal access tokens, unlike `POST /api/v1/auth/change-password/`. "Change your password to cut off a leaked token" therefore worked or not depending on which endpoint the caller used. Both routes now revoke.
- A token revoked concurrently with a request already in flight returned `500` instead of `401`.
- `GET /api/v1/cards/` (the cross-board card query endpoint added alongside this release, #1112) did not declare `TokenHasScope`, so a token's scope was never checked before reaching it. Caught by the same permission-chain conformance test that found the `WSTicketView` gap above.
- `allowed_priorities` on both groups and boards now rejects a submitted list longer than 100 entries before validating it, and de-duplicates the stored value (preserving first-occurrence order) instead of storing duplicates verbatim — closing a storage/broadcast bloat vector where an authenticated user could submit a list with up to ~1M repeated entries. An invalid priority value is now truncated to 50 characters before being echoed back in the `400` error body, instead of being reflected in full.
- MCP tool and resource calls are now rate-limited per personal access token (`MCP_THROTTLE_READ_RATE`, default `300/min`, applied to every call, and `MCP_THROTTLE_COMPUTE_RATE`, default `30/min`, an additional cap on the expensive `list_cards`/`board://{board_id}` reads). Previously `/mcp` had no request throttling at all, since it is mounted in-process and bypasses DRF's throttle classes. A throttled call returns a structured error with a retry hint rather than failing at the transport level.
- Hosted demo is now fenced by the deployment, not by a role: with `DEMO_MODE=true`, a deny-by-default write fence answers `403 {"code": "demo_read_only"}` to every unsafe request (including `TRACE`, allauth's `/accounts/` tree and `/mcp` writes) for every caller, site admins and anonymous clients included, except a small pinned allowlist — sign in/out, WebSocket tickets, and creating, editing, moving, archiving and checklisting cards. `DEMO_MODE` is now parsed strictly (a typo such as `ture` refuses to start). `seed_demo_data --demo-site` publishes a non-admin `visitor` account (MEMBER on every seeded board) instead of the site admin, whose password moves to the new, never-published `DEMO_ADMIN_PASSWORD`, and seeds uploads off and registration closed. The login page gains a one-click "Explore the demo" action and shows the next hourly reset (`DEMO_RESET_SCHEDULE`, default `0 * * * *`; `site-config` and the current user now carry `demo_next_reset_at`), the app shows a demo bar with a countdown and a 5-minute warning, visitors land back on the login page with a "demo was reset" notice, and refused controls are disabled up front with the reason. Off by default; existing installs are unchanged (#1179).
- Fixed the per-account login lockout (5 failed attempts / 5 minutes) not engaging on `POST /api/v1/auth/login/`, the endpoint the SPA and every API client actually use — it now shares allauth's own rate-limit bookkeeping instead of only being protected by the coarser per-IP throttle, closing a gap that let a distributed attacker (many IPs, one target account) skip the account-level lockout entirely. As a result, a second, new limit also now applies to that endpoint: 10 failed logins/minute from any one IP, across any number of accounts, blocking single-IP credential stuffing across many usernames — both this and the per-account lockout return the same `400 Bad Request` and can briefly refuse a correct password from an affected IP or account.
- The production Docker Compose nginx template no longer hardcodes a 2-year `Strict-Transport-Security` header for `TLS_MODE=selfsigned` — self-signed installs now send no HSTS header by default, matching the documented behavior. `TLS_MODE=letsencrypt` still sends HSTS by default (the 2-year value is preserved for existing installs that don't set `SECURE_HSTS_SECONDS`), but the header's `max-age` now honors an operator-set `SECURE_HSTS_SECONDS`, which was previously silently ignored.
